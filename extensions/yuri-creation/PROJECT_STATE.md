# Project state

Repository: https://github.com/imbdsssity/TavernWeave-Yuri. This 0.4.0 feature starts from yuri-dev at b6499d0b666f37c6c9b5e866d1affd1e014bd9d7, on feature/inherited-cards-and-novel-inputs. Main remains accepted 0.2.0 at 8b0e793bafcad532cdf8c251ab48505f723b6e19 pending an explicit release instruction.

Four entry points now cover original conversation, inherited JSON/PNG/worldbook editing, supplied posts, and selected novel TXT/Markdown/EPUB prose. The existing three genre defaults and shared contextual name review remain in force. No native host registration is implied by folder placement.

Inherited editing freezes original bytes and decoded documents. Exact before/after pointer edits preserve all unlisted JSON values, worldbook IDs/order/loading settings and unrelated extensions/scripts. Matching top-level/data mirrors and PNG payload counterparts must be edited explicitly; incompatible structures or stale patches fail without a result. The PNG writer reuses the unchanged Foreverse MIT chunk helper, preserving unrelated chunks byte for byte. No schema defaults, Markdown flattening, invented v2/v3 projection, automatic component merging or artwork replacement is performed.

The novel front end catalogs TXT chapters using the existing pinned splitter and EPUB spine/navigation metadata using a small original standard-library bridge. Only chosen chapters or explicit character ranges are registered; full registration is opt-in. Original hash and source member/offset mappings stay with the descriptor. Exact evidence, extraction/v2 claims, indexing, transactions and adaptation builds reuse the existing shared provenance engine. A third-person novel can have zero source-player records and an explicitly invented player in the adaptation plan. Source uncertainty and the known-minor adult-result guard remain unchanged.

File-folder handling inventories candidates before the agent groups card versions/components or related/independent cards. Text/DOCS-only component assembly uses available host reading/export tools and upstream authoring; it is not advertised as lossless JSON round-tripping. Arbitrary schema remodeling, cross-dialect worldbook migration and script editing are outside the protected replacement adapter.

Testing is restricted by the user's cost instruction: no test execution by the primary model and no repeated old suites. Two GPT-6 Luna checks use exactly one Drive PNG and one Drive EPUB, respectively. EPUB coverage is one declared 1,500-character excerpt and promotion into the shared fact store; no novel card or roleplay trial is claimed. The PNG preservation check and final package readback are recorded in docs/FILE_SUPPORT_REVIEW_2026-11-12.md. The prior 40-check 0.3.1 regression baseline is historical, not a rerun of 0.4.0. Dedicated name-choice behavior testing remains deferred.

Next scope after this feature: native host registration/packaging. Full custom-profile compatibility, legacy original-file licensing, advanced schema migration and exhaustive file-variant compatibility remain separate work. The frozen Workbench v1.2.0 and upstream source/notices are untouched. No withdrawn cases or private source bodies are published or reused. Direct GitHub feature PRs target yuri-dev; main releases still require user authorization.
