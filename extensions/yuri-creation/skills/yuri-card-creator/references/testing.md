# Small conversational trials

Keep human feedback in the conversation. The agent handles files and evidence; do not ask the user to fill out a test document. One card and the relevant path are enough for an initial trial. Do not rerun established generic component suites or build missing product features just to obtain a passing trial.

## Establish the tested revision

Before generation, record the repository, requested commit and actual checked-out commit. Confirm that `extensions/yuri-creation/PROJECT_STATE.md` and the creator script exist. Run the script's `capabilities` command; use `probe-base --tavern-root <repository-root>` only to verify its two authoring-file pins. Neither command proves native host installation.

If an agent receives an archive without `.git`, record that limitation and compare the available extension files with their declared manifest/pins. Never assign the requested commit to an older archive just because it has the same repository name. If the extension is missing or the requested revision cannot be reached, report that before treating the run as an extension trial. An available upstream/host fallback may still be useful, but label its actual source and tools separately.

For a host without repository access, an exact snapshot can be provided before a rerun. Preserve the snapshot's licenses and notices. Do not require a local Codex installation or assume the native plugin was loaded.

## Keep task routes distinct

- Original conversation: keep authored choices/inspiration separate from external canon evidence. Use the original creator contract only for its supported scope.
- Researched character: retain adopted source URLs, versions, retrieval dates and fact/invention distinctions. Report actual search/page tools. A sourced character must not acquire fabricated original-only provenance.
- Inherited card: keep the input unchanged and compare the actual decoded input with the output. Preserve unrelated metadata, entry identities and presentation. Do not substitute a fresh card or a PNG-avatar pack operation for an inherited-card conversion.

## Retain the result, not just the claim

Keep private artifacts outside the public source checkout. The agent should retain the input identity/hash, actual tool route, output filenames and hashes, observed checks, and remaining limits in its existing working notes or receipt. No separate generic test framework is needed.

For PNG output, deliver the actual revised PNG and decoded JSON. A report containing a hash or a broken/empty download link is insufficient for independent verification. Compare payloads and image chunks with the original; image preservation does not establish visual alignment. Deliver a standalone worldbook only if it was actually produced; distinguish it from an embedded book.

Use exact `{{user}}` macros in runtime fields. A spelling difference in source notes alone is not a runtime failure. Keep missing numeric entry IDs and unknown metadata unless a specific change is authorized.

Distinguish agent-reported checks, checks independently reproduced from submitted files, observed host import and observed live roleplay. Ask only for the one manual host interaction that matters next. Do not mark all paths passed because an agent produced plausible JSON.

## Withdrawn cases

Honor the current user-selected test scope. When a case is withdrawn, exclude it from current acceptance evidence and future checks. Do not retrieve it from trash, reopen old links or reuse cached content. Update active review records without rewriting unrelated Git history. Inspect only currently authorized artifacts; a new retained PNG does not reactivate an earlier removed case.
