# E05：世界书目标与状态消费者合同

本节说明世界书消费者如何沿用既有[变量设计](../../tavern-card-builder/references/variable-systems.md)、[模型与迁移](rolecard-data-model.md)、[楼层绑定](floor-and-ui-binding.md)。继续只维护已有字段账本，不另建 schema，也不因读取需要自行增加变量。纯文字世界书只用目标映射部分。

## 名称不是实体身份

按实际项目保留一张可核查映射：`别名 → 稳定实体 ID + 类别 → 内容身份 → 书身份 + 条目 UID + 显示名`。时代/章节可作为已定义实体的限定维度；不能把地图坐标或随时会改的展示名当成主键。UID 仍沿用现有导出保护，跨书时必须带书身份，不能把两本书的同号条目视为相同。

| 原创小例 | 映射与结论 |
| --- | --- |
| “旧桥”“石桥” | 都映射 `bridge-east`，类别 `location`；正文权威为 `fixture-world` 的 UID 101，改显示名不改身份 |
| “渡桥规程” | 类别 `rule`，正文 UID 102；不是因为名字含桥就同时猜 `location`、`faction` |
| 两个控制器提到同一桥 | 保留候选来源，按同一内容身份交 [E06](../../sillytavern-rolecard-performance/references/worldbook-output-budget.md)去重；实体的地点介绍与通行规则仍是不同内容 |

构建/审查时展开所有可构造目标，逐项定位。动态字符串拼接只能覆盖已定义的组合；不能为了补全表格发明时代、章节或素材。

为每项目标明确标记以下状态之一：

- **本书可定位**：书身份、UID、类别和名称匹配；名称 API 的精确/模糊行为另经 E03 核验。
- **外部已核对**：在明确外部书/版本找到目标，且绑定与可达条件有证据。
- **外部待核对**：只猜外部可能补齐，仍是缺口，不能改成已存在。
- **类别或别名不符**：素材存在但映射错位；修复须回到原映射/组件维护者，不执行多类别碰运气读取。
- **缺失/歧义**：找不到或找到多个目标；记录候选和缺口，按已批准策略跳过可选内容、给缺值提示或停止依赖它的生成。

禁用是配置事实，不是上述存在性结论；能否显式读取由 [E03](../../sillytavern-api-reference/references/worldbook-version-verification.md)和真实探针决定。未命中、空正文、读取失败也要分开，不以“没有报错”判断完整。

## 初始化、写入、读取、消费同义同域

沿用原字段账本，补清世界书相关字段从初始化到使用的现有流程：

| 检查点 | 必须一致的内容 |
| --- | --- |
| schema 与初值 | 路径、类型、枚举、缺失/null/空值意义、初始化来源与哨兵 |
| 开局与后续写入者 | 每个阶段的唯一所有者、允许写入的时机、相关字段的成组变化 |
| 模板/脚本读取者 | 同一字段意义、确切会话/消息/swipe、缓存快照及就绪条件 |
| 模型/UI 消费者 | 实际收到的投影/字段、缺值策略与刷新时点，不能只凭界面外观 |

“待初始化”“未开始”是项目声明的哨兵，不是正常章节。存在一个字符串不代表有效状态；默认值只补缺失不能修复已有哨兵。选择章节点时核对其所属时代和时期。需要成组写入时，由原所有者完成；回读确认成功后，才能继续依赖该状态的步骤。API 失败、校验失败或写入未确认时停止依赖的生成，保留原状态或采用已明确的安全降级，不能静默编造值。

例如隔离夹具用 `ready=false` 表示尚未开始，时代/时期/章节尚无业务值；`ready=true` 也必须满足已定义章节与时代/时期的映射。数值 0、布尔 false 可能是有效业务值，不能用真假判断统一当缺失。是否引入 ready 字段是例子的设计选择，不能据此替用户旧卡增加字段。

重生成/swipe/编辑/回退时，按 [共享基础](../../consult-tavernweave-library/references/sillytavern-runtime-foundations.md)和 [E07](../../sillytavern-runtime-debug/references/worldbook-isolated-runtime-checks.md)验证选中消息、状态、UI与下一轮请求；状态读者不自行修复存档。

## 自写隔离例的反向检查

- “外港”只指向尚未提供的外部书，保持 `external-unverified`；不能凭别名或外部书名称宣布目标齐全。
- 把“渡桥规程”的类别误写成 `location`，应报类别错位；规则正文仍存在，不能将其报告成素材丢失。
- `ready=true` 但章节仍是哨兵，或 `return` 章节配着 `early` 时期，均不能进入有效章节点。先检查状态合同，不继续拼接目标名。
- 提议迁入 `return` 时，需要同步 `period=late`；写入未确认就继续生成，会消费旧状态。另一个读者指向不同消息/候选时，即使字段同名也不能宣布已同步。
- 读者使用废弃路径，而字段账本与写入者使用现行路径，没有明确适配就属于消费者合同缺口；不能因此推断其他独立选择器全部失效。

这些是围绕桥梁隔离夹具独立编写的设计检查，不是宿主实测结果。变量生命周期沿用既有合同；本节只补充目标定位和跨组件消费检查，精确 API、导出与迁移仍由原负责技能处理。
