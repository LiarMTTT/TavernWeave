# 反递归执行合同

## 先区分三种结构

- **持久权威蓝图**：改变项目拓扑、完成分母、独立交付物或验收门，长期被 `NEXT.md` 引用。
- **正常步骤检查单**：当前步骤原本就需要的命令、文件、测试和修复项，不是子蓝图。
- **临时问题支线**：由可观察错误、失败证据、未满足的退出条件或实际阻塞触发，只为解决该问题而临时细分。

## 所有活动步骤的固定规则

- 开跑后 `runtimePersistentBlueprintBudget = 0`，只禁止执行期自行新增持久权威蓝图。
- 蓝图最大深度和子蓝图总数上限在设计确认门冻结。
- 任意活动步骤 `Pn` 都不得因为“还可以更细”“任务复杂”或“想规划完整”而递归增殖。
- 没有真实问题证据时，新想法进入现有检查单、风险账本或 Parking Lot；不能改写 First Playable。

## 阶段合同

每个活动阶段只包含：输入、输出、允许修改范围、禁止事项、退出条件、证据、失败回退、下一道门。进入阶段时冻结；退出时只更新证据和结果。

## 临时问题支线

真实问题允许一层最小必要细分，但必须：

1. 绑定一个父步骤并记录问题与触发证据；
2. `persistent: false`，不得改变产品范围、版本承诺、完成分母或独立验收门；
3. 同时最多打开一条问题支线，支线内部不再递归建立问题支线；
4. 解决时记录结果证据，阻塞时记录下一道门；
5. 状态变为 `resolved` 或 `blocked` 后关闭支线，并回到 `returnTo` 指定的父步骤。

例如 P3 可以遇到真实问题，但 P3 只是示例；该规则同样适用于 P1、P7 或任何 `Pn`。

## 升级为持久蓝图

当临时问题已经跨越独立领域、形成独立交付物与独立验收门，且父蓝图无法在不失真的情况下容纳时，停止临时细分并提交 `rescope proposal`。Agent 只能提出提取建议，驾驶员确认后再修改蓝图拓扑；该动作发生在执行门外。

## 停止条件

- 阶段退出条件不清；
- 新事实推翻已确认项目类型或首版合同；
- 需要安装、密钥、付费调用、真实发布、Git 动作或破坏性迁移；
- 自动化证据和真实宿主证据相互矛盾。

出现停止条件时更新 `NEXT.md` 并回到驾驶员门，不用更多规划掩盖阻塞。
