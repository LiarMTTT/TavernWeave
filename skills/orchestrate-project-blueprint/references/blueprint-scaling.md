# 蓝图体量与权威链

## 选择档位

| 档位 | 条件 | 上限 |
|---|---|---|
| `single-blueprint` | 单一宿主、单一主循环、少量组件，可在一个实施文件中清晰追踪 | 深度 1，子蓝图 0 |
| `blueprint-set` | 多领域但仍是一个产品，存在独立交付物与验收门 | 深度 2，直属领域蓝图最多 5 |
| `program-blueprint-set` | RPN 重置版一类多宿主、多阶段、长期迁移工程 | 深度 3，直属蓝图最多 9 |

文件数量不是升级理由。只有当一个领域同时拥有独立边界、独立交付物、独立验证门，并且主蓝图已无法清楚容纳时，才提取子蓝图。

## 权威层级

1. 总设计案：目标、非目标、项目类型、用户价值、系统边界和四态决策；
2. 蓝图或蓝图索引：阶段顺序、依赖、退出条件、证据；
3. 领域蓝图：只描述一个领域的可交付执行合同；
4. `NEXT.md`：当前事实、活动阶段、最近证据、下一道门。

总设计案回答“做什么和为什么”，蓝图回答“按什么边界做到什么证据”，`NEXT.md` 回答“现在从哪里继续”。不得互相复制成三个版本的同一大文档。

## 渐进提取

蓝图集初始化时只创建索引，不创建空白 BP-01…BP-09。到达驾驶员确认门后按需提取。子蓝图 ID 一旦分配不得通过重排改义；废弃时保留状态与替代项。
