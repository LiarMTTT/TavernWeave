# E07：世界书最小隔离验证与观察记录

本节沿用 [runtime-debug](../SKILL.md)的真实宿主边界，不建立另一套验收工程。先用[共享基础](../../consult-tavernweave-library/references/sillytavern-runtime-foundations.md)的纯文字桥梁回合，再按项目实际采用的能力选择下表用例。纯原生项目不安装模板或 MVU，纯文字项目不必跑全部矩阵。

## 运行前置与当前状态

- 先完成 [E03](../../sillytavern-api-reference/references/worldbook-version-verification.md)中用例所需的版本、配置、来源与待验契约；获得具体环境、导入/写入范围及必要调用费用授权。
- 使用新建隔离聊天/测试书和自写短文，记录基线与候选的独立身份。只打开所选依赖；关闭原生递归。不把六类 EJS 场景当作唯一实现，也不套用固定 order、品牌深度或关键词数量配额。
- 只运行获准的自写隔离材料，不执行外部整卡、预设脚本或浮动远程依赖，不改真实存档制造错误。隔离夹具也不是安装、全卡执行或付费调用许可。
- **本次环境未核验，真实酒馆运行待验证，模型调用未进行。** 随包 [静态夹具](../tests/fixtures/worldbook-isolated-contract.json)是新写的 JSON 数据，没有 EJS、宿主脚本或远程导入；仓库测试只证明所声明设计规则自洽，不证明模板运行。

## 最小用例集合

| 用例 | 隔离输入/变化 | 必须观察 |
| --- | --- | --- |
| 原生命中/未命中 | 可靠水位事实 + 桥梁规则；一个命中关键词、一个不命中 | 原生入口与最终请求相应片段，未命中不假装执行条件 |
| 条件真/假/缺值 | 同一已可达入口的水位为涨水、正常、缺失 | 条件值与输出分别记录；缺值不自动等同 false 或正常水位 |
| 入口不可达 | 条件材料为真，但入口未被选中 | 条件未执行、没有输出；不能只改条件表达式诊断 |
| 显式读取 | 明确存在、禁用、缺失的三个目标 | 实际书/UID、返回值/失败、输出和最终请求；禁用读取不支持就如实记录 |
| 状态/聊天冲突 | 状态指向当前时代，消息只谈另一时代 | 按已选优先级解释选中项；不能把提及当作迁移状态 |
| 初始化与一致性 | 缺值、未开始/待初始化、章节点和时期不符 | 明确阻塞或已批准降级；没有无意义的动态目标 |
| 写入失败 | 在隔离作用域使写入被拒绝或返回失败 | 原状态保留、失败可见、依赖它的生成停止；生成开始不证明写成功 |
| 交界重复 | 同义别名、两个控制器、原生+模板同时候选同一内容 | 全局身份仲裁后，实际最终请求仅保留应有的一份 |
| 预算 | 可选项超额；必要内容自身超额 | 优先级与省略原因、完整规则、最终分词；必要项放不下明确失败 |
| 只读投影 | 有效 0、false、缺失以及要折叠的模块 | 投影保留字段语义/必要标记，完整存储前后未变 |

用例可以先验证请求组装，不发送给模型。若宿主不能安全捕获实际待发送请求，应记录捕获受阻；不要把普通页面预览当成该请求，也不要擅自触发收费生成。

采用 MVU 时，还须验证初始化/schema 成功，并检查已有状态的读取、有效补丁与无效补丁的处理、解析/校验/回写各层结果，以及 UI 与下一轮如何使用状态。schema 拒绝不能写成“已经更新”。采用 UI 时，只检查按钮的动作是页面切换、写入还是发消息，并追踪其数据链；不增加 UI 文案案例。

## 同一观察记录贯穿到下一轮

在项目原有证据位置保存记录，使用 [空白记录](../tests/fixtures/worldbook-runtime-observation.pending.json)的字段或等效格式；每个用例与每次复测有独立记录，基线和候选不覆盖。

| 字段 | 记录内容 |
| --- | --- |
| `caseId / artifact / baselineArtifact` | 用例、候选及基线的确定版本/hash；记录来自哪个入口 |
| `environment / authorization` | 宿主、参与扩展版本、浏览器、配置，获准操作/额度；不存凭证 |
| `input` | 状态快照、实际消息窗口及角色、会话/消息/候选身份；用隔离数据 |
| `expected` | 合同要求，与实测严格分开；例如缺值时阻塞而非猜水位 |
| `observed.entry / condition / target / read` | 入口到达、条件真/假/缺失/未执行、目标书名/UID/名称及实际返回/错误 |
| `observed.output / finalRequest` | 输出字符数/标记；真正最终请求的证据引用、接收模型、片段或未捕获原因；token含分词器与范围 |
| `observed.stateBefore / stateAfter / nextRequest` | 写入前后同域状态、投影不改存储证据、下一轮相关输入 |
| `observed.selectionBefore / selectionAfter / ui` | 当前会话/消息/swipe、UI读取的身份与动作性质；不适用写明原因 |
| `runtimeStatus / runtimeBlockers` | 运行组装的 `not-run`、`blocked`、`pass`、`fail`与运行侧缺口 |
| `modelStatus / modelBlockers` | 模型行为的独立状态与模型侧缺口，例如等待调用授权；不得混入运行侧 |

未执行的 observed 字段保持 null，不能把 expected 复制进去充当实测。空串是一次具体读取结果，不能与未读混用。若运行失败，保留最早失败的环节，并标出后续未执行的环节，不能把后续全部写成“不命中”。

两层各自校验：本层 `pass` 要求本层阻塞为空，`blocked` 或 `fail` 必须保留本层原因。运行组装已验证通过、模型调用仍等待授权时，记录 `runtimeStatus=pass`、`runtimeBlockers=[]`、`modelStatus=blocked`和对应 `modelBlockers`，不删除真实模型阻塞，也不因此把运行结果改为失败。原有未分层 `blockers` 要按原因拆分；没有执行的模型结果仍保持空值。

对项目支持的重生成、swipe、编辑、回退，分别保存前后选中候选、补丁应用次数、持久状态、UI读取和下一轮请求。声明由谁恢复/重算；不支持某操作就记录限制，不许推定扩展自动回滚。纯文字回合只需输入、请求、输出、消息保存及下一轮证据。

## 静态检查与真实结果分开

只有完整 TavernWeave 源码检出才包含下面的仓库级测试；在仓库根目录运行：

```sh
node --test tests/worldbook-runtime-contracts.test.mjs
```

独立 Skill 安装也可以运行随包记录校验，将 `<skill-root>` 换成当前 `sillytavern-runtime-debug/SKILL.md` 所在的真实绝对目录：

```sh
node "<skill-root>/scripts/validate-worldbook-observation.mjs" "<skill-root>/tests/fixtures/worldbook-runtime-observation.pending.json"
```

第一条只测试新写的目标映射、条件/冲突、去重预算、只读投影及记录边界；内部示意函数不实现或模拟 SillyTavern/EJS/MVU，不导入外部整卡。第二条只检查记录结构与证据等级是否自相矛盾；通过表示记录合格，**不是 runtime pass**，也不能验证证据引用内容是否真实。它不采集日志、不连接酒馆、不触发模型。

真实验收仍需人工/驱动核对证据：入口→条件→目标→输出→最终请求；状态写入→下一轮消费。UI亮灯、模板未报错、Node测试通过和模型回答貌似合理均不能替代。模型行为如需比较，使用获准的相同模型/参数单独记录，不从请求组装结果推出行为保证。
