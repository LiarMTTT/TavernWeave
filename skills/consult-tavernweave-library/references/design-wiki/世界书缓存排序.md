# 世界书缓存排序

## 一句话定义

用稳定常亮规则当前缀、把每楼动态摘要和关键词设定往后放，提高 prompt 缓存命中。交错宙域 2.6.2 把这套策略写成 `promptCacheOrdering`。

## 为什么重要

每楼都变的变量摘要若排在最前，整段前缀每轮失效，缓存无意义。机甲/探索卡世界书条目多，这个问题更尖。

## 如何运作

回封时统一：

- 灯（常亮 / 关键词）
- 深度 depth
- `insertion_order`
- `display_index`
- `cfSortKey`

排序原则：

1. `[mvu_update]变量更新规则` 与 `[mvu_update]变量输出格式`：常亮、浅深度、前置。
2. 探索、战斗、资源、基地、装备、关系、任务、数值等常亮规则：同样前置浅深度。
3. `[mvu_context]每楼变量摘要`：后置高排序。
4. 世界设定细分：关键词触发，贴近上下文后置。
5. 原版参战作品与原版锚定机体：默认灭灯，只留删减版。

门禁用 `validate_card.mjs` 与 `check_crossed_zone_2_6_0.mjs` 卡住。

## 例子

- 正例：2.6.2 把动态摘要从缓存前缀里拿掉。
- 反例：所有设定常亮且深度相同，每轮 token 与缓存一起烂。

## 边界与易混概念

- 这是装配/回封策略，不是状态栏 CSS。
- 星月也有世界书 insertion 字段，但不等于已经落地同一套 `promptCacheOrdering` 门禁。
