# 虚拟列表

本页不是已采用技术，也不是成品列表壳。检索时间：2026-08-14。蒸馏自 [[queries/第三批蒸馏目标]] **B3-Virt**。只谈公开文档与规范旁注，不写攻击步骤或凭证。

## 一句话定义

虚拟列表（windowing）只把视口附近的行做成真实节点，其余用占位高度撑开滚动条。TanStack 的心是 **`Virtualizer` 坐标器**：算 `start` / `size` / 可见区间，**不是组件**，不交付 markup 或样式。react-window 才是组件库。没有 W3C「虚拟列表」规范。

## 为什么重要

几千行世界书、楼层、控制中心表若全量挂 DOM，会拖长任务、伤 INP。行业解法分两路：JS 窗口化（卸掉屏外节点）与 CSS `content-visibility`（节点还在，跳过屏外排绘）。前者没有标准 API；后者在 css-contain-2，不能当成虚拟列表专章。酒馆 iframe 里滚动容器往往不是 `window`，坐标器的 `getScrollElement` 指错窗，列表会空滚或错位。

## 如何运作

### 坐标器不是组件

[引言](https://tanstack.com/virtual/latest/docs/introduction) 原话：TanStack Virtual 是 headless UI utility，**因此不交付、也不渲染**任何 markup 或样式。心是 `Virtualizer`：默认可竖、可横，两轴叠起来才像网格。

调用方必须自己准备三层，引言示例写死了：

1. **滚动盒**：`overflow: auto` 的元素，经 `getScrollElement` 交给坐标器。
2. **内层占位**：高度（或宽度）= `getTotalSize()`，`position: relative`，用来撑滚动条。
3. **可见行**：只 map `getVirtualItems()`，`position: absolute` + `transform: translateY(start)`。

[Virtualizer](https://tanstack.com/virtual/latest/docs/api/virtualizer) 必填是 `count`、`getScrollElement`、`estimateSize`。适配器「通常替你 new」，但你拿到的仍是这个类，不是 React 组件。`@tanstack/react-virtual` 的 hook 返回同一实例；`useWindowVirtualizer` 只是把滚动元素换成 `window`。

不要把 `useVirtualizer` 读成「已经有一个列表组件」。无头行为层见 [[concepts/无头组件与根节点]]；本页的无头是**坐标**，不是菜单/对话框的焦点合同。

### react-window v1 / v2 分站

[README](https://github.com/bvaughn/react-window) 现行句：文档在 [react-window.vercel.app](https://react-window.vercel.app/)；**version 1.x** 在 [react-window-v1.vercel.app](https://react-window-v1.vercel.app/)。这是**两个站**，不是同一站点的版本开关。

### 无 W3C 虚拟列表规范

没有「Virtual List」TR。css-contain-2 §4.2 只在 `content-visibility: auto` 下写了一句旁注：在许多情况下可用来代替复杂的 "virtual list" 手法。那是**跳过屏外排绘**，节点仍在 DOM，读屏与页内查找仍看得到。JS 窗口化则卸掉屏外节点，省的是内存和提交量，不是同一合同。

两边都留：规范认为 CSS 能替代「许多」虚拟列表；万级行、回收节点、测高缓存仍是库的事。`content-visibility` 不能写成「W3C 版 react-window」。

## 必须保留的冲突

- **坐标器不是组件。** TanStack 引言明文不交付 markup；react-window 自称 component library。不要并成「都是虚拟列表组件」。
- **v1 / v2 分站。** README 仍写两个 Vercel 主机。v2 活；v1 分站本轮 404。作者 #897 改指 Wayback，并承认 Next 会删旧部署。
- **无 W3C 虚拟列表规范。** css-contain-2 只旁注 CSS 可替代许多手法；不是 List / Virtualizer 的 API 合同。
- **web.dev 旧文是 v1 面**，不能当 v2 真源。
- 工坊「现在不用」≠「窗口化不正当」。本页映射 ≠ 采用。

- 不包括：本仓库已采用声明、成品表壳、攻击或凭证。

- 易混：坐标器 ≠ 列表组件。TanStack 算位置；react-window 交组件。
- 易混：v1 分站 ≠ v2 现行站；README 有 URL ≠ 该 URL 仍 200。
- 易混：`content-visibility` ≠ 窗口化。前者留节点，后者卸节点。
- 易混：`useWindowVirtualizer` 的 `window` 是**当前浏览上下文**的窗，不是「浏览器大窗」的口头禅。
- 区分：先问「谁画节点」；再问滚动元素在哪份 document。

## 映射到本仓库

映射 ≠ 采用。稳定卡今天的长列表多半是普通 DOM。若在宿主抽屉、控制中心或消息 iframe 里做窗口化：

1. `getScrollElement` / 列表高度必须对着**实际 overflow 盒**。脚本在 TH iframe 里时，默认 `window` 是框内窗，不是 ST 主页。分层见 [[concepts/酒馆宿主与iframe分层]]。
2. 行高估计错会让滚动条和锚点一起漂；动态测高是库选项，不是规范。
3. 窗口化卸节点会让「整表 querySelector / 读屏数行数」失效；需要完整可访问树时，先看 `content-visibility`，不要默认 JS 窗口化。
4. 性能指标仍走 [[concepts/Web性能与INP]]；本页不重写 INP。
