# 向量检索入口

本页不是已采用技术，也不改工坊或角色卡栈。检索日 2026-08-14。账本枢纽是 [[queries/第三批蒸馏目标]] **B3-Vec**（约 7 条，枢纽 [OpenSearch Vector search](https://docs.opensearch.org/latest/vector-search/)）与 **B3-CDC**（约 15 条，枢纽 [Debezium `/stable/`](https://debezium.io/documentation/reference/stable/index.html)）。CDC / FTS 只作相邻对照，**不镜像**整路 15 行。不收权重镜像。

## 一句话定义

向量检索是把文本（或图、音）先编成固定维的**嵌入向量**，再按距离找近邻。它回答「语义上像什么」，不是倒排词项命中，也不是把库变更从日志里掏出来。

## 为什么重要

口语常把「语义搜 / RAG / pgvector / OpenSearch kNN / 全文 / CDC」并成一种「搜索」。合同不同：谁生成向量、存在哪、查询是精确 kNN 还是近似（ANN）、要不要和词项分混合。选错的典型后果是：用 `tsvector` 当语义检索、把变更捕获当索引刷新器，或把演示里的 Hugging Face 模型登记写成必须自建权重仓。工坊和卡 iframe **现在都不因此改栈**；行业入口仍值得留。

## 如何运作

先分四层，避免并成一个「搜」：

| 层 | 管什么 | 本批入口 | 不管什么 |
|---|---|---|---|
| 嵌入 | 文本 → 向量 | OpenSearch 可自带生成，也可自带向量 | 权重文件、盗版镜像 |
| 索引 | 向量怎么存、怎么近邻 | `knn_vector` / pgvector | WAL、词项倒排 |
| 查询 | 原始向量 / `neural` / 混合 | kNN DSL、语义检索页 | 分面 UX、站内静态包 |
| 相邻 | 词项 FTS、变更捕获 | PG 第 12 章、Debezium | 不是向量合同 |

[OpenSearch 总览](https://docs.opensearch.org/latest/vector-search/) 写明：向量可和既有字段同索引；用法包括语义检索、RAG、推荐。两条进数路：**自带向量**，或让引擎在摄入时生成嵌入。查询面至少四类：原始向量（`knn`）、语义（`neural`）、混合、神经稀疏；多模态是同一棵文档树的另一枝，不是本页第四套真源。

[近邻技法](https://docs.opensearch.org/latest/vector-search/vector-search-techniques/index/) 把 **ANN** 和精确 kNN 拆开。旧插件树 `/search-plugins/knn/` 采集日已重定向到此页；插件仓主页若仍挂旧址，不当现行入口。[kNN 查询](https://docs.opensearch.org/latest/query-dsl/specialized/k-nn/index/) 采集日记：`nmslib` 已弃用；gRPC 检索 3.2 GA。[字段映射](https://docs.opensearch.org/latest/mappings/supported-field-types/knn-vector/) 管 `knn_vector`、HNSW / IVF、`in_memory` / `on_disk`。

**pgvector** 没有独立文档站，[仓库 README](https://github.com/pgvector/pgvector) 即真源。它是 Postgres 扩展：列存向量、建索引、用距离算子查近邻。采集日记安装示意 v0.8.6、PG 13+。它**不是** CDC 连接器，也**不是** `tsvector`。

**CDC** 是变更捕获。Debezium `/stable/` 采集日等于 **3.6**（3.7 为 development）；`/2.4/` 仍活但已过时，勿钉旧树。Postgres 连接器默认 `pgoutput`。逻辑复制是手册第 29 章；逻辑解码是第 47 章。二者都不是全文、也不是向量。

**FTS** 是手册第 12 章：`tsvector` / `tsquery` / `@@`。GIN 优先，GiST 有损。`/docs/current/` 采集日指向 **PostgreSQL 18.6**。词项命中 ≠ 嵌入近邻。

## 例子

- 正例：文档站要「问意思」时，先选定嵌入合同，再选 OpenSearch `knn_vector` 或 pgvector，查询用近邻而不是 `@@`。
- 正例：只要词项、拼写、中文分词，走 PG FTS 或 B2-Search 静态包，不上向量引擎。
- 正例：要把订单行变更送到下游，走 Debezium / 逻辑复制，不把 CDC 当成「自动重建向量索引」的规范。
- 反例：把 `tsvector` 写成「Postgres 的向量检索」，或把 pgvector 写成 CDC 插件。
- 反例：引用已重定向的 `/search-plugins/knn/` 当现行 API。
- 反例：因演示登记了某个句向量模型，就把权重文件或镜像写进本仓。
- 反例：因本页出现 OpenSearch / pgvector 就写进 recipe 或发卡依赖。

## 边界与易混概念

- 不包括：接入逐步实现、集群运维、密钥、攻击检索接口、盗版语料、权重镜像、成品 RAG 皮肤。
- 向量检索 ≠ 全文检索。前者比距离，后者比词项。
- 向量检索 ≠ CDC。CDC 运的是变更流；最多当索引刷新的上游，本身不定义近邻。
- 语义检索 ≠ 原始向量查询。前者查询侧还要嵌入模型；后者你自己送向量。
- ANN ≠ 精确 kNN。近似换召回/延迟，不是同一种保证。
- pgvector ≠ 独立「向量数据库产品站」。真源在 GitHub README。
- 逻辑复制 ≠ 逻辑解码 ≠ 事务隔离。隔离页在 B2-Data，不在本页。
- 站内搜索（B2-Search）是构建后倒排或托管引擎；分面（B3-Facet）是筛选交互。都不替代嵌入近邻。
- 浏览器推理（B3-ML）是端上跑模型，不是向量库。

映射放最后，不当过滤器。

[[concepts/世界书注入路径]] 写过：向量化匹配、Outlet、`@@activate` 以 A3 为准，**不是**三张稳定卡的主用法。那是酒馆世界书激活面，不是 OpenSearch / pgvector 运行时。卡 iframe 没有「向量索引 + 嵌入服务」这层合同，见 [[concepts/酒馆宿主与iframe分层]]。工坊目录与包网关是所有权与审核，不上向量库，见 [[concepts/后端架构名词与工坊对照]]。

因此：

1. **不要**把 OpenSearch kNN 或 pgvector 写成状态栏 / 控制中心 / 世界书的运行时依赖。
2. Wiki 或独立文档站若谈语义检索，用本页当入口对照；**不等于**本仓已建向量索引。
3. 世界书「向量化匹配」与本页行业向量库不是同一条实现。
4. CDC / FTS 正文不在本页展开；隔离与多租户不在本页。

本页不写「已采用 OpenSearch / pgvector / Debezium」。
