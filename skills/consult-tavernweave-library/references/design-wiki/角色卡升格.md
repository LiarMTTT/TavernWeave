# 角色卡升格

## 一句话定义

升格把「一张可导入的角色卡」做成「一套可移植、可被同源卡取用的系统」：功能先在验收卡上做稳，再回落组件库，再装配到其它卡。

## 为什么重要

同源卡若各自改控制中心、状态栏和变量链，会分叉。升格用同一套组件、recipe 和验收门，避免每张卡重写一遍前端。

## 如何运作

验收卡是 [[entities/星月私立高等学院|星月私立高等学院]]。技术做稳后回落 `模块化组件/`，再装配到其它同源卡。[[entities/交错宙域|交错宙域]] 最新头已是已验证稳定发卡。[[entities/终末浮城|终末浮城]] 仍是未出生设定设计档，不是已装配稳定头。

四条验收同时满足才算「做稳」：

1. 离线校验全绿；
2. 仿真器注入数据通过（开发期主力）；
3. 留兼容余量；
4. 可移植到其它同源卡。

真机 SillyTavern 导入是最终门，不是每个小功能的开发节奏。节奏是：闭合链路图 → 实现 → 仿真 → 回落组件库。一次只做稳一个功能。

层序：变量系统与变量根分片 → 世界书管理器与卡族白名单 → 状态栏范式 → 卡内功能 → 平台线（创意工坊 / 创作平台）。

## 例子

- 正例：状态栏先当范式样板，自包含 UI、动效、变量根、更新规则，过四条门再给别的卡用。
- 反例：一次整吞开局页、悬浮球、工坊、地图，缺止损点，最后哪张卡都装不回去。

## 边界与易混概念

- 它不包括把 JSON/PNG 当真源。真源是组件、registry、recipe 与版本目录里的 Markdown/源文件。
- 不要和「发一张新卡」混淆。发卡是装配与回封；升格是让功能可复用。
- 怪谈笔记后来也回落进组件库，但是卡族专属模块，不混装进星月 / 交错宙域的变量与状态栏。
