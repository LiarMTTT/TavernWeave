# 打包回封路径

Source-first：改组件源，再组成卡，不手改导出 JSON/PNG。指南格式面是 A2；工坊执行面是 `card_workflow` 和模块化组件库。

## 主链

```text
profile / recipe
  → 校验（卡型、依赖、正则、区域 loader）
  → compose（按 registry 拼世界书 / MVU / 正则 / 脚本 / 开场）
  → pack（JSON，可选 PNG 嵌入）
  → 世界书版本与卡绑定同步
  → 嵌入载荷对账
```

创意库项目停在 `04-源文件` 和 `allow_release: false`，本 Vault 不产出发卡物。

工作区入口（在 `角色卡工作区/` 下跑，不是 AFV 里）：

```text
node card_workflow/tools/workflow.mjs --profile xingyue
node card_workflow/tools/workflow.mjs --profile xingyue --action validate
node card_workflow/tools/workflow.mjs --profile crossed-zone --action validate
node card_workflow/tools/workflow.mjs --profile xingyue --action full --mode release
```

增量：`workflow_targeted.mjs --changed <path>`。中文文件用 `utf8_edit.mjs --spec … --dry-run`。

README 里 xingyue / crossed-zone 的验证版本字可能停在旧号（摄入时见过 2.5.0 / 2.6.0）。2026-08-13 总监裁定：实际使用时动态改 profile，**不必**把 README 版本字对齐到产品头。命令入口不变。怪谈不在该 README 的 profiles 表里，走 `card_families.json` 的 `kaidan-note`。

## 两套清单不要混

| 清单 | 管什么 |
|---|---|
| `card_families.json` 三族 | 工作区哪几条产品线、白名单 |
| 模块化组件 `registry` + `recipe` | 一版卡由哪些组件、哪个版本拼出来 |

星月目录头是 4.0.0，组件库 recipe 仍可能停在 3.9.6。怪谈发卡 1.0.9，回落记载 0.9.7。对账时两套都写，不静默覆盖。

## 回封时容易漏的

- 交错 2.6.2：`insertion_order` / `display_index` / `cfSortKey` 要一次写齐，见 [[concepts/世界书缓存排序]]。
- git-mount 壳：`BASE` / `BASE_CF` 版本段必须和本次 runtime 一致。
- 正则 `placement` / `markdownOnly` / `promptOnly` 决定它进渲染还是进 prompt，见 [[concepts/消息渲染与正则管线]]。
- 出卡后不要再往 JSON 里补「最后一刀」；下一刀改源再 pack。

## 边界

- A2 覆盖 SillyTavern 官方导入导出字段；工坊额外字段以项目 manifest 为准。
- 本页不替代 `sillytavern-card-pipeline` skill 的逐步操作。
- 终末浮城、末日之后没有稳定 pack 产物，只有设计档和阶段源。
