# CSS平台2026

本页不是已采用皮肤，也不是工坊必须换原生控件的工单。检索日 2026-08-14。账本枢纽是 [[queries/第五批蒸馏目标]] B5-CSS26；采集行仍在 [[10-收件箱/写回候选/第五批-B5-CSS26]]。

不重写 [[concepts/视觉CSS与设计token]] 已有的 `grid-lanes` / `@scope`，也不重抄 B2-Layout 的 `field-sizing`、B2-VT 的 View Transitions。本页只蒸 2026 平台新面：锚点、Popover、Invoker、可定制 select、换行与切盒、树计数、入场过渡与固有尺寸插值。

## 一句话定义

2026 平台 CSS 新面是浏览器已打开规范入口、成熟度参差的一组能力：浮层怎么锚、谁声明式打开、原生控件怎么 opt-in 换皮、文字怎么换行切盒、树序怎么计数、入场和固有尺寸怎么过渡。它们不是一套设计系统，也不是 Rec 清单。

## 为什么重要

HUD、选项菜单、开局页表单会碰到「浮层贴按钮」「原生 select 换皮」「标题平衡换行」「高度从 none 过渡到 auto」。先认清哪份规范、哪条 Baseline、哪两个关键字不是同一合同，再谈落地。跨文档根见已有对照页；本页不上可定制 select 当已采用。

## 如何运作

### 锚点是 WD，Popover 可给隐式锚

[CSS Anchor Positioning 1](https://www.w3.org/TR/css-anchor-position-1/)（WD 2026-03-27）：绝对定位盒用 `position-anchor` / `position-area` 和 `anchor()` / `anchor-size()` 相对锚盒。`anchor-name` 是树作用域名，默认不被 containment 挡住。规范写：用 Popover API 时，宿主会设 `position: fixed` 并建立隐式锚，不必再写 `anchor-name` / `position-anchor`。

[[queries/第二批蒸馏目标]] B2-Layout 当时记「锚点仍草案」。现已是 2026-03 WD，仍不是 Rec。两边留，不把 WD 写成已完成标准。

### Popover ≠ dialog；三套调用面不要并

[Popover API](https://developer.mozilla.org/en-US/docs/Web/API/Popover_API)：平台 popover **永远非模态**。要模态走 `<dialog>`。可以把 `popover` 挂到 `dialog` 上叠语义，合同仍是两条。`:popover-open`、`::backdrop`、`showPopover()` / `hidePopover()` / `togglePopover()`。

[WHATWG](https://html.spec.whatwg.org/multipage/popover.html)：`auto` 开时关其他 popover、有 light dismiss；`manual` 不关别人、不 light dismiss；`hint` 只关其他 hint。空值默认 `auto`，非法值默认 `manual`。无障碍语义不足时作者补 ARIA。

[Invoker Commands](https://developer.mozilla.org/en-US/docs/Web/API/Invoker_Commands_API)（2025-12 Baseline Newly）：`commandfor` + `command` 声明式驱动目标。内建含 `show-popover` / `hide-popover` / `toggle-popover`、`show-modal` / `close` / `request-close`。自定义必须以 `--` 开头，在目标上听 `command` 事件。

[Open UI Invokers](https://open-ui.org/components/invokers.explainer/)：**同时写 `popovertarget` 与 `command`/`commandfor` 时，忽略 `popovertarget`，`command` 优先。** explainer 写「意图最终由 `commandfor` 取代 `popovertarget`」。表单参与 / `type=submit` 的按钮上 `command` 必须被忽略。`command` 事件不冒泡、composed、可取消。这是 explainer；冲突以 HTML / MDN 为准时两边都留。

MDN Popover 另列 **interest invokers**（`interestfor` / hover·focus），**不是** `commandfor`。三套调用面：`popovertarget`、`commandfor`、`interestfor`。Invoker 是更广的按钮合同，不是 Popover 的新名字。跨文档根仍看 [[concepts/酒馆宿主与iframe分层]]，本页不重写。

### 可定制 select：opt-in 关键字冲突

[Open UI](https://open-ui.org/components/customizable-select.explainer/) 与 [MDN Learn](https://developer.mozilla.org/en-US/docs/Learn_web_development/Extensions/Forms/Customizable_select)：元素与 `::picker(select)` **都要** `appearance: base-select`。解析器放宽，允许几乎所有子代；作者 `<button>` + `<selectedcontent>` 可换按钮面。Chromium 已出；键盘行为「因其他引擎要跟平台惯例，**未写入标准**」。`multiple` / `size` 仍在原型，**不在现行规范**。`selectedcontentelement` 未随首批发。不推荐拿它做 split button。

[CSS Forms 1](https://www.w3.org/TR/css-forms-1/)（FPWD 2025-03-25）通用 opt-in 是 **`appearance: base`**。全文无 `base-select`。`::picker()` 要渲染，起源元素与 picker **计算值都必须是 `base`**。同一条「双处 opt-in」规则，关键字两边留，不静默合成。select 定制走 CSS opt-in，不是新元素。工坊不上它当已采用。

### 换行与切盒

[CSS Text 4](https://www.w3.org/TR/css-text-4/)（WD 2026-06-08）：`text-wrap` 是 `text-wrap-mode` + `text-wrap-style` 的简写。`balance` 给标题/题注，尽量不改行数，**超过十行 UA 可当 `auto`**。`pretty` 偏质量、可贵，给正文。另有 `stable`（编辑时上行不动）和 `avoid-orphans`（MDN 简写页未列此值）。MDN 写 Chromium `balance` 限六行、Firefox 十行——实现上限与规范「可当 auto」两边留。`pretty` ≠ `balance`。

[CSS Inline 3](https://www.w3.org/TR/css-inline-3/)：`text-box-trim`（`none` / `trim-start` / `trim-end` / `trim-both`）切首末行半 leading；切多少看 `text-box-edge`。简写 `text-box`。Limited，不是 Baseline。

### 树计数、入场、固有尺寸

[CSS Values 5](https://www.w3.org/TR/css-values-5/)：`sibling-index()` 从 1 起；`sibling-count()` 含自己。走扁平树，不是选择器。`interpolate-size` 默认 `numeric-only`；`allow-keywords` 才允许长度 ↔ `auto` / `min-content` / `max-content` / `fit-content`。规范写：若有时光机就不需要此属性——存量表假定固有关键字不能动画，**不能默认开**。两端都是固有关键字仍不能插。`calc-size()` 才能对固有尺寸做算术。

[CSS Transitions 2](https://www.w3.org/TR/css-transitions-2/)（WD 2026-02-04）：`transition-behavior: allow-discrete` 才给离散属性开过渡；`@starting-style` 只在没有 before-change style 时当起点（新插入或从 `display: none` 出来）。规则不引入新层叠序，独立块要写在「目标态」**之后**才生效。`@starting-style` 只管 transition，不管 `@keyframes`。

MDN：popover / top layer 进出还要把 `display` 与 `overlay` 列入过渡，并加 `allow-discrete`，否则出场直接消失。`interpolate-size` 标 Experimental / Limited。`allow-discrete` ≠ `allow-keywords`。View Transitions 皮肤不在本页，见 [[concepts/动画库与动效管线]]。

## 必须保留的冲突

- **`appearance: base`（Forms 1 FPWD）≠ `appearance: base-select`（Open UI / MDN / Chrome 135）。** 双处 opt-in 一致，关键字两边留。
- `popovertarget` 与 `command`/`commandfor` 并存；同时写时 command 优先。Open UI 写最终取代，HTML / MDN 仍两套都活。
- Popover 永远非模态；模态是 `dialog`。`interestfor` ≠ `commandfor`。
- `pretty` ≠ `balance`；`balance` 行数上限规范与 Chromium/Firefox 实现不一致。
- `interpolate-size` 不能默认开。`allow-discrete` ≠ `allow-keywords`。
- 锚点是 2026-03 WD，不是 Rec；B2「仍草案」与现 WD 两边留。可定制 select 键盘与 `multiple`/`size` 未进规范。
- 本页映射工坊 HUD / 菜单 / 开局表单会碰到的**平台合同**；**不是**「工坊已采用这些皮肤」。

## 例子

- 正例：菜单用 Popover + 隐式锚；要模态用 `<dialog>`，不要把 popover 当模态对话框。
- 正例：声明式开关写 `commandfor` + `command="toggle-popover"`；自定义命令以 `--` 开头。
- 正例：标题 `text-wrap: balance`，正文 `pretty`；不要对长文开 `balance` 当已保证。
- 正例：入场过渡把 `@starting-style` 写在目标态之后，并把 `display` / `overlay` 列入 `allow-discrete`。
- 反例：把 `appearance: base` 与 `base-select` 合成一个关键字交差。
- 反例：同时写 `popovertarget` 与 `command` 却按旧属性解释。
- 反例：默认打开 `interpolate-size: allow-keywords`，或把 `allow-discrete` 当成固有尺寸开关。
- 反例：因本页出现可定制 select 就写进 recipe / 发卡依赖。
- 反例：重写 `grid-lanes` / `@scope` 当本页新发现。

## 边界与易混概念

- 不包括：masonry / `grid-lanes`、`@scope` / Cascade 6、`field-sizing`、滚动状态查询、View Transitions 皮肤。
- 不包括：某张卡的皮肤 token、把实验值打进 PNG。
- 易混：Popover ≠ `<dialog>`；可叠，不是一词。
- 易混：`popovertarget` ≠ `commandfor` ≠ `interestfor`。
- 易混：`pretty` ≠ `balance`；`allow-discrete` ≠ `allow-keywords`。
- 易混：`appearance: base` ≠ `appearance: base-select`。
- 易混：锚点 WD ≠ Rec；B2「仍草案」与现 WD 两边留。
- 区分：Invoker 是按钮命令合同；Popover 是非模态顶层；锚点是定位合同。三者可叠用，不是三个名字同一件事。
