# 无头组件与根节点

检索日 2026-08-14。账本枢纽是 [[queries/第二批蒸馏目标]] 的 **B2-Head**。不是已采用技术，也不是成品皮肤。

## 一句话定义

无头组件（headless）只交付行为、焦点、键盘和 ARIA，不交付视觉；根节点是这套行为去哪份 `document` / ShadowRoot 查节点、挂 Portal、锁焦点。错了根，浮层会出现在另一扇窗里。

## 为什么重要

菜单、对话框、下拉、工具提示都要：查触发器、把浮层传送到某份文档、在正确的浏览上下文里做焦点陷阱。行业库用 `getRootNode`、`EnvironmentProvider` 或 Portal 的 `container` 显式交代「根在哪」。酒馆里同一套控件可能挂宿主 `document`，也可能跑在 TH iframe 的框内文档——这是映射，不是选型。

## 如何运作

### 无头管行为，不管皮肤

[Base UI About](https://base-ui.com/react/overview/about) 写：组件 unstyled、不捆 CSS、不规定用 Tailwind 还是 CSS Modules。[Radix Styling](https://www.radix-ui.com/primitives/docs/guides/styling) 更硬：功能样式也归你，Dialog Overlay 默认不会铺满视口。

因此：**无头组件 ≠ 无样式设计系统。** 设计系统还要 token、色板、间距、字体和组件皮肤。无头只保证开合、焦点、键盘、`aria-*`；按钮长什么样仍要自己写。把 headless 当成「开箱即用的灰皮肤」会漏掉视觉层，也误读了库的合同。

行为合同对齐的是 [WAI-ARIA APG](https://www.w3.org/WAI/ARIA/apg/) 那类模式（菜单、对话框、combobox），不是某家皮肤。Radix 站点上的 **Themes** 是带样式的一层，和 **Primitives** 无头层不是同一份合同；不要用 Themes 的默认外观反推「无头已经有设计系统」。

Zag 的 Menu 只给 `data-part` / `data-state`，样式指南是选择器提示，不是主题包。Ark 包一层 React/Solid/Vue/Svelte，行为仍来自 Zag。

### Radix → Base UI 是产品线迁移

[About](https://base-ui.com/react/overview/about) 自称来自 Radix、Material UI、Floating UI 的作者。[useRender](https://base-ui.com/react/utils/use-render) 专设「Migrating from Radix UI」：Radix 用 `asChild` + `Slot`，Base UI 用 `render`。这是**同一作者群的后继产品线**，API 换了组合面。

不要写成「Radix 已死」。2026-08-14 仍能打开 [Introduction](https://www.radix-ui.com/primitives/docs/overview/introduction)、[Composition](https://www.radix-ui.com/primitives/docs/guides/composition)、[Portal](https://www.radix-ui.com/primitives/docs/utilities/portal)；文档仍教 `radix-ui` 单包和 `@radix-ui/react-*` 分包装。既有卡或工坊若已用 Radix，它还在；新栈若跟作者后继，才看 Base UI。并存，不是讣告。

Ark 走另一条：Zag 状态机 + `asChild`。三套组合面不要混抄。

### 两个 `getRootNode`，不要并成一个

| 名字 | 是什么 | 返回 |
|---|---|---|
| DOM [`Node.getRootNode()`](https://developer.mozilla.org/en-US/docs/Web/API/Node/getRootNode) | 浏览器方法。普通页给 `HTMLDocument`；影子树默认给 `ShadowRoot`；`composed: true` 可越过影子到文档 | 现有树上的根 |
| Zag / Ark 的 `getRootNode` | **机器上下文里的函数**，告诉库去哪份根做 `querySelectorAll` / `getElementById` | 文档里写 `() => ShadowRoot \| Document \| Node` |

Zag [Composition](https://zagjs.com/guides/composition) 原话：自定义环境（iframe、Shadow DOM、Electron）里全局 `document` 可能不对；把 `getRootNode` 传进 `useMachine`。影子树里可用元素上的 DOM `getRootNode()` 推出根。官方 iframe 例：`useFrame()` 拿到框内 `document`，再 `getRootNode: () => document`。

Ark [Environment](https://ark-ui.com/docs/utilities/environment) 承认内部就是 Zag。`EnvironmentProvider` 可自动探测，也可 `value={document}` 或 `value={() => shadowRoot}`。`useEnvironmentContext()` 再取出 `getRootNode`。

Radix / Base UI 不叫这个名字，但 Portal 做同一件事：默认挂**当前 JS 看到的** `document` / `document.body`；要换文档就传 `container`。

## 映射到酒馆 iframe 分层

这一节是把行业合同对照 [[concepts/酒馆宿主与iframe分层]] 和 [[comparisons/嵌入三路径对照]]。**映射 ≠ 本仓库已采用 Zag / Ark / Base UI / Radix。** 稳定卡今天的壳是宿主挂载、TH 消息 iframe、git-mount blob，不是这些库的安装声明。

先认谁造窗，再谈根：

| 窗 | 这份文档是谁 | 浮层 / 焦点 / Portal 必须对着谁 |
|---|---|---|
| 宿主页 | SillyTavern 主 `document` | 入口、悬浮球、抽屉、浮窗、小手机。Overlay 挂这里才能盖聊天区、摸 `#send_textarea` |
| 脚本框 `TH-script--…` | TH 注入的独立 iframe 文档 | 控制中心等整页脚本若在此框跑，根是**框内** document，不是宿主 |
| 消息框 `TH-message--…` | 另一份 TH iframe 文档 | 交错整页 HUD、星月薄壳。`vh`、焦点、Portal 默认都在框内 |
| 卡内 blob / `#xy-sb-inner` | 再隔一层；默认无 TH 全局 | 根是内层 document；要摸宿主必须 `injectBridge` / `hostDocument()`，不能假定 `document.body` 是 ST 主页 |
| `.mes_text` 碎片 | 不是 iframe | OMNI / 气泡 / 选项走 DOMPurify，没有无头库的浏览上下文 |

规则：

1. **入口挂宿主 `document` 时**，浮层、焦点陷阱、Portal 必须拿到**宿主根**。默认 `document.body` 若取自脚本所在窗，而脚本其实在 TH iframe 里，菜单会传送到框内 `body`：宿主看不见、磨砂糊不到聊天区、焦点锁在小框。应对：`hostDocument()` / `hostWindow()`，或把 Portal `container` / Zag `getRootNode` 指到宿主文档（同源才合法；跨域会 `SecurityError`）。
2. **整页脚本在 TH iframe 里跑时**，根就是**框内 document**。框内菜单对框内 `getRootNode: () => document` 是对的；不要强行挂到宿主，除非产品明确要「框内按钮、框外浮层」。
3. 脚本框和消息框**不是同一个 `window`**。`window.XY_RT_BASE` 到不了状态栏壳，同一条根函数也不能两边共用而不问窗。
4. 不要在消息 iframe 里 `position: fixed` 装全屏浮窗。壳挂宿主，见 [[concepts/入口外壳与HUD宿主]]。
5. Shadow DOM 只抗样式，不是安全边界。影子内的无头机器仍要 `getRootNode` 指向该 `ShadowRoot`，否则查不到触发器。

跨文档还有两条视觉合同，根选错时会一起炸：[backdrop-filter](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/backdrop-filter) 糊不到另一份文档的聊天区；iframe 里的 `1vh` 是框高不是浏览器视口。滤镜和全屏壳必须与「根在哪」同一条决策，见 [[concepts/视觉CSS与设计token]]。

行业库的 `getRootNode` 正好对应「先认窗再查节点」。本仓库没有因此改用 Zag。

## 例子

- 正例：Zag 官方在 `react-frame-component` 里把框内 `document` 传给 `getRootNode`。
- 正例：Ark 在 iframe 里包 `EnvironmentProvider`，或 `value={document}` 手写框内文档。
- 正例：Radix `Dialog.Portal container={el}` / Base UI `Popover.Portal` 的 `container` 指到与触发器同一份文档（或产品指定的那份）。
- 正例（映射）：小手机、魔棒、抽屉挂宿主；整页 HUD 的框内控件用框内根。
- 反例：把 headless 当成「已经有一套灰皮肤的设计系统」。
- 反例：写成「Radix 已死，只剩 Base UI」。
- 反例：在 TH 消息 iframe 里 `createPortal(..., document.body)`，却以为 `document` 是 ST 主页。
- 反例：因本页出现 Zag 就写进 recipe / 发卡依赖。

## 边界与易混概念

- 不包括：某张卡的组件库选型、皮肤 token、把无头库打进 PNG。
- 不包括：Headless UI（Tailwind 团队）、React Aria 的全文；要蒸另开账本。
- 易混：DOM `node.getRootNode()` 与 Zag 上下文 `getRootNode`。前者读树，后者是库的查询范围钩子；Zag 在影子里会**调用**前者。
- 易混：无头、无样式、设计系统。无头 ⊂ 无样式行为层；设计系统 = 行为 + 视觉语言。Radix Themes ≠ Radix Primitives。
- 易混：TH Blob URL 渲染（仍是 TH 前端界面）与星月 git-mount blob（默认无 TH 全局）。
- 区分：先问「脚本在哪个 `window`」，再问 Portal / 焦点 / `querySelector` 用哪份根。

### 已知冲突（不静默覆盖）

- **映射 ≠ 采用。** B2-Head 与总监口径：Zag `getRootNode` 与酒馆 iframe 分层直接相关，这是对照，不是「本仓库已采用 Zag」。
- **Radix 未死。** 作者群把后继写在 Base UI，并提供 `asChild` → `render` 迁移页；Radix Primitives 文档与包装仍在。采用「后继」或「并存」必须分开写。
- **无头 ≠ 设计系统。** 库自己说不捆 CSS；视觉仍要作者写。
- **Zag 文档路径。** 活页是 `https://zagjs.com/guides/composition`。Ark Environment 链到 `https://zagjs.com/overview/composition#custom-window-environment`，同日 WebFetch 返回服务器错误。冲突保留：以 guides 活页为准，overview 旧锚点标待核。
- **`getRootNode` 返回类型。** 官方 Menu 上下文写 `ShadowRoot | Document | Node`。GitHub PR `chakra-ui/zag#3127` 主张改成 `Element`，理由是 `Node` 没有 `querySelectorAll`。本页采用文档现场类型，PR 只作版本差，不把未发布签名写成现行合同。
- **自动探测 vs 显式根。** Ark 说 `EnvironmentProvider` 可自动探测；Zag 例程显式传框内 `document`。嵌套 iframe / 宿主桥不要赌自动探测。
- **Portal 默认值。** Radix 写默认 `document.body`；Base UI Popover 写默认挂到文档，再用 `container`。语义同属「当前浏览上下文的文档」，API 字面不同。
- **组合面三套。** Radix / Ark：`asChild`。Base UI：`render`。Zag：spread props + `mergeProps`。不能把一份示例改三个库名交差。
