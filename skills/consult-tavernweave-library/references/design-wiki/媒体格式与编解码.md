# 媒体格式与编解码

本页不是已采用媒体栈，也不是发卡媒体库。检索时间：2026-08-14。蒸馏 [[queries/第二批蒸馏目标]] **B2-Media**、[[queries/第三批蒸馏目标]] **B3-Codec** / **B3-PiP**。B3-RTC、B3-Spch 不并进本页。只谈公开格式与 API 边界，不写盗版片源、绕过 DRM 或攻击步骤。

## 一句话定义

浏览器媒体合同分四层：容器与编码怎么投递（AVIF/WebP、HLS/MSE）、帧怎么编解码（WebCodecs）、窗怎么浮（视频 PiP 与文档 PiP 是两套 API）、屏怎么不灭（Screen Wake Lock）。格式表不是卡内 `media_library.js`。

## 为什么重要

同一段「放一张图 / 播一段片」会落到完全不同的合同：`<picture>` 管格式回退，`srcset` 管分辨率，MSE 管分段喂给 `<video>`，WebCodecs 只管帧、不管封装。窗口层再拆：视频 PiP 只抬 `HTMLVideoElement`；文档 PiP 另开一份始终置顶的 HTML 文档。混成一词，就会把 iPhone 的 HLS、Chrome 的非标准轨生成器、或宿主 HUD 浮窗写成同一条 API。

## 如何运作

### 图像：格式回退 ≠ 分辨率切换

[MDN 图像类型](https://developer.mozilla.org/en-US/docs/Web/Media/Guides/Formats/Image_types) 把 AVIF / WebP 写在同一张能力表。AVIF 无渐进渲染，必须准备 JPEG/PNG 回退。WebP 现版四大浏览器都有，历史仍浅，正文仍建议用 `picture` 回退。`<picture>` 的 `type` 选格式；`srcset` / `sizes` 选分辨率或艺术指导。两套选择器不要并成「响应式一张图」。原生 `loading="lazy"` 只写在 `img` 上，CSS `background-image` 不能用；首屏 / LCP 图禁 lazy。关 JS 时浏览器不推迟加载（防追踪）。

JXL 装载、PNG-3 HDR、以及「Safari 已装 JXL / Chrome Stable 默认无」见 [[concepts/JPEG XL与HDR静图]]。本页只记 AVIF/WebP 投递与 `<picture>` / `srcset` 分工，不重抄那一页。

### 流媒体：原生 HLS ≠ MSE 喂片 ≠ 托管源

桌面 Chrome / Firefox 不能只丢 `.m3u8` 给 `<video src>`，要 MSE + JS（或播放器库）。Safari / iOS 与多数 Android 可原生播 HLS。DASH 靠 dash.js + MSE。常见可互操作基线是 H.264 + AAC + MP4；容器与编解码器参差，不是「有 MSE 就能播任意包」。

iPhone 长期没有完整 MSE。官方接法是 [ManagedMediaSource](https://developer.mozilla.org/en-US/docs/Web/API/ManagedMediaSource)：UA 可随时驱逐缓冲，适合省电流。Safari 上必须把 `HTMLMediaElement.disableRemotePlayback` 设为 `true`，或提供 HLS AirPlay 备源，否则 **`sourceopen` 不触发**。这是实验性接口，不是 Baseline。

### WebCodecs：帧合同，不是播放器

[WebCodecs](https://www.w3.org/TR/webcodecs/) 给 `VideoEncoder` / `VideoDecoder` / `VideoFrame` 等接口，对接**已有**编解码实现。规范不点名 H.264 / AV1，实现可以一个都不支持。解码配置要完整 codec string（如 `avc1.64001F`），禁写光秃 `h264`。先 `isConfigSupported()` 再配；HEVC 面窄，不要当默认档。`VideoFrame` 占编解码系统资源，用完必须 `close()`。无内置混流；音频不自动接 Web Audio。封装、清单、自适应码率仍归 MSE / HLS / `<video src>`，不要用 WebCodecs 替代播放器。登记册只防字符串撞名，不是专利或实现承诺。

轨进出另走 Insertable Streams（`MediaStreamTrackProcessor` / 规范名 `VideoTrackGenerator`）。Chrome 主线程长期暴露非标准 `MediaStreamTrackGenerator`，对不上规范 `VideoTrackGenerator`。这是邻接冲突，本页不蒸 WebRTC；对等通话与信令见 [[concepts/WebRTC信令边界]]。

### 视频 PiP ≠ 文档 PiP

[Picture-in-Picture](https://www.w3.org/TR/picture-in-picture/) 扩展 `HTMLVideoElement`：`requestPictureInPicture()`、`document.exitPictureInPicture()`、`pictureInPictureEnabled`、`pictureInPictureElement`。浮的是**那一路视频**，不是任意 DOM。规范建议进全屏时退出视频 PiP。

[Document Picture-in-Picture](https://wicg.github.io/document-picture-in-picture/) 是另一套 API：`window.documentPictureInPicture.requestWindow()`，得到一份始终置顶、与 opener 同origin 的空白文档，可塞任意 HTML。它不是 W3C `/TR`，也不是视频 PiP 的超集。文档 PiP 窗：不能设位置、不能导航到新文档、不能活过 opener、**禁止再全屏**（`requestFullscreen()` 必须禁用）。API **只在顶层 traversable 上可用**；窗里可以再嵌 iframe，包括跨源。

两套不要写成「PiP」。宿主 HUD / 抽屉 / 浮窗外壳也不是文档 PiP。桌面壳自己的 OS 窗口同样不是文档 PiP，见 [[concepts/桌面壳Electron Tauri]]。

### 全屏与唤醒锁

全屏真源是 [WHATWG Fullscreen](https://fullscreen.spec.whatwg.org/)，不是 PiP 规范的一章。iframe 要单独的 fullscreen 许可（策略默认 allowlist 常是 `'self'`）。切页 / 切应用会退出全屏。视频 PiP 的 Permissions-Policy 名是 `picture-in-picture`（MDN 册记默认 allowlist `*`）；唤醒锁是 `screen-wake-lock`（默认 `'self'`）。三道闸不要抄成同一条 `allow`。头与框策略的总合同见 [[concepts/CSP与Trusted Types]]，本页只记这三道媒体闸。

[Screen Wake Lock](https://www.w3.org/TR/screen-wake-lock/) 只有 `screen` 一种锁，且只有**可见文档**能拿到。隐藏文档自动释放，须听 `visibilitychange` 再申请。策略名 `screen-wake-lock`，默认 allowlist 是 `'self'`。规范正文仍写「extremely unstable」；实现普及不等于已升 Rec。`web.dev/articles/wake-lock` 已死，指南看 Chrome 文。

## 必须保留的冲突

- **视频 PiP ≠ 文档 PiP**：W3C WD 只管 `HTMLVideoElement`；文档 PiP 是 WICG CG 草案、无 `/TR`、禁全屏、只顶层可申请。账本与本页都不得并成一词。
- **Chrome `MediaStreamTrackGenerator` ≠ 规范 `VideoTrackGenerator`**：规范名在 mediacapture-transform；Chrome 非标准旧名仍在主线程。MDN `VideoFrame` 邻接页若仍写旧名，以 TR 为准。
- **`web.dev/articles/wake-lock` 已 404**（2026-08-14 直读）。活源是 Chrome 能力文。`web.dev/wakelock` 会跳转，不要当独立正文。
- **Wake Lock TR 自称极不稳**，与「实现已较常见 / MDN 曾标 Baseline Newly」并存；成熟度以 TR 状态为准，不升 Rec。
- **iPhone MSE**：完整 MSE 长期缺席；JS 喂片走 ManagedMediaSource，且缺 `disableRemotePlayback` / HLS 备源则 `sourceopen` 不触发。不要写「移动 Safari 已有桌面 MSE」。
- **HLS 投递分叉**：Safari / iOS 可原生；Chrome / Firefox 桌面必须 MSE + JS。web.dev 无 HLS 专文，不要用压缩图文冒充流媒体合同。
- **WebCodecs 仍是 WD（2026-07-08）**：不规定算法，实现可零支持。过期 dated TR 与 `webcodecs.org` 镜像偏旧，以 `/TR/webcodecs/` 为准。
- **文档 PiP 窗禁全屏**；视频 PiP 规范建议进全屏时退出 PiP。方向相反，不要抄错。
- 本页映射投递、帧、窗与锁；**不是**「已采用 AVIF / hls.js / WebCodecs / 任一种 PiP」。

## 例子

- 正例：英雄图用 `<picture>` 先 AVIF 再 WebP 再 JPEG；`srcset` 只负责密度；LCP 图不写 `loading="lazy"`。
- 正例：桌面 HLS 走播放器 + MSE；iPhone 走原生 `.m3u8`，或 `ManagedMediaSource` 且关掉 Remote Playback。
- 正例：自定义滤镜管线用 WebCodecs 出 `VideoFrame`，封装仍交给 MSE 或 `<canvas>` 绘制。
- 正例：只想让影片贴在别的窗上，用视频 `requestPictureInPicture()`；要带控件/歌词/进度条，才考虑文档 PiP。
- 反例：给 Chrome / Firefox 桌面只挂 `src="…/master.m3u8"`，指望原生播。
- 反例：在 TH iframe 里调 `documentPictureInPicture.requestWindow()`，或把文档 PiP 当成宿主 HUD。
- 反例：把 `MediaStreamTrackGenerator` 写成规范名，或把 WebCodecs WD 写成 Recommendation。
- 反例：引用 `web.dev/articles/wake-lock` 当活源。

## 边界与易混概念

- 不包括：卡内媒体库槽位、工坊对象存储、WebRTC 信令、语音 / MIDI、盗版片源、绕过 DRM。
- [[concepts/媒体库路径]] 管类型 / 槽 / 变体 / 来源，不是本页的 MIME 与编解码合同。
- AVIF 能带宽色或 HDR 元数据，不等于 Display P3 就是 HDR；色域合同见 [[concepts/视觉CSS与设计token]]。静图 HDR 编码面见 [[concepts/JPEG XL与HDR静图]]。
- WebCodecs ≠ MSE ≠ `<video src>` ≠ WebRTC。帧、分段、文件、对等传输是四条路。对等层见 [[concepts/WebRTC信令边界]]。
- 视频 PiP ≠ 文档 PiP ≠ 全屏 ≠ 宿主浮窗 ≠ [[concepts/小手机与宿主桥|小手机]] 抽屉。
- 唤醒锁 ≠ 防休眠整机；它只挡屏幕熄灭，且文档一隐藏就掉。
- 三维资产格式见 [[concepts/WebXR与glTF]]，不并进本页的 AVIF / HLS / WebCodecs。
- 桌面壳 OS 窗口 ≠ 文档 PiP，见 [[concepts/桌面壳Electron Tauri]]。
- B3-RTC、B3-Spch 是邻接账本，本页不收。

## 来源与证据

- 图像类型与 `picture`：MDN Image types；MDN `picture`。AVIF 无渐进、须回退；`type` 选格式、`srcset` 选分辨率。
- HLS / MSE：MDN MSE；MDN 自适应流配置。桌面 Chrome / Firefox 不能只挂 `.m3u8`；Safari / iOS 可原生。

- WebCodecs：`/TR/webcodecs/` WD 2026-07-08；登记册 2026-02-12 DRY。不规定算法；完整 codec string；`close()`。
- 轨生成器旧名：Chrome `MediaStreamTrackGenerator` ≠ 规范 `VideoTrackGenerator`。

- 文档 PiP：WICG CG 草案 2026-02-04，无 `/TR`；Chrome 文：`requestWindow()`、要手势、Limited、禁全屏、只顶层。
- 全屏：WHATWG Fullscreen 活标准。
