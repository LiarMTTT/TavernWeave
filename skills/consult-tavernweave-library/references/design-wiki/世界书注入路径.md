# 世界书注入路径

世界书是生成前的动态字典：扫描聊天，命中则把条目推进 prompt。它保证进上下文，不保证模型听话。指南：`A3_世界书优化.md`。缓存前缀专页见 [[concepts/世界书缓存排序]]。

## 生成前发生什么

```text
扫描缓冲（深度、额外源）
  → 关键词 / 常亮 / 滤镜 / 分组
  → 按 position + insertion_order 插入
  → 受 token budget 裁切
  → 和角色描述、预设、历史拼成 prompt
```

稳定卡用角色绑定 Lorebook（character_book），不是靠玩家手动开全局书。

## 条目上必须想清楚的字段

创意库 Source-first 也要求同一组语义：

| 语义 | 常见字段 | 稳定卡怎么用 |
|---|---|---|
| 策略 | constant / 关键词 | MVU 规则条目常亮；设定条目多数关键词 |
| keys | 主词 / 次级滤镜 | 常亮也要写明空数组，别用「高频」糊弄 |
| 位置 | position、role、depth | 规则浅深度前置；每楼摘要往后 |
| 排序 | insertion_order、display_index、cfSortKey | 交错 2.6.2 回封时统一 |
| 递归 | 是否被触发 / 是否触发别人 | 默认收紧，避免书打书 |
| 内容 | content | 真正进模型的字 |

`[mvu_update]` 标记的条目专门送变量规则和输出格式。Zod 脚本会等 `XingyueWorldbookReady`（及交错等同名）再拉 bundle，避免书还没亮就注册。

## 和别的路径的接口

- 开局/工坊改身份、地理、来源：经世界书管理器写条目，不直接改导出 JSON。
- 控制中心 `updateWorldbookWith`：事务写入，API 以 C2 / C1 为准。
- 变量摘要若插在 prompt 最前，缓存全废。交错把这件事做成 `promptCacheOrdering`。

## 边界

- Chat / Persona Lorebook 是较新 ST 能力；三张稳定卡主路径仍是角色书。
- 向量化匹配、Outlet、`@@activate` 以 A3 为准，不是这三张卡的主用法。
- 终末浮城 `世界书_v2/` 是素材，不是已按 3.9.6 协议排完的制作层。
