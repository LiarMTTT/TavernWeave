# 通行密钥规范入口

本页不是已采用登录方案，也不是工坊必须改鉴权的工单。检索时间：2026-08-14。只收 WebAuthn / Passkeys 规范与官方指南入口。不写攻击步骤、绕过、PoC 或凭证。

## 一句话定义

通行密钥（passkeys）是面向人的产品名：一份可发现的 FIDO 公钥凭证，用来替代口令登录。浏览器侧合同是 [WebAuthn](https://www.w3.org/TR/webauthn-3/)；客户端与漫游认证器之间的合同是 FIDO [CTAP](https://fidoalliance.org/specs/fido-v2.3-ps-20260226/fido-client-to-authenticator-protocol-v2.3-ps-20260226.html)。两者合称 FIDO2，不是同一份文本。

## 为什么重要

口令是共享密钥，服务器一旦漏库就能被复用。通行密钥把私钥留在认证器，依赖方只存公钥。规范还要求凭证按来源（origin / RP ID）收窄，浏览器和操作系统负责核对站点身份，而不是让人自己辨认真假站。工坊现网鉴权仍是 Cookie / JWT / OAuth 三件，见 [[concepts/后端架构名词与工坊对照]] 与 [[concepts/OAuth与OIDC]]；本页只给规范入口，不改那一页的落点。

## 如何运作

### 三层合同，不要并成一份

1. **宿主凭证 API**：[Credential Management](https://www.w3.org/TR/credential-management-1/) 提供 `navigator.credentials.create()` 与 `get()`。截至检索日仍是 Working Draft。
2. **Web 公钥凭证**：WebAuthn 把 `PublicKeyCredential` 接到上述宿主。注册走 `create({ publicKey })`，断言走 `get({ publicKey })`。
3. **认证器通道**：漫游认证器（USB / NFC / BLE / hybrid）走 CTAP。平台认证器走操作系统接口，不经过 CTAP 文本的每一节。

[FIDO](https://fidoalliance.org/passkeys/) 写明：同一套 FIDO2（WebAuthn + CTAP）既可部署同步通行密钥，也可部署设备绑定通行密钥。跨设备出示常见走 CTAP 的 `hybrid` 传输；那是客户端与认证器的事，不是依赖方再实现一份 CTAP。

### 现行 Level 与短名

[W3C history：webauthn-3](https://www.w3.org/standards/history/webauthn-3/) 最新一行是 2026-05-26 Candidate Recommendation Snapshot。[W3C 新闻](https://www.w3.org/news/2026/proposed-advancement-of-webauthn-3-to-w3c-recommendation/) 宣布提议升 Recommendation；提议 ≠ 已是 Rec。`/TR/webauthn-3/` 文首仍写 CR，并写明 CR 不代表 W3C 与会员背书。

[W3C history：webauthn-2](https://www.w3.org/standards/history/webauthn-2/) 钉 2021-04-08 Recommendation。检索日访问未带 Level 的 [`/TR/webauthn/`](https://www.w3.org/TR/webauthn/) **仍落到 Level 2**，不是 Level 3。新工作引用 Level 3 必须写 `/TR/webauthn-3/`。

编辑稿 [`w3c.github.io/webauthn`](https://w3c.github.io/webauthn/) 检索日仍标题 Level 3，日期 2026-07-30。活稿可以新于 CR 快照，**不能**代替 TR 引用。

### 两场仪式，不是一次 API

WebAuthn 自己分两场仪式：

| 仪式 | 宿主调用 | 结果 |
|---|---|---|
| 注册 Registration | `create({ publicKey })` | 认证器生成并收窄到该依赖方的公钥凭证 |
| 认证 Authentication | `get({ publicKey })` | 依赖方收到断言，证明用户在场且同意 |

L3 把多设备凭证（文中称 synced passkeys）写进用例。设备绑定凭证仍是通行密钥，只是不同步。不要把「同步」写成通行密钥的定义条件。

依赖方、用户代理、认证器各有一节安全与隐私考虑。本页到此为止，不摘利用面、不写绕过。

### 相邻草案不是本家族

[FedCM](https://www.w3.org/TR/fedcm/) 让人用联邦账号登录，保护的是联邦流程里的隐私，不是 FIDO 公钥凭证。[DBSC](https://www.w3.org/TR/dbsc/) 把浏览器会话绑到设备持有的密钥，目标是降低会话 cookie 被挪走后的冒用。二者检索日都是 First Public Working Draft。可以并列收藏，不能写成「通行密钥的下一版」。

## 必须保留的冲突

- `/TR/webauthn/` 短名现仍是 **L2 Rec**，不是 L3。
- L3 是 **2026-05-26 CR Snapshot**；2026-07 新闻只是提议升 Rec，**还不是 Recommendation**。
- L3 编辑稿（2026-07-30）≠ CR 快照；引用以 TR 为准。
- 外文百科仍写 L3 = FPWD，与 history 页冲突，以 W3C history 为准。
- WebAuthn ≠ 通行密钥 ≠ CTAP ≠ FIDO2。FIDO2 是前两者成对；通行密钥是可发现凭证的产品名。
- 同步通行密钥 ≠ 设备绑定通行密钥；FIDO 两者都叫 passkeys。
- Credential Management 仍是 **WD**；L1/L2 WebAuthn 已是 Rec，却接在这份 WD 宿主上。两边都留。
- CTAP 现行是 **2.3 PS（2026-02-26）**，不是 2.2。
- FedCM / DBSC 都是 **FPWD**，不是通行密钥规范。
- 平台指南（Google / Apple / Microsoft）不是 W3C 或 FIDO 规范。
- 本页映射工坊鉴权词表；**不是**「工坊必须上通行密钥」。

## 例子

- 正例：新站点引用写 `/TR/webauthn-3/`，并标明它是 CR，不是 Rec。
- 正例：产品文案说「通行密钥」，实现清单同时写 WebAuthn（浏览器）与是否需要 CTAP（仅漫游认证器）。
- 正例：同时支持同步通行密钥与安全钥匙上的设备绑定通行密钥，并在文档里分开写，不把同步当成定义。
- 反例：把 `/TR/webauthn/` 或百科的「L3 = FPWD」当成现行 Level。
- 反例：把 2026-07 提议升 Rec 写成「L3 已是 Recommendation」。
- 反例：把 FedCM 或 DBSC 叫做通行密钥；或把 OAuth 委托写成 WebAuthn。
- 反例：把本页当成攻击、绕过或 PoC 手册。

## 边界与易混概念

- 不包括：攻击步骤、绕过、PoC、Gateway token、OAuth 密钥、对象存储凭证、卡 JSON/PNG。
- 不包括：支付确认（SPC）、数字凭证（Digital Credentials）、已过期的 Token Binding 草案。
- 通行密钥 ≠ 授权模型。WebAuthn 回答「人是不是这个依赖方的持有者」；角色与权限另写。
- 通行密钥 ≠ 会话。登录成功之后的浏览器会话仍常是 Cookie；DBSC 若采用也是另一份草案。
- OAuth ≠ WebAuthn。OAuth 管谁来证明人；WebAuthn 管公钥凭证仪式。见 [[concepts/OAuth与OIDC]]。
- 生物识别材料按平台指南不离开本机；依赖方校验的是签名，不是指纹模板。本页不写采集或比对步骤。
- 易混：听到「无密码」就以为只有通行密钥。魔法链接、OTP、联邦登录都是无密码，合同不同。

## 映射到本仓库

当前工坊：Gateway 同进程管包生命周期 + 所有权 + 审核；OAuth 只证明发布者，见 [[concepts/后端架构名词与工坊对照]] 与 [[concepts/OAuth与OIDC]]。卡内 fail closed 见 [[concepts/创意工坊与安全契约]]。酒馆 iframe 无独立 OS 安装面，见 [[concepts/酒馆宿主与iframe分层]]。

本页只回答「通行密钥的规范入口在哪、哪一级成熟」。不把工坊发布者登录改成 WebAuthn，也不把卡内 HUD 写成必须注册通行密钥。这是资料库入口，不是已采用清单。
