# 酒馆与角色卡：从一轮输入到下一轮

这是共用的概念起点，不是第二份 API 手册。制卡判断、世界书首次联合规划或蓝图涉及酒馆运行依赖时，先检查当前上下文；已有完整理解就直接接着做，缺哪一段只读哪一段。纯文字项目不必加载后面的全部扩展与验证矩阵。

## 谁负责什么

| 参与者 | 本轮职责 | 不能由此推定 |
| --- | --- | --- |
| 酒馆宿主 | 管理会话、配置、请求组织、消息与扩展入口 | 宿主不是模型；各处理器的精确时序要查目标版本 |
| 角色卡容器 | 携带文本、开场白、关联世界书与可选扩展数据 | 导入不等于每个字段进请求，脚本存在不等于执行 |
| 预设 | 按所用接口配置提示组织、消息结构和生成参数 | 排在后面或使用标签，不会凭空取得更高权限 |
| 世界书 | 提供按原生条件或已核验扩展路径选入的资料 | 存在、启用、命中、处理、进入最终请求分别检查 |
| 扩展 | 提供模板、状态处理、界面等所选能力 | 不要求所有卡安装；作用域与生命周期各有合同 |
| 模型 | 根据这一次实际收到的请求生成输出 | 不自行读卡文件、完整书库、存档或玩家专用 UI |
| 玩家 | 输入消息和作选择 | 点击或说出选择不必然写状态、发消息或触发生成 |
| UI/渲染 | 展示数据，并连接已定义的交互动作 | 显示不等于保存，保存不等于下一轮已注入 |

## 最小贯通：桥梁的纯文字回合

用同一条自写规则理解整条链：“桥正常开放；涨水时关闭。”不需要模板、MVU 或前端。

1. 玩家输入“我要过桥”，当前材料另有可靠的“正在涨水”。
2. 宿主按本次配置选择卡文本、历史和适用世界书，组装实际请求。检查相关请求片段是否同时包含桥梁规则与当前水位；只有文件里存在规则还不够。
3. 模型收到这些材料后生成回应。若回应说“桥已关闭”，这只是生成的文字，本身不证明任何外部状态已改写，也不证明规则总会被遵守。
4. 宿主及已启用处理器分别处理输出、保存消息并展示。这里描述职责，不规定所有版本的保存、处理和显示先后。玩家看到的 HTML 可能不同于保存文本，也可能不同于发给模型的文本。
5. 下一轮玩家问“等水退了再过呢？”宿主根据新输入、选中历史、配置和可用状态重新组装。重新检查桥梁规则、水位与前一轮相关事实是否仍在实际请求中，不能用屏幕上的上一段回应代替证据。

教学或验收保留六样东西即可：输入、选中资料、本轮请求相关片段、输出、保存/展示结果、下一轮请求相关片段。实际运行的记录与边界用 [E07 隔离观察](../../sillytavern-runtime-debug/references/worldbook-isolated-runtime-checks.md)；未捕获请求时标“运行待验证”。

## 只在需要时接入

- **模板**：在已核验入口读取材料或状态，按条件输出或显式读取条目，再进入目标请求。条件为真但入口没到，仍不会输出；模板显示成功也不证明模型收到。精确入口、作用域、读取行为由 [E03 版本核验](../../sillytavern-api-reference/references/worldbook-version-verification.md)负责。
- **MVU/结构化状态**：初始化与 schema 先确定可用状态；本轮读取并按需投影；模型按所选协议提出更新补丁；处理器解析、校验、成功回写；UI 和下一轮再读正确作用域。补丁是提议，回写证据才是更新；schema 的结构约束不自动替代玩法结算，也不保证所有值会被夹紧或修复。精确规则仍在 [变量合同](../../tavern-card-builder/references/variable-systems.md)和[状态消费者合同](../../sillytavern-database-rolecards/references/worldbook-target-state-contract.md)。
- **UI**：按钮可能只切页面、写状态、发送聊天消息，也可能组合；逐项说明动作、写入者、持久化、是否生成以及模型可见路径。实现归 [embedded-ui](../../sillytavern-embedded-ui/SKILL.md)，这里只接回数据链，不另增 UI 文案案例。

[text / mvu_zod / hybrid](../../tavern-card-builder/references/card-types-and-runtime-dependencies.md) 是整卡运行类型，与原生、模板、局部混合世界书不是同一分类。文字和历史已够用，就停在最小回合。

## 重生成、swipe、编辑与回退

同一消息可以有不同候选；重生成、切换 swipe、编辑历史、回退到早期分支可能改变材料与状态来源。按项目实际支持的操作检查：

- 当前会话、消息与选中候选是什么；状态属于消息、会话还是另一明确作用域？
- 旧补丁是否会重复结算；谁负责重算、恢复或拒绝不支持的操作？
- 操作后的持久状态、UI 与下一轮请求是否指向同一有效分支？

保留操作前后状态、选中候选标识与下一轮相关请求片段。不承诺所有扩展自动回滚、重算或隔离 swipe；不支持时写清限制和安全路径。沿用 E07 的适用行，不另建一套测试工程。
