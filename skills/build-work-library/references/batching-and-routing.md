# 采样、项目分工与有界长任务

## 先把采样做成真实证据

已有项目按其采证方法和验收题继续；不要重新争论长任务自动化是否值得。先选代表材料：普通叙事、别名/多人关系、跨阶段或跨版本冲突、源文缺口；联网/图片若属于目标，再加入页面归属和实际图像观察样本。按用途决定数量，样本也在本轮材料/调用授权内。

顺序处理与宿主原生子 Agent 只在真实可用时对照。记录模型/宿主、样本单元、实际尝试次数、用量来源、输入/输出 token、返工、错误断言和检索题结果。缓存与推理字段按该宿主口径另记，不重复加进输入/输出；本地字符数不能冒充 token。不要用本任务账户累计用量或不同材料估算节省百分比。

`measured` 指可核对的宿主/API 回执；`estimated` 是明确标注的估算；`unavailable` 使用空值并说明缺口。工具验证格式与数值，不认证回执真实性或语义质量。样本报告必须由执行者回查证据，不能为让 `plan` 通过而自填成功。

选择策略需要检索题通过且无悬而未决的无依据断言。不一定要多 Agent；若未测出价值，串行是有效选择。token 不可见时，说明不能实施 token 总量门；只有用户明确接受后才用调用/批次数上限继续，不能擅自把未知记成零。

## 项目专用路由

在该项目的计划 `roles` 内记录实际职责，例如：采集员定位官方文图；精读员处理指定章节；人物/关系整理员更新档案；校核员回查原句与阶段；主 Agent 承担去重、冲突处理、落库和交付。按当前任务裁剪角色，不强制开满全部角色。

每个子任务收到：作品版本、改编线、源单元和哈希、允许读的既有条目、产出格式、不得写入的范围、调用/上下文上限、完成/失败信号和返回对象。默认子 Agent 返回候选文件，主 Agent 唯一调用 `usage`/`commit`；不同子 Agent 不共同写记录、索引或任务账本。同一实体跨批次保持 ID，以当前文件哈希接续。不能为了多 Agent 把整部作品重复塞给每个角色。

没有原生子 Agent 时按同一合同串行；三席 Soul 不当作三个运行中的子 Agent。后台/恢复能力逐项观察，不把可生成批次 JSON 当作宿主已经支持无人值守。

## 批次循环与停止条件

`plan` 绑定实际样本哈希、当前源集合、选中策略、明确单元列表、用户范围说明、项目角色和调用/批次上限。计量总数在库内累积，更换计划不自动清零。采样用量独立保存在 benchmark，批次计量在任务账本；报告两者时分别列出。

1. `next` 分配有界单元。已有 active 时返回同一批，先核对候选和已登记尝试，不能盲目重发调用。`execution_allowed=false` 时只做不新增模型调用的校验/落库或停下处理。
2. 宿主在实际输出/调用限制内执行分配任务；保留开始/结束状态。不要声称脚本能强制限制宿主未提供的生成长度。
3. 每次成功、失败和重试都用独立 `attempt_id` 调用 `usage`；同 ID 同数据重复登记不计两次。崩溃后无法确定调用是否已发生时先核对宿主回执，不能把“没保存结果”解释为“没花 token”。
4. 校核候选的出处、阶段、改编线与矛盾，再 `commit`。批次 ID＋候选哈希防重复，更新旧条目需要当前 Markdown 哈希；有冲突保留候选和人的版本。
5. 持续领取下一批，直到本轮单元完成或预算/范围/质量边界触发。正常批次不打断用户；完成、失败、预算不足或需选择时通知。

token 预留只是下次启动条件，实际用量可能超出单批预留；真实超额照记并阻止后续启动，不截断或隐藏费用。调用端需设置实际可用的生成上限；未计量调用存在时，token 总量门停止继续分配。授权范围变更、材料指纹变化或策略变化时重做受影响的采样/计划绑定。

`pause` 阻止继续领任务，不会远程取消已经发出的请求；取消要用宿主实际能力并保留不确定结果。`recover` 只补齐已准备的本地写入；文件被人改过则报告冲突，不覆盖。进程退出会释放本地写入互斥；没有自建后台模型服务。应用/对话关闭后是否继续由宿主决定，中断后从项目账本恢复。
