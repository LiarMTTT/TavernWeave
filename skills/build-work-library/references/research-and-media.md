# 联网与文图采集

## 先定研究问题

围绕作品、作者/制作方、版本/地区、改编线、人物/专题和允许剧透范围收集。已有本地材料先定位缺口，再补网，不把整网搜索作为每次转库的必需开销。为联网轮次记录查询词、允许来源/域名、页面/图片数量与用量上限；正常范围内连续推进。

使用宿主实际可用的搜索、网页读取和图像查看能力。优先原作与官方来源，作品 Wiki、访谈转述、社区解析和同人作品分别标身份；没有联网工具时登记缺口并继续本地材料，不声称已检索。搜索命中只生成候选，打开实际页面并比对作品版本后才能采纳。页面失效、付费/登录限制、地区版本冲突记录在悬项里，不绕过访问控制。

## 文字来源登记

为每个采纳页面记录标题、实际来源 URL、作者/机构（可见时）、发布时间/作品版本、采集时间、原作身份、改编线、使用边界及必要定位。保存自己的事实摘要和核验必需的短摘录，不整站抓取或复制受限正文；用户自带原文与网页摘录的可用范围不同。工具 `add-source` 只保存提供的 UTF-8 摘录，不负责获取页面。

`kind=web-text`、`realm=reference` 是未能确认官方/原作身份时的常见选择。不能仅凭搜索排名或 Wiki 标签提升为 `canon`。登记一版后保持冻结；内容更新另建来源 ID/edition，重新核对引用与样本计划。

## 图片资料

建立图片来源卡，包含原始页面 URL、可用原图 URL、作者/机构、作品版本、角色/场景、所需视觉特征、版权/许可证现状、采集时间、查看回执和预期用途。原图看不到就标 `not-viewed`，可以保存候选，不能写服装/构图细节为已经观察。实际看过后才用 `inspection=viewed` 与非空 `inspection_ref`；这是宿主观察回执记录，不是本地脚本验证了像素。

默认 `use=reference-only`：登记来源卡与链接，不下载、裁切或把图片打进可分发包。长期保存/视觉库导入需要针对实际候选的既有授权；已获同一范围授权可连续执行，不重复逐步确认。来源的“可看见”不等于能再分发，许可证未知就保留未知，不能填默认可商用。

MediaWiki 站点可在站点确实开放 API 时使用其 [Imageinfo 接口](https://www.mediawiki.org/wiki/API:Imageinfo)查文件页面、URL 和扩展元数据；字段不保证完整，也不代替原图查看及许可核对。本能力不固定依赖某站或专用采集服务。

## 采纳与二创使用

文字和视觉证据可以连接同一人物/场景，但保持不同来源 ID。官方设定、改编版外观和同人改绘可以并列检索，不能物理揉成一个“标准答案”。事实冲突保留各版本说明；可分发的创作资料包只带获准内容、自己的整理文本和必要来源链接。图片生成、编辑、批量下载或实际视觉库导入使用对应工具和授权，不由转库命令代办。
