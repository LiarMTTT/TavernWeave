# 项目沙盒适配合同

本合同供 Agent 在用户项目中实现沙盒时参考。TW 提供能力要求，函数名、框架、控件布局和启动入口沿用项目约定；本文中的接口名是说明用法，不代表随 Skill 附带可执行工具。

用户采用后才建立沙盒。跳过就沿原流程继续。这里的“隔离”指测试状态与真实聊天／存档分开，不是操作系统安全沙盒认证。

## 描述与装载

从工程入口得到完整模块清单，为每个模块记录 ID、真实源码路径、执行版本、文件散列、挂载入口、窗口层级、所需接口和未模拟能力。模块 ID 唯一；散列待核对时写 `unverified`。维护源和测试副本的差异另列。

装载要等待真实入口就绪；失败清理半装载资源并保留错误。卸载要清理节点、订阅、观察器、定时器和临时全局值。切换单模块／联合模式或重复装载时，检查旧实例确实退出。缺少能力就显示未接入或不支持，不用空函数、固定成功返回或隐藏模块凑齐清单。

## 隔离状态与确认

项目可用以下形状描述状态读写，也可映射到既有接口：

```text
readState() -> { context, revision, data }
commitState(context, expectedRevision, nextState) -> 实际提交结果
```

- `context` 是当前作用范围，例如测试聊天、消息楼层、swipe；必须能识别切换后又切回的陈旧确认，可额外记录会话代次。
- `revision` 在状态变化时更新。读取返回副本，避免修改待应用区就直接改到共享状态。
- 只写声明的测试存储，不能连接玩家存档、在线世界书或真实消息发送接口。真实组件触发业务写入时，同样经过受控测试宿主；适配不能放行未确认的写入。纯导航与 UI 设置按 UI 参数规则处理。
- 空白宿主可有结构性空值。初始测试预设、丰满角色、历史数据副本、自动序列的来源与作用范围先展示并确认；采用沙盒不等于确认任意数据注入。

提交顺序：

1. 读取当前范围、版本和数据，保存注入前快照。
2. 生成待应用批次，展示来源、目标、完整字段增删改和预计事件；用户确认绑定这一份内容、范围与版本。
3. 在实际写入点重新检查范围、版本与批次。编辑待应用内容、切聊天、外部状态更新都会使旧确认失效；重新生成差异后再确认。拒绝重复提交。
4. 写入后重新读取实际数据与版本，再核对模块观察值；不以请求已发送当作成功。

取消不写数据。恢复快照和重置场景也是业务写入，先说明目标并确认，不能把原聊天快照恢复到另一聊天。重置目标必须明确，不能猜测“重置”就是清空。写入或恢复失败如实记录；部分成功保留实际可读状态，不静默回滚。已确认序列内部不逐步重复询问，遇到冲突或失败就停止并记录完成到哪步。

## 事件与状态对照

提供事件订阅与清理路径，记录操作、写入、刷新、异常的实际类型、顺序、作用范围和状态版本。预计事件与真实事件分别保存。

并列呈现注入前、待注入、提交后和各模块观察到的状态。项目字段映射应说明“数据字段 → 显示格式 → 实际控件”，例如 `health: 76 → 76% → 状态栏文本`。实际值从组件／DOM 读回，期望值由独立映射算出，不能把输入数据直接复制成观察结果。

模块装载、状态一致、浏览器操作、人工观感分开记录。没有字段映射或模块未装载时，对应观察为未测试／不可用，不能记为一致。

## UI 参数与对照

每个参数说明名称、作用模块、范围、步长、单位、当前值和基线值，接入真实组件参数或局部 CSS 变量。滑条与精确输入同步；提供单项／整组复位、预设切换、按住看基线与参数导出／载入。

UI 调参只改变界面设置，不能写业务状态。在已采用范围内可即时预览，不逐次请求确认；验证其影响没有越过声明模块。导出包含源码版本、模块与参数值；版本不同先做差异检查，确认迁移再应用。并排比较时使用相同源码的两个隔离实例，不能共享可变单例或混用存储。

控件安排适应作品页面和用户调试习惯。需要面板时支持移动、收起、隐藏与重新打开；保留用户手动调整的视口。正式回落参数后移除临时覆盖，重新从维护源码加载，核对同一场景效果。

## 结果记录

输出 JSON／Markdown：源码身份、模块与入口范围、场景和数据来源、确认批次、前后状态差异、各模块观察、实际事件、UI 参数、错误与复现步骤、未接入／不支持／未测试项。私有材料留在项目测试目录。

自动检查、浏览器、真实宿主和驾驶员体验分别给出证据与状态。未测就写未测，沙盒通过不能设置 `driverAccepted` 或宣称实机验收完成。
