# 单模块与联合模拟：场景参考

以下是按真实项目搭建沙盒的参考步骤和合成数据，不是可运行的演示应用。先读[工作流程](sandbox-workflow.md)与[项目适配合同](adapter-contract.md)，使用用户作品的真实源码、既有技术栈和本机预览入口。

## 单模块：状态栏

1. 清点状态栏源码、构建入口、变量字段、事件及窗口层级。若结构是“模拟宿主 → 消息 iframe → blob 前端”，保留三层，变量桥放在源码实际访问的位置。
2. 在项目测试目录建立源码引用或可追溯副本，记录版本、依赖与散列。已有适配能复用就复用；不重写状态栏业务渲染逻辑。
3. 启动空白测试宿主，列出已装载、未接入和未模拟能力。准备合成状态 `health: 30 → 76`，展示目标聊天／楼层和预计刷新事件；明确确认后提交。
4. 对照提交后数据、状态栏观察值与格式映射。先取消一笔修改验证不写入，再确认新批次。预览等待期间切聊天或更改状态，验证旧确认被拒绝。
5. 在测试副本中移除必要变量桥、将接口故意放错窗口层级，检查失败是否暴露。修复后重新加载同一源码；不向所有窗口铺同名接口掩盖问题。
6. 手动调整字号、间距、面板宽度，检查基线、复位、导出与重新载入的效果。选择候选后回落维护源码，移除调试覆盖复测。

源码散列可用项目现有工具核对；Windows 示例：`Get-FileHash -LiteralPath "<实际源码绝对路径>" -Algorithm SHA256`。同时检查装载路径与依赖，不能只核对入口文件。

## 联合模拟：状态栏、手机与控制中心

以同一作品的三个真实模块为例：保留各自入口、样式边界、事件接口；在声明的同一测试聊天内使用正确的共享状态。未接上的模块仍出现在范围清单中。

| 场景 | 操作与观察 |
| --- | --- |
| 一次状态更新 | 准备合成 `health: 76`、`time: 08:30`，确认后读取三个模块各自实际使用的字段；没有相关显示的模块不硬造映射 |
| 控制中心改数据 | 用户在真实控件编辑后，测试宿主先显示差异和目标；明确确认才写测试状态，其他模块按原事件链更新 |
| 取消、失败与恢复 | 取消前后数据相同；模拟写入失败保留错误；恢复前说明快照范围，确认后读回实际结果 |
| 重复装载与连续事件 | 卸载再加载、连续触发刷新，检查一次操作是否被重复处理、定时器与旧订阅是否清理 |
| 切聊天再返回 | A/B 使用各自状态与存储命名空间；回到 A 读回 A，旧数据预览作废，不能复用旧确认 |
| 样式与遮挡 | 更换手机皮肤、展开控制中心，检查状态栏和弹窗是否受污染、是否遮住必要操作 |
| 基线与候选并排 | 同一源码版本建立两个隔离实例，用已确认的相同场景对照；参数、存储与事件总线各自独立 |

如果联合模拟需要调整宿主适配，只在测试层修正；真实业务缺陷则单独记录并按已授权范围修改维护源码。不要为了让模拟器通过而改坏项目契约。

## 两个失败机制参考

- **事件枚举不完整**：适配只提供更新结束事件，组件还依赖更新开始与生成停止。订阅失败后清理已有监听，界面能显示但停在初值。从源码补齐必需事件与顺序，保留失败和修复后的对照。
- **世界书未绑定**：在隔离测试宿主中构造“所需世界书未绑定”，检查前端是否给出可理解的错误及恢复入口。该合成例不证明真实酒馆绑定正常；实际绑定和扩展行为仍需实机检查。
