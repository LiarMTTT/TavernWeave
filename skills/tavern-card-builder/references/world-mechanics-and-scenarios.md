# 世界因果、玩法与可选事件

用一次过河说明世界规则怎样影响资源、路线和玩家选择，也适用于独立游戏蓝图。世界创作沿用 [worldbuilding-design.md](worldbuilding-design.md)，条目拆合与加载交给世界书设计入口，状态如何维护见 [variable-systems.md](variable-systems.md)。这里不另建调度器或状态库，也不另立创作决定。

## 由规则产生一次有意义的选择

从当前行动出发，追踪一条已确认规则：条件变化后，哪些资源或路线受限？谁执行这条规则？玩家还可以怎样做，代价是什么？写到足以支持当前选择即可，不为凑栏目补齐历史、生态、制度或远方地区。

世界规则、玩法目标和重大剧情若尚未获授权，先作为建议提出。一般细节在已授权创作范围内补足。下面全部名称、数值和设定是原创教学假设，不会自动写入用户作品。

沿用[榆冠王国的石渡](../../worldbook-design-and-writing/references/examples.md#shared-setting-the-kingdom-of-yuguan)。旧桥连着南岸城门与北岸河港；涨水时桥面不再供人通行，船工便开行顺水渡船。为避开急流，载客船只从南岸驶向北岸，空船回拖时不载客。船票代表一个座位；愿意花更多时间的人，可以走青岑高地的土路。

此例的通行条件仍是：涨水关闭旧桥，高地道路不受水位影响，但各路段可能临时封闭。高地有分别核对的往返路线；渡船只有上述单向载客航线。写清这些就足以形成选择，不必再增设船票买卖或完整经济系统。

本例把玩家已选择的目标限定为“抵达北岸”，而不是拯救城市或必须参加某条剧情。若玩家尚未选择目的地，先给选项与后果，不替其设定目标。

## 可操作机制合同

下一位作者应能据此判断一次操作是否成立、怎样结算。写清所需前提、玩家动作、效果与代价，以及失败或退出时会发生什么，并让玩家看得到结果。按机制实际需要组织，不要求固定 YAML 模板或效果数量。

| 动作 | 前提与结算 | 玩家能看到的结果 |
| --- | --- | --- |
| 查看路线 | 读取本轮已确认水位、道路封闭信息和船票；只读，无移动或扣费 | 可走路线与各自耗时；缺少信息则说明未核实 |
| 走桥 | 当前在对应起点，低水位且该边未封闭；成功移动并增加 5 分钟 | 抵达另一岸；成功前不先写成已经到达 |
| 乘船 | 在南岸，高水位，至少 1 张船票，航线未封闭；成功移动、扣 1 票并增加 10 分钟 | 北岸位置、剩余票数和耗时；没有反向航线承诺 |
| 绕高地 | 每段 15 分钟，检查该段起点和封闭条件；南岸经高地到北岸共 30 分钟 | 每段成功后的位置与累计耗时；第二段封闭不取消已走的第一段 |
| 等待或放弃 | 等待按本例约定增加 10 分钟，但不凭空改变水位；放弃不扣票、不移动 | 说明时间变化或本次停止；没有强制后续任务 |

非法动作或资料不足时说明原因，保留原状态；不靠“为了推进故事”强行过河。通行前再次核对最新条件，避免把先前可用路线当作永久可用。结算责任由已选实现负责：纯文字卡按确认规则与历史保持连续；结构化状态卡由已验证写入者处理。模型说“已扣票”不证明持久化完成。重复提交、重生成及回退的状态一致性依原运行检查，不在本页另造补丁协议。

## 有向地图与稳定节点

地点使用稳定 ID；名称、图上坐标、列表排序只是视图。每条通行边分别说明起点、终点、条件及时间/距离。反向边必须有自己的依据；地理相邻不表示可通行，能单向乘船不表示能原路返回。临时阻断标记具体边，影响双向时明确两条边，不能从一个“封路”字样猜测范围。

## 事件图表达可能性

事件 ID 与地图位置 ID 分开。边表示可能到达的后续情境，不表示它已经发生；规划节点、满足条件、玩家选择、结算成功及历史记录分别判断。

在 `event-route-choice`，玩家可以选择过河，也可以停留；若绕行青岑高地，还能登高查看河道。走高地不强制触发观察，直接乘船也不需要补演这个节点。`event-ridge-observation` 后仍可继续、返回或停止，实际移动依地图边。`event-arrival` 只有结算后确实位于北岸且出现相应到达记录时成立；“加载了抵达条目”不算到达。返回路线选择时可以再次使用已有节点，不能因原图未画循环就禁止合规动作。

节点的作者合同至少能回答当前任务需要的这些问题：

| 责任 | 本例 `event-ridge-observation` |
| --- | --- |
| 启动条件 | 已在高地且玩家主动查看；从南岸计划绕行不算已经到达 |
| 所需材料 | 当前地点、已确认通行规则及可见地形；不要加载其他路线的未来结局 |
| 可用信息与自由区 | 可描述已确认河道与路径；水位未知时保持未知，不为气氛改值 |
| 动作和退出 | 看完可继续或返回；可直接跳过，不追加新任务或固定剧情 |
| 完成证据及影响 | 本次查看的实际记录；查看本身不扣票、不移动、不强制推进其他节点 |

信息披露围绕当前选择所需事实安排。付票、单向航线和已知封路必须在相关选择前可见；景观细节可以在主动查看时补充。不能为悬念隐藏必需成本，再把后果归咎于玩家。未证实传闻保留来源，叙述顺序变化不改变事件实际先后。人物心理、对白或弧光不属于本次方法交接。

故事圈、章节布局或情节图只在作者需要时作为检查因果与节奏的工具；不要求每个场景有转折、固定阶段数或不可逆成长。先检查某个条件怎样改变选择及后果，不能把写好的纲要提升为压过玩家行动和世界规则的必然未来。新增重大剧情仍按原创作决定门。

例如可用“看清处境 → 尝试路线 → 承担已知代价 → 确认结果”检查这次短冒险：是否在选船前说明了单向航线与船票，绕行后是否承接真实耗时，到达后是否仍留有下一步选择。它检查的是信息与反馈有没有缺口；玩家选择停下时，就沿停止条件结束，不补造失败、成长或返乡来凑齐故事圈。

## 交接与反例

向世界书设计者交接“本轮需要哪些共同规则、当前节点资料与条件”，由其结合实际原生/模板能力决定拆合和加载；不把每个地点或事件自动变成一条世界书。向状态 owner 交接位置、时间、船票及封路的消费需求；能从既有字段可靠派生的可走路线不再做一个由模型另写的状态。向开场作者交接相同起点与初值；向实现者交接动作与失败反馈。具体 API、模板语法和真实加载证明分别由专项能力负责。

| 检查输入 | 应得结果 |
| --- | --- |
| 高水位、有票、人在南岸 | 可选单向渡船或未封闭的高地；旧桥不可走 |
| 高水位、无票 | 不扣成负数；仍可选高地或停止，不能强制安排赠票剧情 |
| 人在北岸、高水位 | 没有反向渡船；回程检查高地路线 |
| 高地第二段刚封闭 | 已走的第一段保留；说明前方阻断，可检查返回或等待 |
| 水位未知或路径 ID 不存在 | 不猜水位、不跳到默认节点；只保留条件可确定的选择 |
| 节点条目被读取、玩家尚未选择 | 没有移动、扣票或事件完成记录 |
| 改名、调视图坐标、重排列出顺序 | 已有 ID 与关联保持，不改变通行和事件意义 |

随包测试只验证这个原创数据例的引用、条件与成本，并用故意改坏的数据检查反例。它不是生产运行时，不执行预设或卡内脚本，也不证明实际宿主、模型或存档已经通过。真实项目仍检查本轮选择、结算前后、显示/保存/下轮模型可见性，并分别报告证据。
