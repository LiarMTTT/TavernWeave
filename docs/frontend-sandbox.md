# 前端沙盒：让 Agent 按你的作品搭建

前端沙盒适合在封装前反复调界面、试交互、检查多个前端能否正确配合。**TW 提供搭建规范和工作方法；你可以让 Agent 根据作品的真实源码，在项目自己的测试目录里搭建沙盒。** 页面布局、调试控件和预览方式按作品需要安排，沿用已有技术栈。

这一步是可选的。你可以直接跳过，继续原有制作、封装与真实酒馆测试；跳过不算失败。

> 作者在实际制卡中，通过封装前的沙盒打磨，减少了后续实机验收中的反复调整和 Bug；具体效果取决于项目与使用方式。

## 直接这样告诉 Agent

```text
采用封装前沙盒打磨，按我的作品搭建。
先读真实源码和续接记录，列出本次全部前端模块、入口与宿主依赖，推荐单模块或联合模拟。
在项目测试目录里直接加载这些源码，保留必要的 iframe／blob 层级和接口位置；沿用项目的预览方式，调试控件贴合我的前端。
测试数据先展示来源、目标聊天／楼层、前后差异及预计事件，等我明确确认后注入。目标或状态改变时，重新预览；已确认的场景序列不用每步再问。
让我用滑条和精确数值调 UI，支持基线对照、复位、预设和参数导出。手调预览尺寸时不要替我改视口。
最后把选中的改动回落到真实源码，移除临时覆盖复测，留下状态对照、复现记录和实机还需检查的项目。
```

本次不用时，直接说：“跳过沙盒，按已有制作与封装流程继续。”已经作出的采用／跳过决定可沿用。

## 选哪种模拟

| 方式 | 适合什么情况 | 搭建时要保留什么 |
| --- | --- | --- |
| 单模块 | 集中调状态栏、手机、开局页或控制中心 | 该模块的真实源码、依赖、窗口层级与交互逻辑 |
| 多前端联合 | 检查共享状态、事件同步、遮挡与皮肤干扰 | 本次范围内的全部模块、正确的状态与事件连接、各模块的样式和存储边界 |

“全量”按本次确认范围计算。让 Agent 分别列出已装载、未接入、暂不支持和本次未测试的项目；页面打开不代表所有功能都测过。

## 实际操作顺序

1. **对准源码。** 核对正在跑的文件、版本和依赖；有测试副本时记录它和维护源码的关系。不能用仿制界面代表你的组件。
2. **看数据再注入。** 初始预设、后续修改、恢复和重置都先说明目标与差异。确认绑定这一批数据和当前状态；切聊天或状态变化后旧确认失效。取消不写入，写入失败如实记录。
3. **对照各处显示。** 把注入前、待注入、实际提交后和各模块看到的值放在一起，检查该更新的地方是否更新、事件有没有重复。
4. **亲手调 UI。** 在已采用范围内，滑条和数值输入即时预览，业务数据仍走确认。保留当前值与基线，可单项／整组复位、切预设、导出和重新载入。需要面板时让它能移动、收起和隐藏；并排对照使用同一源码的两个隔离实例。
5. **把结果带回源码。** 临时样式只算候选。选定后写回维护源码，移除调试覆盖，再重放同一场景；保存 JSON／Markdown 记录、参数与尚未覆盖的宿主行为。

搭建的详细要求见[工作流程](../skills/sillytavern-embedded-ui/references/sandbox-workflow.md)、[项目适配合同](../skills/sillytavern-embedded-ui/references/adapter-contract.md)和[场景参考](../skills/sillytavern-embedded-ui/references/sandbox-recipes.md)。这些资料是给 Agent 的实施依据；具体项目仍需要实际搭建和验证。私有源码、原聊天与玩家数据留在项目测试目录。

## 沙盒之后还要检查什么

报告分别写清自动检查、浏览器操作、真实酒馆表现和你亲自试用的结果。沙盒的宿主适配有范围，真实 SillyTavern 的消息楼层、扩展、模型和设备行为仍需用新构建复验；驾驶员验收由你的明确确认给出。

本页对应[奶人教程第四章的可选小节](newbie-guide/index.html#frontend-sandbox)。第四章的 **Mock Receiver** 是接收真实酒馆运行记录的本机工具，名字里的 Mock 不表示模拟酒馆。
