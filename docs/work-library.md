# 作品资料库 · 1.6.0 使用说明

TW 新增 `build-work-library`，把小说、原作设定、同人材料、联网文字与图片参考整理成可供二创检索的资料库。本能力随 [TW 1.6.0](https://github.com/LiarMTTT/TavernWeave/releases/tag/v1.6.0) 正式提供。真实宿主发现、真实作品样本/token 试验和驾驶员体验另行记录，不由本地测试代替。

可以直接这样说：

> 把这部作品整理成二创资料库，先做人物、关系和世界规则。原作和同人分开，开局资料不要混进后期剧透。先跑代表样本，核对质量和 token，再按本轮范围分批继续。

> 补充这部作品的官方设定和服装图片参考。先打开原始页面、核对版本并实际看图，登记出处和使用边界，再整理进对应人物。

> 从资料库中整理开局阶段的主角关系和场景参考，给我一份能回查出处的二创资料包。

默认产物是人能直接编辑的 Markdown 资料正文，以及工具能查询、可重建的 JSONL 索引；需要时导出 SQLite。原作、官方补充/参考、同人分支和不确定材料保留身份与来源，不合成无出处的统一设定。

第一次使用时，提供作品/版本、已有文件或原始页面、要做的创作，以及希望避免剧透的范围。已有项目直接读取续接和采证规则；工具支持全书分批，也支持按人物/专题定向整理，不强制先读完整部作品才产出。

联网采集由当前宿主的搜索、网页和图像查看能力承担；本地工具负责保存来源、分段、精确引文校验、任务计量、接续、索引与导出。图片默认登记来源卡和链接；实际下载、裁切和长期视觉库导入按已授权选材范围进行，网页可见不等于获准再分发。

长任务先评估代表样本，记录实际 token 或明确的估算/不可见状态，再按源单元、调用/批次和可观察 token 上限执行。项目可以定义采集、精读、人物整理、校核等职责；宿主支持原生子 Agent 时使用，不支持就串行。没有真实后台能力时，不能保证关闭对话后继续运行；项目账本用于之后恢复。

人改正文后，Agent 先读最新文件和哈希，再重建索引。旧任务回写遇到版本不同会停止，避免覆盖人的新内容。遇到中断用恢复命令检查待写内容，存在新的人工作业时保留冲突；人工查询、索引重建和导出不需要模型回复。
