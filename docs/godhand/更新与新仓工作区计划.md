## 2. 三个仓库的更新分工

| 所在位置 | 长期负责 | 本次更新落点 |
|---|---|---|
| TavernWeave | Skill、Soul、创作/开发方法、公开 Library 与 Picker 来源 | 神之手连接所需的最小公开合同、能力说明、必要回执；保留纯 Skill 使用路径 |

两产品各自发布版本。神之手修界面或导出器，可以只发布神之手；TW 调整一般创作方法，可以只发布 TW。只有跨仓接口、资料结构或可观察行为变化，才安排相关组合验证。新仓先不增加第三个协议仓库、通用 SDK 仓库或独立服务仓库。

| 变化触发 | 需要更新的一侧 | 必须关注的结果 |
|---|---|---|
| 神之手编辑、预览、保存问题 | 神之手 | 当前项目重开、编辑交接和人工导出 |
| TW 的 Skill/Soul 方法变化 | TW；碰到神之手调用约定时联验 | 真实任务调用、人格状态和项目接续 |
| TW 公开资料库刷新 | TW 先发布来源；神之手按需接纳固定快照 | 条目 ID、筛选、选择、来源和预览保持一致 |
| 宿主非破坏性升级 | 拥有相关适配的神之手，必要时 TW | 已支持客户端的实际调用与保存/导出；异常组合有明确状态 |
| 项目格式改变 | 神之手 | 先备份再迁移，失败可恢复；旧数据不会因更新被覆盖 |

TW 的普通更新不会迫使神之手即时换资料快照；神之手也不在宿主中另装一份隐藏的 TW 同名 Skill。资料按精确版本与哈希构建，实际 Skill 仍由宿主安装的单一来源提供。两个产品的版本、接口版本、项目格式和资料快照分别记录，不能用“仓库分开”代替运行兼容检查。

| 文件 | 最小责任 |
|---|---|

| `.gitignore` | 排除密钥、私人作品、缓存、临时输出、构建包；不忽略活动设计和 NEXT |
| `.gitattributes` | 文本编码/换行约定与二进制识别；对后来抽取的文件先看差异，避免无关整文件改写 |
| 三份设计与计划 | 迁移本轮修订版本，按新层级修正链接和权威入口；保留需求、验收编号与历史来源 |

仓库先建立清楚的文档基线。前端目录、项目工具目录、宿主适配目录在 P0 确定技术栈后按实际代码建立；不会先选框架、安装依赖或堆出空模块。插件清单在真实接入方式确定后生成，不能为“像个插件”预写未经验证的宿主字段。

复用代码进入新仓时附来源路径、提交或内容哈希、原许可/署名和改动说明；第三方许可按真实依赖登记。私有仓库不改变来源许可义务。对外公开前再确认新仓整体许可证，首个可用版本稳定也不自动切换可见性。

## 5. 建仓与权威交接的执行顺序

下列 B 编号是建仓检查步骤，隶属现有 P0 的准备工作，不是新增产品阶段。实际执行前需要明确建仓/迁移范围；若一次授权已覆盖连续步骤，正常检查通过后顺序完成，不重复询问同一道许可。

| 步骤 | 执行动作 | 可核对的完成标志 |
|---|---|---|
| B01 复核前态 | 读 TW/旧 RPN 当前权威与 Git 状态，重新检查三处目标路径及影响 Git 定位的环境变量，保存文件清单和哈希 | 目标没有未知内容；TW 的既有修改被识别；来源与备份可读回 |
| B02 本地新仓 | 建立所需根目录，初始化独立 Git 元数据，建立初始文档，保留初始 `main`；后续开发分支使用 `codex/` 前缀 | 工作区根、Git 目录与分支读回正确；没有把 TW/原 RPN 当成新仓重新初始化 |
| B03 交接活动权威 | 按下表迁移三份文档、修正链接、写新 NEXT；确认后把 TW 旧入口标为冻结并指向新入口 | 新仓有且只有一个活动续接入口；14 条产品需求、24 个待执行场景、P0–P6 完整；TW 历史保留 |
| B04 首次源码提交 | 在明确提交范围内检查差异、精确暂存初始源码文件并提交；TW 的交接变化单独提交 | 两仓各自提交清单与 SHA 可核对；没有把用户作品/证据包混入历史 |
| B05 私有远端与恢复 | 在明确远端创建/推送范围内核对账户及仓名、创建私有仓、设置 origin、推送；在外部测试区做恢复检查 | 实际 URL、可见性、默认分支、远端 SHA 与本地一致；恢复出的受跟踪源码可读回 |

B02 的拟执行核心命令如下，**本轮未执行**；必须先通过 B01，不能对已存在且内容未知的目录照抄运行：

```powershell
git init --initial-branch=main --separate-git-dir 'E:\LocalGit\RPN-GodHand.git' 'E:\OneDrive\ST-\RPN-GodHand'
git -C 'E:\OneDrive\ST-\RPN-GodHand' rev-parse --show-toplevel
git -C 'E:\OneDrive\ST-\RPN-GodHand' rev-parse --git-dir
git -C 'E:\OneDrive\ST-\RPN-GodHand' status --short --branch
```

远端创建前不填猜测的 owner/URL，也不把私有选择当作已经建仓的回执。完成本地建仓后，即使远端步骤暂未执行，只要当前范围允许，也可继续本地 P0；远端网络不应成为已授权本地调查的阻塞理由。

### 5.2 失败与恢复

目标路径出现已有内容时先识别，不覆盖、清空或把它接进另一个仓库。新仓初始化完成但文档校验失败时，TW 原入口继续有效，修复新副本再交接。交接完成但远端推送失败时，本地新 NEXT 继续有效，记录远端待完成；不为网络失败来回切换权威。

两仓提交/推送无法做到一个原子操作，交接清单要分别记录实际进展。补做未完成的一侧即可，不改写旧提交来制造“同时完成”。任何恢复均保留旧文档与证据，不删除原 RPN。
