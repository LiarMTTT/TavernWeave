00

Vibe Code 到底是什么

不是“让 AI 随机抽一个成品”，而是一套由你驾驶的工程循环。

真正可持续的 Vibe Code，是你负责方向和验收，Agent 负责调查、执行与验证。

你定义结果
→
Agent 调查项目
→
提出方案
→
修改与验证
→
你亲自验收
角色定位你不是坐在副驾驶座上的乘客。你是驾驶员；Agent 是能操作工作台的执行者。
目

目标

最终要出现什么可见结果，而不是笼统地说“优化一下”。

界

边界

哪些文件能动、哪些结构不能碰、哪些工作必须先获得批准。

验

验收

页面能否打开、按钮是否生效、变量是否真正写入，而不是 Agent 是否声称完成。

01

先完成第一次成功交付

先让新手看到“它真的做出来了”，再补术语。

建立一个干净的练习目录不要把桌面、系统盘或唯一一份正式项目直接交给 Agent。新建一个专用文件夹，例如“我的第一个 Vibe 项目”。
用 Agent 桌面端打开文件夹先不要折腾终端、插件和复杂环境。选择一个图形化 Agent，明确它只能操作当前目录。
发送一个肉眼可验收的小任务第一次只做纯 HTML、CSS 和 JavaScript 单页，不安装依赖，不碰外部目录。
亲自打开并点击确认文件真的出现、页面能打开、按钮能工作。文字报告不等于完成。
第一次任务 · 可直接复制
这是我的第一个 Vibe Code 项目。

请先查看当前文件夹，不要访问文件夹以外的内容。

帮我创建一个可以直接用浏览器打开的单页网页，要求：

1. 页面标题为“我的第一个 Vibe 项目”；
2. 页面中央有一张卡片；
3. 卡片里有一段介绍文字和一个按钮；
4. 点击按钮后显示“项目已经成功运行”；
5. 使用纯 HTML、CSS 和 JavaScript；
6. 不安装任何额外依赖。

完成后告诉我：
- 创建了哪些文件；
- 怎么打开页面；
- 我应该检查哪些地方。
02

认识 Agent，并选一个适合自己的

不是按“初级—高级”排队，而是看你准备怎样与 AI 一起工作。

普通聊天 AI 和 Agent 的区别

普通聊天 AI

回答问题、解释代码、给出建议。更像坐在旁边的顾问。

VS

编码 Agent

能阅读项目、改文件、运行命令、查看报错、执行测试并继续修正。

30 秒 Agent 选型器

点击最符合你的工作方式，可多选。

选择你的工作方式后，这里会给出推荐。
工具主要优势更适合谁
Codex 桌面端以项目、任务线程和 Agent 调度为中心；支持差异审查、并行 Agent、Worktree 和 Skills。主要通过自然语言管理项目，希望直接使用 TW Skill 阵列，不准备频繁手改代码。
Claude Code Desktop集成文件编辑器、终端、应用预览、可视化 Diff、并行会话与电脑操作。经常制作前端、状态栏或桌面工具，需要 Agent 实际打开并测试程序。
Cursor Agents WindowAgent 工作台与完整 IDE 共存，可在本地、Worktree、云端和 SSH 环境并行运行。希望 Agent 干活，同时保留人工编辑、跳转定义、调试和完整 IDE 能力。

为什么不推荐纯新手从 CMD、CLI 和普通 VS Code 开始

它们不是能力弱，而是会把大量与目标无关的系统复杂度同时暴露给新手。

CLI 的额外负担

目录、PATH、环境变量、权限提示、会话恢复、命令报错和文本 Diff 都需要自己识别。

普通 IDE 的额外负担

文件树、插件、终端、Git 面板、调试器、任务系统和工作区信任会同时出现。

桌面 Agent 的价值

把项目、会话、权限、计划、差异和运行结果集中在同一条可见任务链里。

默认建议主要靠说人话、使用 TavernWeave：Codex 桌面端。需要频繁预览和真实操作：Claude Code Desktop。愿意进入代码层：Cursor。脚本与自动化：CLI，放进阶教程。

产品能力参考：OpenAI Codex app · Claude Code Desktop · Cursor Agents Window

03

工作区、版本记录和在线仓库

先拆开三个经常被混成一件事的概念。

1

普通项目文件夹

只是文件集合。Agent 能修改，但目录本身没有可靠的版本历史。

2

本地 Git 仓库

在当前电脑记录提交、分支、差异和恢复点，不需要先连接互联网。

3

线上 Git 仓库

GitHub、GitLab、Gitee 等服务器上的另一份仓库，用于协作、发布和异地保存已推送版本。

关键区别Agent 把工作区初始化为 Git 仓库，不等于把项目上传到了 GitHub；配置在线仓库，也不等于它一定公开。
项目文件夹
→
初始化本地 Git
→
建立本地提交
→
有发布/协作需求时再连接线上
只初始化本地 Git · 不上传
请检查当前工作区是否已经是本地 Git 仓库。

如果不是，请初始化一个本地 Git 仓库，并建立第一次基础提交。

本轮要求：
1. 不创建任何 GitHub、GitLab 或其他在线仓库；
2. 不连接任何远程地址；
3. 不上传或推送文件；
4. 告诉我哪些文件被 Git 记录；
5. 告诉我如何恢复到这次基础提交。

Git 不是完整备份

本地 Git 与项目通常仍在同一块硬盘；未提交文件、忽略文件、外部素材和运行数据也未必进入仓库。版本记录、在线同步和完整备份应当分别理解。

04

TavernWeave Skill 阵列怎样运行

不教新手训练 Skill；只教你怎样调用已经准备好的专业阵列。

Skill 不是另一个模型，也不是需要重新训练的“大脑”。它是 Agent 可以按需读取的专业工作包。

工作流程

任务进入条件、执行顺序、阶段门与交接格式。

专业规则

强制约束、禁止事项、版本边界、参考资料和范式。

验证能力

检查表、脚本、测试方式、停止条件和回滚要求。

TW 阵列中的主要职责

Skill负责什么
tavern-card-builder设计文字卡或 MVU 变量卡，处理 schema、初始化、世界书、提示词与开局协议。
sillytavern-card-components无损拆卡、组件边界、依赖声明与往返一致性。
sillytavern-card-pipeline从维护源码组装、验证、构建并打包 JSON/PNG。
sillytavern-api-reference查证 ST、Tavern Helper、STScript、EJS、宏和 MVU 的版本敏感 API。
sillytavern-runtime-debug在真实 ST 中复现问题，检查 iframe、DOM、控制台、数据与生命周期。
sillytavern-embedded-ui设计或审查开局页、状态栏、控制中心、抽屉和弹窗。
code-quality-workflow代码审计、重构门控、最小修复和回归验证。
rolecard-workshop-ops诊断和运维角色卡工坊发布链，并保护生产坐标与凭据。

一次任务如何进入阵列

用户描述任务
→

→

→

→
计划、执行、验证、交接
不是每次全阵列出动检查世界书时，不该同时加载 Live2D、工坊发布和无关前端 Skill。按需路由能减少噪声、范围膨胀与 Token 浪费。

审查和修复是两条链

代码治理链
code-audit-orchestrator
        ↓ 组织只读扫描与合并结果
code-quality-audit
        ↓ 提供具体证据
code-refactor-gate
        ↓ 判断能否重构、允许改多大
code-optimization-loop
        ↓ 执行最小安全修改并验证

Agent 不能因为“看起来不够漂亮”就重写项目。没有错误、测试、运行现象或门控结论，就不应自动进入大规模优化。

06

A0：开始驾驭 AI

A0 不是为了把提示词写复杂，而是确保开工同步、执行有边界、结束有交接。

新手版三格检查

A

我要什么

写最终可见结果，不写“高级一点”“优化一下”。

B

哪些不能动

变量结构、已有功能、框架、目录范围、发布坐标。

C

怎样算完成

能点击、能刷新、无新增报错、旧功能不坏、能恢复。

07

一次完整的 ST 开发任务

以“给控制中心新增折叠面板”为例。

保留安全副本或本地 Git 基线不要直接使用唯一一份正式角色卡。
先只读调查让 Agent 找到控制中心代码，并查询前端挂载、按钮事件和生命周期相关指南。
审核计划确认找对文件、没有准备重写整个模块、没有改无关变量，并给出了验证方式。
批准小范围执行本轮只做面板基础结构和开关，不允许顺手重构。
在真实 SillyTavern 中运行检查入口、打开/关闭、刷新、旧功能和浏览器控制台。
反馈实际现象给出操作步骤、预期、实际表现和控制台错误，不说“还是不对”。
生成交接修改摘要、文件清单、验证结果、残余风险、恢复方式和下一步。

08

新手最高频的错误

这些错误比“不会写代码”更容易直接毁掉项目。

任务太大

一次要求世界观、变量、状态栏、地图、战斗和工坊。正确做法是拆成可独立验收的阶段。

只描述感觉

“高级一点”没有明确约束。应该描述层级、布局、状态、响应式和交互。

相信完成宣言

文件可能写了但没加载，测试可能通过但真实环境仍报错。

允许顺手优化

修改范围越大，出现问题后越难定位。一次只处理一个行为路径。

没有恢复点

没有副本、本地 Git 提交或分支时，不要进行大规模修改。

换会话不交接

新会话不知道旧决策。先生成项目目标、架构、进度、禁区和下一步。

09

从新手到驾驶员

成长不是背更多命令，而是逐渐掌握范围、证据和恢复能力。

能让 Agent 做出一个小东西打开项目、描述任务、看到结果、给出具体反馈。
能保护项目限制目录、建立副本或本地 Git、先计划后执行。
能使用工程资料根据任务查询 ST DB，要求 Agent说明依据、版本和不确定项。
能使用 TW Skill 阵列检查路由是否正确，避免加载无关 Skill，要求验证与交接。
能管理复杂任务拆阶段、控制并行 Agent、保留行为契约和验收记录。

毕业检查单

  • 我最终想得到什么可见结果？
  • Agent 可以修改哪些文件，哪些绝对不能动？
  • 当前任务应该使用哪些 TW Skill？
  • 应该查询 ST 开发指南 DB 的哪个方向？
  • Agent 准备修改什么，证据是什么？
  • 我如何亲自验证结果？
  • 失败后如何恢复？
  • 切换 Agent 或新会话时，如何完成交接？
最终结论会不会写代码，决定你能否深入修改实现；会不会驾驭 Agent，决定 AI 写出的东西能否成为真正可用的项目。
