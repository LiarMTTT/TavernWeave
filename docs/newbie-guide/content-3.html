04

文件夹、Git、GitHub：真不是一回事

一个装文件，一个留后悔药，一个把提交送上网。

1

普通项目文件夹

只是文件集合。Agent 能修改，但目录本身没有可靠的版本历史。

2

本地 Git 仓库

在当前电脑记录提交、分支、差异和恢复点，不需要先连接互联网。

3

线上 Git 仓库

GitHub、GitLab、Gitee 等服务器上的另一份仓库，用于协作、发布和异地保存已推送版本。

别看见 Git 就喊“上传了”Agent 把工作区初始化成 Git 仓库，不等于项目已经上 GitHub；连了线上仓库，也不等于它一定公开。

→

请检查当前工作区是否已经是本地 Git 仓库。

如果不是，请初始化一个本地 Git 仓库，并建立第一次基础提交。

本轮要求：
1. 不创建任何 GitHub、GitLab 或其他在线仓库；
2. 不连接任何远程地址；
3. 不上传或推送文件；
4. 告诉我哪些文件被 Git 记录；
5. 告诉我如何恢复到这次基础提交。

Git 是后悔药，不是保险柜

本地 Git 通常和项目躺在同一块硬盘；未提交文件、忽略文件、外部素材和运行数据也未必进仓库。版本记录、在线同步、完整备份，三件事一个都替不了另一个。

05

TavernWeave 不是咒语，是一套施工队

你不用训练 Skill；会按任务叫对人，就已经赢了一半。

Skill 不是另一个模型，也不是等你训练的新“大脑”。它是一包随叫随到的专业流程、规则和工具。

工作流程

任务进入条件、执行顺序、阶段门与交接格式。

专业规则

强制约束、禁止事项、版本边界、参考资料和范式。

验证能力

检查表、脚本、测试方式、停止条件和回滚要求。
