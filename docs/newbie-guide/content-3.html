文件夹、Git 与 GitHub，各自负责什么

先知道文件放在哪里、版本记在哪里，再决定是否需要上传到远程仓库。

1

普通项目文件夹

用来存放项目文件。Agent 可以修改它，但文件夹本身不会替你记录每次改动。

2

本地 Git 仓库

在当前电脑记录提交、分支、差异和恢复点，不需要先连接互联网。

3

线上 Git 仓库

GitHub、GitLab、Gitee 等服务器上的另一份仓库，用于协作、发布和异地保存已推送版本。

别看见 Git 就喊“上传了”Agent 把工作区初始化成 Git 仓库，不等于项目已经上 GitHub；连了线上仓库，也不等于它一定公开。

Git 是后悔药，不是保险柜

本地 Git 往往和项目放在同一块硬盘，硬盘坏了，两者可能一起丢。未提交文件、外部素材和运行数据也未必被记录。Git 帮你回看和恢复版本，重要资料仍要另做备份。

TavernWeave 怎样组织 Agent 的工作

Skill 提供具体任务的做法，Harness 把工具、规则与检查流程组织起来。

把 AI 比作高达，TW 的 Skill 与 Harness 组合就像操控它的 OS：知道遇到什么任务该调用哪些方法，动手前查什么，做完后怎样检查。Skill 本身是一组指引、资料或脚本，不需要你另外训练一个模型。

工作流程

任务进入条件、执行顺序、阶段门与交接格式。

专业规则

强制约束、禁止事项、版本边界、参考资料和范式。

验证能力

检查表、脚本、测试方式、停止条件和回滚要求。
