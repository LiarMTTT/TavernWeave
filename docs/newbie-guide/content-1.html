先坐对位置你不是等成品掉下来的乘客。你是驾驶员；Agent 是能操作工作台的执行者。
目

目标

最终要出现什么可见结果，而不是笼统地说“优化一下”。

界

边界

哪些文件能动、哪些结构不能碰、哪些工作必须先获得批准。

验

验收

页面能否打开、按钮是否生效、变量是否真正写入，而不是 Agent 是否声称完成。

01

先做出一个真能点的东西

第一课不背术语：文件出现、页面打开、按钮真有反应。

建立一个干净的练习目录不要把桌面、系统盘或唯一一份正式项目直接交给 Agent。新建一个专用文件夹，例如“我的第一个 Vibe 项目”。
用 Agent 桌面端打开文件夹先不要折腾终端、插件和复杂环境。选择一个图形化 Agent，明确它只能操作当前目录。
发送一个肉眼可验收的小任务第一次只做纯 HTML、CSS 和 JavaScript 单页，不安装依赖，不碰外部目录。
亲自打开并点击确认文件真的出现、页面能打开、按钮能工作。文字报告不等于完成。
第一次任务 · 可直接复制
这是我的第一个 Vibe Code 项目。

请先查看当前文件夹，不要访问文件夹以外的内容。

帮我创建一个可以直接用浏览器打开的单页网页，要求：

1. 页面标题为“我的第一个 Vibe 项目”；
2. 页面中央有一张卡片；
3. 卡片里有一段介绍文字和一个按钮；
4. 点击按钮后显示“项目已经成功运行”；
5. 使用纯 HTML、CSS 和 JavaScript；
6. 不安装任何额外依赖。

完成后告诉我：
- 创建了哪些文件；
- 怎么打开页面；
- 我应该检查哪些地方。
02

先认清 Agent，再选你的工作台

别按“初级—高级”排队；看它能不能配合你的干活方式。

聊天 AI 出主意，Agent 下场干活

普通聊天 AI

回答问题、解释代码、给出建议。更像坐在旁边的顾问。

VS

编码 Agent

能阅读项目、改文件、运行命令、查看报错、执行测试并继续修正。

Agent 到底多了一双什么手

聊天 AI 像顾问：你提问，它给文字、代码或建议。Agent 则被允许碰工作台——搜文件、改代码、跑命令、看报错、开页面，再根据结果继续修。

关键不在它更会聊天，而在于：它不只告诉你怎么做，还能在你划出的范围里真正动手。

最简单的比喻聊天 AI 像隔着电话告诉你怎么修东西；Agent 像来到工作台前，能够查看现场、使用工具、动手修改，再检查结果。

Agent 不是一锤子买卖，它会边干边查

一次靠谱交付，通常要把下面这圈跑上好几遍：

听懂任务
→
查看现场
→
决定下一步
→
使用工具
→
检查结果
→
继续修改或交付
听懂你要什么Agent 先判断最终想看到什么结果、当前处理哪个项目、哪些地方允许修改、哪些内容不能碰，以及做到什么程度才算完成。如果要求不清楚，它就只能猜。
查看项目现场它会搜索和打开文件，确认功能写在哪里、项目使用什么结构、有没有现成规则、当前有没有未保存的改动，以及应该修改源码还是构建后的成品。这一步像工人开工前先检查房间，而不是进门就砸墙。
决定下一步做什么根据刚看到的信息，它可能继续搜索、阅读说明、提出方案、修改一小部分内容、运行项目、打开页面，或者发现风险后先询问你。
使用工具实际动手只有使用工具时，项目才会真正发生变化。编辑文件才会写入代码，运行构建才会生成产物，打开浏览器并点击才知道按钮是否有效。
根据结果继续修正如果运行失败，Agent 会把错误当成新的线索，继续经历“修改—运行—发现问题—查找原因—再修改”的循环。它不是一开始就知道全部答案，而是在每次行动后读取结果，再决定下一步。
完成后向你交付它应说明修改了什么、动了哪些文件、实际运行了哪些检查、哪些结果已经确认，以及哪些部分仍需要你亲自验收。
嘴上干活不算干活“我准备修改”不等于文件变了，“应该可以”也不等于验过。盯工具动作和返回结果，别只看总结写得多漂亮。

拿“复制按钮”跑一遍

你交给 Agent 的任务
给这个页面增加一个复制按钮，
点击后把模板复制到剪贴板。

Agent 可能会这样工作：

  1. 打开项目，找到页面文件；
  2. 查找模板内容和现有按钮样式；
  3. 添加复制按钮和点击逻辑；
  4. 打开页面；
  5. 实际点击按钮；
  6. 检查剪贴板内容；
  7. 如果按钮没有反应，读取报错并继续修改；
  8. 验证成功后向你报告改动。
生成代码不等于完成任务如果它只生成了一段按钮代码，却没有写入文件、打开页面和实际点击，那么它只完成了“提出答案”，还没有完成真正的交付。

别许愿，给 Agent 一张施工单

你不必先会写代码，也不用提前猜该改哪个文件。先把最重要的事钉死：最后到底要出现什么结果。

热知识你的知识越全面，指挥 AI 的效率就越高，所以该看教程就看。你不必先成为开发者，但越理解自己在做什么，越能给出准确目标、判断 Agent 有没有找对方向。实在不行，就给 AI 提供可靠样本，让 AI 先搞明白，再用你能听懂的方式教你。

VS

更容易成功

优化奶人教程的 PC 页面，提高信息密度和正文可读性。

允许修改布局和样式，不要修改教程正文与手机端功能。1440 宽度下正文空间应更大，页面不能出现横向滚动；如果需要重做结构，先告诉我。

你没有告诉 Agent 应该写哪一条 CSS，但已经把结果、边界和验收说清楚了。这就足够让它开始调查。

一句话管不住一个完整项目

项目不是生日愿望。你要一轮轮看现场、收范围、批方案、验结果：

  1. 先给出目标和边界；
  2. 观察 Agent 找到了什么；
  3. 对风险较高的方案先审核；
  4. 让它执行并检查；
  5. 根据实际页面继续反馈；
  6. 满足验收条件后再结束任务。

反馈也别只扔一句“不对”“不好看”“没成功”。把操作、预期和实际表现摆出来：

可执行的反馈
我在 1440 宽度下查看了页面。

预期：
左侧目录只显示章节标题，需要时再展开。

实际：
第一章仍然默认展开，占用了大部分高度。

请只修正目录默认展开逻辑，不要调整正文。

你负责Agent 负责
决定想要的结果调查项目和相关资料

记住这句话你不需要告诉 Agent 每一行代码怎么写，但必须告诉它要到哪里、不能撞什么，以及怎样才算真正到达。

纯新手别急着钻进黑窗口

CMD、CLI 和普通 VS Code 并不弱，只是会把目录、权限、环境和插件这些杂活一次全倒到你面前。

CLI 的额外负担

目录、PATH、环境变量、权限提示、会话恢复、命令报错和文本 Diff 都需要自己识别。

普通 IDE 的额外负担

文件树、插件、终端、Git 面板、调试器、任务系统和工作区信任会同时出现。

桌面 Agent 的价值

把项目、会话、权限、计划、差异和运行结果集中在同一条可见任务链里。

默认建议主要靠说人话、使用 TavernWeave：Codex 桌面端。需要频繁预览和真实操作：Claude Code Desktop。愿意进入代码层、自己挑供应商：优先 OpenCode。Cursor 可以当完整 IDE 用，但国内环境不建议没验货就购买 Pro+ 或 Ultra。脚本与自动化：CLI，放进阶教程。

手机端买 ChatGPT：先别把三张账单混了

这里只算官方套餐这笔账ChatGPT 套餐、OpenAI API 和第三方模型 API 是三套服务、三套计费。下面不讲第三方接入，也不把套餐购买硬写成手机号闯关。

OpenAI 当前说明是：创建账号和使用 ChatGPT 已不再要求手机号验证。如果注册时出现手机号页面，先确认是否进入了 OpenAI Platform 的首次 API Key 流程——首次生成 API Key 目前仍可能要求手机号验证，这与购买 ChatGPT 套餐不是同一件事。

中国大陆目前不在 OpenAI 公布的 ChatGPT 支持地区列表中。因此，“中国大陆手机号不能用于相关验证”和“购买 ChatGPT 套餐需要绕过手机号”不能写成同一件事；真正需要检查的是服务地区、应用商店地区、付款资料与账号归属是否一致。

iPhone 与 iPad

位于支持地区、并且能从当前 Apple App Store 下载官方 ChatGPT 应用的用户，可以：

  1. 从 App Store 安装 OpenAI 发布的官方 ChatGPT 应用；
  2. 登录自己的 OpenAI 账号；
  3. 在应用内选择升级套餐；
  4. 通过 Apple 的订阅确认页面完成购买；
  5. 以后由 Apple 管理扣款、续订、收据和退款入口。
Apple 礼品卡有地区限制礼品卡、Apple 账号商店地区和使用地区需要匹配。礼品卡不能跨国家或地区兑换；部分订阅即使已有余额，也可能要求账号绑定有效付款方式。更换设备后套餐没有恢复，可在 ChatGPT iOS 应用设置中选择 Restore purchases。

Android

位于支持地区、并且拥有正常 Google Play 环境的用户，可以：

  1. 从 Google Play 安装 OpenAI 发布的官方 ChatGPT 应用；

  3. 在应用内选择升级套餐；
