Vibe Code 不是许愿柳

按现阶段 AI 和 Agent 的能力水平，我更愿意把它们看成“外置大脑＋力工”：帮你想办法，也替你做具体工作。

在这份教程里，Vibe Code 指的是：你用自然语言说明想做什么，让 AI 协助分析、写代码、修改项目，再通过检查和实际使用逐步改进。

“外置大脑”帮你整理想法、查资料、比较方案，把暂时不懂的问题解释清楚。“力工”负责阅读文件、修改代码、运行检查，遇到问题后继续修正。这两部分结合起来，才有了从讨论走到实际成果的可能。

把 AI 比作高达，TW 的 Skill 与 Harness 组合就相当于操控它的 OS（操作系统），你是驾驶员。Skill 提供处理具体任务的方法，Harness 把工具、执行流程与检查机制组织起来；两者配合，让你能用清楚的指令和反馈驾驭这台机器。

你负责判断要做什么、接受哪些取舍，以及做出的东西是否符合自己的用途。高达已经能帮你干不少活了。至少现阶段，驾驶舱还不能空着。

别只做一个许愿者

“帮我做一个好用的角色状态栏”，可以作为讨论的开始。接下来还得逐渐说清楚：你想看到哪些信息，最常用什么操作，现有角色卡的哪些内容需要保留。

一句“优化一下”能有多少种理解？很容易得到一份 AI 自己觉得挺满意的作业。至于你用起来满不满意，那可就未必了。

你不用一开始就写出完美需求，也不用提前知道该改哪个文件。可以让 Agent 帮你梳理，拿出方案或样稿后再讨论。调查发现限制，就调整做法；实际用着不顺，就把哪里别扭告诉它。

当驾驶员，也不要求你替它干完所有活。你需要做的是理解关键选择，给出判断，并在结果偏离预期时及时纠正方向。

目

预期目标

先说希望看到什么效果。比如：“打开页面就能看到角色状态，点击按钮可以展开详细信息。”具体怎么实现，可以让 Agent 调查项目后提出方案。

界

修改边界

哪些地方可以改，哪些必须保留，哪些操作需要先征得你的同意。比如：“可以调整状态栏布局，但保留现有变量名。”省得你只想修一个按钮，整页却被重新装修了。

验

验收的面和点

Agent 先完成自己能做的检查，再列出需要你验收的方面与具体操作：看哪里、点什么、预期出现什么。已验证结果和仍需亲验的项目分别写清楚。

例如，验收“功能表现”时，要说明页面能否正常显示、按钮有没有反应、变量是否真的写入；验收“使用体验”时，要让你判断常用信息好不好找、操作顺不顺手。需要回到真实酒馆检查的项目，也要单列出来。“已经完成”这四个字很好写，实际效果还得看这些具体结果。

00.1

驾驶员在场／无人值守

两组可复制提示词：人在时一起确认方向；要离开时，先把可以推进的范围交代清楚。

下面两组提示词按作者工作区的“驾驶员在场协议”整理。使用时填好方括号里的内容，再发送给 Agent。它们约定的是当前任务怎么协作；能否持续运行，还取决于客户端与任务是否保持运行，复制提示词本身不会创建定时任务。

驾驶员在场：先看计划，再确认开工

适合你正在看方案、讨论取舍，或需要边做边确认的任务。先让 Agent 说明改动面、验证方式与顺序，你确认之后，它继续完成已经授权的工作。

同一范围已经确认后，继续完成已授权的工作，不重复询问同一道门。新增范围或需要新的授权时，说明原因再问我。普通回答、解释和只读分析直接进行。

大阶段结束时列出验收对齐项：做了什么、怎么验证、哪些已通过、哪些还没验，以及需要我验收的面和点。每项写清检查对象、操作方式和预期结果；需要真实环境或我亲验的项目单列，等我确认后再记为已验收。小任务简短结算即可。

只有我明确授权“自主推进”或无人值守时才切换方式；不能因为我暂时没回复，就推断我已授权。分不清时，按驾驶员在场处理。

无人值守：在已经说清的范围内自主推进

适合你已经确认了方案，准备让 Agent 继续处理一段工作。原协议要求“按既有规约自主推进到底，事后交诚实结算”。所以先写明要做到哪一步，完成后还剩哪些检查由你回来处理。

没有成功时，带着现象回来记录你打开了哪个文件、点了哪里、实际看见什么；有报错就保留原文。让 Agent 解释已经查明的原因和仍需确认的部分，再给恢复步骤。不要把“检查通过”当作你已经亲手试用成功。

聊天 AI 出主意，Agent 下场干活

普通聊天 AI

没有接入项目工具时，主要通过对话解释问题、给建议或生成文本。需要你把材料和结果来回搬运。

VS

编码 Agent

接入文件、命令行等工具后，可以读取项目、执行修改、查看运行结果，再继续处理问题。能做哪些事，要看客户端提供了什么工具和权限。

Agent 到底多了一双什么手

区别在于它有没有工具可用、能不能根据工具结果继续行动。同一个模型接入不同的工作环境，能完成的任务也会不同。

放回高达这个比喻里看：模型提供理解和判断能力，工具让它能操作工作台，Skill 与 Harness 则组织这些能力。驾驶员需要知道这台机器现在能干什么，哪些动作还做不到。

界面名字只是入口有些聊天产品也能调用工具，有些 Agent 当前却只能读文件。看它实际拿到了哪些能力，比单看产品名字更有用。

Agent 不是一锤子买卖，它会边干边查

以修一个按钮为例，Agent 往往需要先读源码，再改、再试；第一次没修好，就顺着报错继续查。下面这圈可能要走几遍：

听懂你要什么先弄清你期望的结果、所在项目、可改范围和验收标准。能从项目里查到的事先查，涉及你的偏好或新授权时再问你。
查看项目现场搜索相关文件，看看已有规则和实现，确认当前改动由谁留下、应该修改源码还是生成物。进门先认房间，总比抡起锤子才问承重墙在哪强。
决定下一步做什么根据刚看到的信息，它可能继续搜索、阅读说明、提出方案、修改一小部分内容、运行项目、打开页面，或者发现风险后先询问你。
使用工具实际动手编辑工具写入文件，命令工具运行构建或测试，浏览器工具检查页面。它在回复里说“准备修改”，只是说明意图，还要看后面实际执行了什么。
根据结果继续修正运行失败会提供新的线索。Agent 应读取错误、定位原因，再做有依据的修改；同一个问题反复修不好时，先重新检查假设，别继续往上糊补丁。
完成后向你交付说明改了什么、哪些检查通过，以及哪些结论还没验证。需要你验收的部分，应写成“看哪个页面、做什么操作、预期出现什么结果”。
别被漂亮总结哄住一句“已全面优化”听着很忙，实际可能只改了按钮颜色。让它指出具体改动和检查结果，你才知道这轮工作推进到了哪里。

拿“复制按钮”跑一遍

你交给 Agent 的任务
给这个页面增加一个复制按钮，
点击后把模板复制到剪贴板。

Agent 可能会这样工作：

  1. 打开项目，找到页面文件；
  2. 查找模板内容和现有按钮样式；
  3. 添加复制按钮和点击逻辑；
  4. 打开页面；
  5. 实际点击按钮；
  6. 检查剪贴板内容；
  7. 如果按钮没有反应，读取报错并继续修改；
  8. 验证成功后向你报告改动。
生成代码不等于完成任务这次要求的是一个可用的复制按钮。只给一段代码还没完成要求；如果受工具限制无法操作浏览器，也应交代已完成到哪一步，把点击和粘贴检查留成明确的待验收项。

项目越做越清楚，需求也会跟着调整

调查之后，你可能发现旧功能有限制；试用之后，也可能才意识到另一种做法更合适。这些调整很正常，关键是把新的决定说清楚，再按确认过的范围推进：

  1. 先给出预期目标和修改边界；
  2. 查看 Agent 的调查结果，修正不成立的假设；
  3. 确认本轮计划；已授权的范围内无需反复批准同一步；
  4. 让它执行并检查；
  5. 根据实际页面继续反馈；
  6. 满足验收条件后再结束任务。

反馈也别只扔一句“不对”“不好看”“没成功”。把操作、预期和实际表现摆出来：

请只修正目录默认展开逻辑，不要调整正文。

文件树、插件、终端、Git 面板、调试器、任务系统和工作区信任会同时出现。

手机端买 ChatGPT：先别把三张账单混了

先认清自己买的是什么ChatGPT 订阅、OpenAI API 和第三方 API 分别计费。这里讲手机上购买 ChatGPT 订阅；买了套餐，不代表 API 账户也有可用余额。

截至 2026-09-04，OpenAI 帮助页说明：创建账号和使用 ChatGPT 不再要求手机号验证；首次生成 API Key 则要求验证。如果看到了手机号页面，先确认自己进入的是哪条流程。

中国大陆目前不在 ChatGPT 官方支持地区列表中。购买前要核对服务地区、商店地区和付款资格；手机内购只提供付款入口，不会改变服务的地区要求。

iPhone 与 iPad

位于支持地区、并且能从当前 Apple App Store 下载官方 ChatGPT 应用的用户，可以：

  1. 从 App Store 安装 OpenAI 发布的官方 ChatGPT 应用；
  2. 登录自己的 OpenAI 账号；
  3. 在应用内选择升级套餐；
  4. 通过 Apple 的订阅确认页面完成购买；
  5. 以后由 Apple 管理扣款、续订、收据和退款入口。
Apple 礼品卡有地区限制礼品卡、Apple 账号商店地区和使用地区需要匹配。礼品卡不能跨国家或地区兑换；部分订阅即使已有余额，也可能要求账号绑定有效付款方式。更换设备后套餐没有恢复，可在 ChatGPT iOS 应用设置中选择 Restore purchases。

Android

位于支持地区、并且拥有正常 Google Play 环境的用户，可以：

  1. 从 Google Play 安装 OpenAI 发布的官方 ChatGPT 应用；
  2. 登录自己的 OpenAI 账号；
  3. 在应用内选择升级套餐；
  4. 通过 Google Play 的订阅确认页面完成购买；
  5. 以后由 Google Play 管理扣款和续订。
Google Play 礼品卡不是通用跨区付款方式Google 要求礼品卡购买地、币种、Google Play 国家资料以及用户实际所在国家或地区一致。礼品卡只能在购买国家兑换和使用。
设备没有 Google Play 怎么办jieoupen/Google-Play-Store 是社区整理的 Google 服务框架安装资料，只能作为设备兼容性参考，不是 OpenAI、Google 或设备厂商的官方教程，也不解决商店地区和付款资格问题。仓库中包含第三方安装器、APK 镜像与虚拟空间方案；新手应优先使用设备厂商支持的 Google 服务环境，不要在未知安装器或虚拟空间中输入 Google、OpenAI 或付款账户凭据。
移动端内购不是地区绕过方案不要使用临时接码、来源不明的成品账号、虚构的常住地区或账单资料，也不要购买与账号地区不匹配的礼品卡。Apple 和 Google 内购只是官方移动端支付渠道，不会改变 OpenAI 对服务地区的要求；从不支持地区访问或使用不受支持地区的付款方式，可能导致账号被阻止或暂停。
