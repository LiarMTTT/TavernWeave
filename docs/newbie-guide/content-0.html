TavernWeave 到底能做什么

一句话说需求，TW 负责分诊、查资料、施工、留证据，再把最终验收交回你。

TavernWeave 是一套由 20 个专职 Skill 组成的制卡与 Vibe Coding 工程系统。你不需要知道每个 Skill 的英文名；先判断自己是在想项目、照镜子复盘成长、做角色卡、搭前端、查故障，还是准备安装发布。

项目规划与脑暴 NEW · V1.2.0

适合“我有一个想法，但不知道该怎么落地”“项目太大，Agent 越做越散”或者“先帮我想清楚，不要马上写文件”。

把愿望收成第一版

从项目类型、核心价值和功能方向，收束到总设计案、最小可玩/可用闭环与后续路线。

按体量生成蓝图

小项目用单蓝图，大项目拆领域蓝图；不提前制造空壳，也不让任意步骤无限长出子步骤。

Soul 三席联席

阿瞳看用户与创作核心，MTTT.sir 查技术和逻辑门，强尼·银手审前端方向，最后共享一份收束账本。

照镜子看成长 NEW · V1.3.0

从当前 Codex、Chat、项目和交付证据重评完整能力网络，输出文字表单与七章报告；再次核验只比较量表可比项。

脑暴模式，Soul 联席

先判断项目类型，帮我收束总设计案、第一版核心和后续更新路线。不要直接写文件。

角色卡与变量系统

适合从零做卡、把纯文字卡改成变量卡，或者为旧卡增加背包、任务、关系、商城、世界书和状态栏。

从零搭角色卡

先访谈玩法与叙事目标，再建立变量结构、初始化、更新规则、正文、开局和展示层。

旧卡增量升级

先调查原卡的变量方言与真实结构，尽量保留原味，再增加组件；不把整张卡静默重封。

拆分与重新组装

把大 JSON 拆成可维护的组件源码，逐项验证后再按明确授权组装或发布。

你可以直接这样说“帮我从零制作一张 MVU 角色卡，先访谈，不要直接写文件。”或“把这张纯文字卡改成 MVU 卡，尽量保留原来的味道。”

前端、交互与美术 NEW · V1.3.0

适合制作开局页、状态栏、悬浮球、抽屉、弹窗、控制中心和媒体界面，也适合在动手前判断是否真的需要复杂前端。

先选承载面

判断同层、独立或嵌入式前端是否适合；不适合时会明确劝退，并给出更轻、更稳的替代方案。

完整设计与动效资料

从 462 个设计、194 个动效、86 个概念和 1,609 条蒸馏账本里按需筛候选，再结合主题、信息密度和真实视口落地。

灵魂杀手审查

用强尼·银手同人彩蛋人格直说层级、排版、配色、动效和 AI 模板味的问题，并给出修改顺序。

前端审查
灵魂杀手！

检查这个前端的视觉层级、中文排版、配色、动效目的和 390px 窄屏表现。可以直说，但每个问题都要给证据、影响、修法和复验方式。

调试、审计与优化

适合“变量明明变了，状态栏没刷新”“按钮在预览页能点，进酒馆就坏”“刷新或切换聊天后功能失效”等真实运行问题。

沿链路找最早断点

区分变量写入、重新读取、事件、DOM、iframe 和渲染层，先找到第一处不符合预期的位置。

安全与性能审计

检查危险输入、凭据、重复监听、重型渲染、资源生命周期和回归预算，不把“没有报错”写成通过。

真实酒馆验收

离线预览用于缩小问题，最后仍回到真实 SillyTavern，用正式产物完成点击、刷新和跨对话验收。

最有用的输入是现象告诉 Agent“做了什么、看见什么、本来应该发生什么”，再提供卡片、控制台或最小复现；不要只说“坏了，优化一下”。

资料库、安装与发布 NEW · V1.3.0

适合查 SillyTavern、酒馆助手、MVU、EJS 与 STScript 的真实用法，或者安装、更新、核验和发布 TavernWeave。

Library 按任务取资料

A0、ST 指南、设计、动效、概念、蒸馏账本和离线挑选页随 TW 分发；确定性查询只返回当前任务相关的少量候选。

20/20 与全局前门

安装时创建新增 Skill，并可把 Soul、脑暴、照镜子与 A0 loop 的识别入口写入客户端全局受控区块。

从部件到发布

默认交付可导入部件；只有你明确要求时才组装整卡、提交 Git、推送、打标签或发布 Release。
