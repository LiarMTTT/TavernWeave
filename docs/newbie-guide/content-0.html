TavernWeave 到底能做什么

从整理想法、制作角色卡，到排查问题、组装发布，TW 帮你把项目一步步做出来。

TavernWeave（简称 TW）是一套面向角色卡制作与 Vibe Coding 的工作系统。v1.4.0 本地候选版包含 21 个专职 Skill，你可以把它们理解为 Agent 按任务调用的工作方法：有的负责规划，有的负责制作，有的负责检查。

你可以用 TW 讨论一个还没想清楚的项目，制作或改进角色卡，搭建界面，精修文字，查找故障，也可以在各部分完成后组装作品、准备发布。想回顾自己一路怎么做项目、积累了哪些经验，可以调用“照镜子”，复盘你的 Vibe Code 经验与成长历程。

开始时不用记住这些 Skill 的英文名。直接告诉 Agent 你想做什么，或者卡在了哪里，它会判断需要调用哪些能力。

不知道该怎么提需求？先描述你遇到的情况就行。比如：“角色的数值已经变了，状态栏却还是旧的，帮我查一下原因。”你不必提前知道问题出在哪个文件，也不必先选对 Skill。交付时，Agent 应说明做了哪些检查，以及哪些地方需要你亲自查看和试用。

项目规划与脑暴 NEW · V1.2.0

适合“我有一个想法，但不知道该怎么落地”“项目太大，Agent 越做越散”或者“先帮我想清楚，不要马上写文件”。

把愿望收成第一版

先聊清楚作品给谁用、最想让人体验什么，再决定第一版做哪些内容、以后加什么。别一开场就把十年的更新计划塞进第一版。

按体量生成蓝图

小项目用一份蓝图说明白；项目大了，再按模块拆开。每一步都要对应实际工作，不能为了显得专业，先给你盖一排空文件夹。

Soul 三席联席

阿瞳关注你想表达什么，MTTT.sir 检查技术和逻辑，强尼·银手看界面方向。三种视角围绕同一份方案讨论，最后留下统一的决定与待办。

照镜子：复盘 Vibe Code 经验 NEW · V1.3.0

回顾你如何提出需求、选择方案、发现问题和纠正方向，看清哪些地方更熟练了，哪些问题还在反复出现。评估依据当前能查到的对话、项目记录与实际交付，给出文字评估和七章交互报告，并说明资料缺口。有历史履历时，只比较前后口径一致的部分。

先脑暴，再决定是否开工
脑暴模式，Soul 联席

先判断项目类型，帮我收束总设计案、第一版核心和后续更新路线。不要直接写文件。

角色卡与变量系统

适合从零做卡、把纯文字卡改成变量卡，或者为旧卡增加背包、任务、关系、商城、世界书和状态栏。

从零搭角色卡

先聊玩法和故事，再按需要制作设定、开局、世界书、变量与界面。哪些真的要做，取决于这张卡想怎么玩。

旧卡增量升级

先读懂旧卡用的变量格式和组件关系，再加功能、尽量保留原来的味道。修改部件与重新封装整卡，会分别说明范围。

拆分与重新组装

把大 JSON 拆成便于修改的源码部件，逐项检查后再组装。组装和发布都按你已经确认的范围执行。

你可以直接这样说“帮我从零制作一张 MVU 角色卡，先访谈，不要直接写文件。”或“把这张纯文字卡改成 MVU 卡，尽量保留原来的味道。”

文本精修：去 AI 味与去八股 V1.4.0 · 待发布

一段话看着挺工整，读完却不知道它想说什么；几个人物一开口，像共用一个发言稿——这些都可以交给文本精修。改的是表达，事实、设定和技术结构要保住。

按需要改轻或改深

只想读着顺一点，选轻润色；段落顺序不合适，选结构改写；整篇都需要换一种讲法，再选深度重写。力度再大，也不能替你编事实。

单次、持续与持久

可只改一段，或在当前任务持续精修；工作区和客户端持久模式分别由你同意后开启。

前端、交互与美术 NEW · V1.3.0

适合制作开局页、状态栏、悬浮球、抽屉、弹窗、控制中心和媒体界面，也适合在动手前判断是否真的需要复杂前端。

先选承载面

先决定界面放在哪里：跟着消息显示、单独打开，还是嵌入现有页面。用一个折叠区就能解决的需求，没必要先造一座控制中心。

完整设计与动效资料

内置 462 个设计、194 个动效、86 个概念和 1,609 条蒸馏记录。Agent 按当前任务挑选参考，再结合你的主题、内容多少和屏幕尺寸设计界面。

灵魂杀手审查

让强尼·银手同人彩蛋人格来挑界面的毛病：哪里难读、配色哪里打架、动画有没有必要。吐槽归吐槽，每个问题都得说清怎么改。

前端审查
灵魂杀手！

检查这个前端的视觉层级、中文排版、配色、动效目的和 390px 窄屏表现。可以直说，但每个问题都要给证据、影响、修法和复验方式。

调试、审计与优化

适合“变量明明变了，状态栏没刷新”“按钮在预览页能点，进酒馆就坏”“刷新或切换聊天后功能失效”等真实运行问题。

沿链路找最早断点

沿着“数据写入—读取—通知—页面更新”追查，找到最早出错的一步。数值没写进去和页面没刷新，修法完全不同。

安全与性能审计

检查输入和凭据处理、重复监听、渲染开销，以及页面退出后有没有留下计时器等资源。还要核对旧功能，避免修好一处又坏一处。

真实酒馆验收

先用离线预览查结构和样式，再用待验收产物进入真实 SillyTavern，检查点击、刷新和切换聊天。两种环境的结果分别记录。

全量审查 V1.4.0 · 待发布

先确定项目范围，再检查实现、配置、测试和核心流程；报告会说明哪些已看、哪些还没看。

架构审查

查清各部分负责什么、依赖谁、数据由谁说了算。既能查软件模块，也能查角色卡的世界书、提示词和变量；要覆盖整个项目，可用全量架构审查。

最有用的输入是现象把“做了什么、看见什么、本来应该发生什么”告诉 Agent，再附相关卡片或报错。比如“切换聊天后按钮消失，刷新页面才回来”，已经比一句“坏了”多了很有用的线索。
