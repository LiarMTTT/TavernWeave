# 奶人教程更新日志

这里记录的是读者真正能看到、能用上的变化，不写构建过程和维护细节。

在线阅读：[TavernWeave · Vibe Code 制卡入门](https://liarmttt.github.io/TavernWeave/newbie-guide/)

## v0.5.2 · 2026-07-26

### 从“让 Agent 干活”走到“看懂它怎么干活”

这次更新把教程补到了一个更完整的阶段：

你不仅可以让 Agent 修改项目，还可以理解它怎样查看现场、使用工具、根据结果继续修正，以及怎样用真实运行证据判断它有没有做对。

### 你会直接看到的变化

#### 1. 学习路径重新分成入门与进阶

- 第一至三章属于入门篇。
- 第四章开始进入进阶篇。
- 左侧目录改成按章节折叠，长教程更容易定位。
- PC 页面扩大了正文空间，减少无意义装饰，把信息密度和阅读效率放在前面。

第一次阅读时不需要直接冲进第四章。先掌握前三章的目标、边界、变量、脚本与真实验收，再进入运行时调试。

#### 2. 补全“Agent 到底是什么”

[第一章 02](https://liarmttt.github.io/TavernWeave/newbie-guide/#agent) 不再只比较产品，而是先回答三个零基础用户最容易卡住的问题：

- Agent 和普通聊天 AI 有什么区别；
- Agent 接到任务后怎样查看、行动、检查和继续修正；
- 不会写代码的人应该怎样给目标、划边界、做验收和反馈问题。

新增了完整的工作循环、复制按钮示例、新手指挥模板、含糊需求与可执行需求的对比，以及用户和 Agent 各自负责什么。

这里最重要的不是背提示词，而是理解：

> 你不需要告诉 Agent 每一行代码怎么写，但必须告诉它要到哪里、不能撞什么，以及怎样才算真正到达。

你的知识越全面，指挥 AI 的效率就越高，所以该看教程就看。暂时讲不清时，也可以把可靠样本交给 AI，让它先弄明白，再用你能听懂的方式教回来。

#### 3. 新增第四章：监听真实酒馆实例

[第四章](https://liarmttt.github.io/TavernWeave/newbie-guide/#chapter-4) 面向已经开始制作角色卡、状态栏或交互脚本，但经常遇到“代码看起来没错，酒馆里就是不对”的读者。

这一章会带你理解：

- 为什么文件存在、构建成功和真实功能正常是三件不同的事；
- 怎样在真实 SillyTavern 中挂载受控的调试 Probe；
- 怎样建立只服务于本次调试的本机 Mock 接收端；
- 怎样让 Agent 读取事件顺序，找到最早缺失、重复或没有闭合的步骤；
- 怎样确认新构建真的已经接管，而不是继续测试旧产物；
- 怎样在修复后移除调试设施，再用正式产物完成最终验收。

这里的 Mock 不是伪造一个酒馆。酒馆仍然是真实运行实例，Mock 只负责接住经过筛选的本机调试证据。

#### 4. 增加 Agent Mock 与 VS Code 的明确对比

教程不再把“监听”和“断点”混成一件事：

- Agent Mock 更适合保存长时间事件顺序，观察生命周期、重复监听、热重载、切换对话和写入—刷新链。
- VS Code 更适合停在精确代码现场，查看调用栈、局部变量、闭包、条件分支和异常。

遇到复杂故障时，推荐先用事件流缩小范围，再用断点检查精确状态，最后回到真实酒馆完成正式验收。

#### 5. 明确教程示例不是项目标准答案

第四章中的本机接收器只是用来讲清调试链路的最小示例，不应该被所有项目原样照抄。

真正开工前，应先根据自己的项目确认：

- 构建和重载方式；
- 酒馆、iframe、脚本与扩展之间的运行边界；
- 当前可以观察到哪些事件；
- 正在调查哪一种故障；
- 哪些数据不能记录；
- 最终准备怎样验收。

再据此决定监听入口、业务检查点、记录字段、保留时长和清理方式。教程提供原则，Debug 机制必须以项目实际为准。

### 这次更新适合谁

- 第一次接触 Agent，不知道它和聊天 AI 有什么区别；
- 会让 AI 生成代码，但不知道怎样判断它真的完成了；
- 已经开始制作状态栏、按钮或交互功能；
- 经常遇到刷新、切换对话、重复点击或热重载后的偶发问题；
- 想让 Agent 参与 Debug，但不希望它只读源码后凭感觉猜；
- 想知道什么时候该看事件流，什么时候该进 VS Code 打断点。

### 推荐阅读路线

- **纯零基础：**00 → 01 → 02，先学会描述结果、保护边界和亲自验收。
- **开始正式制卡：**继续阅读工作区、TavernWeave、ST 开发指南 DB 与 A0 驾驭协议。
- **在做变量卡：**进入第二章，理解 Zod、CoT 与计算脚本的分工。
- **在做状态栏或交互：**进入第三章，理解脚本、正则、UI、变量写入与生命周期。
- **功能只在真实酒馆出问题：**进入第四章，从运行时证据、Agent Mock 和 VS Code 联合调试开始。

### 需要继续记住的边界

- Agent 的完成声明不能代替实际结果。
- 页面出现不能证明按钮、变量和生命周期都正确。
- 静态检查和构建成功不能代替真实 SillyTavern 验收。
- 调试日志不要记录聊天全文、Cookie、API Key、完整变量表或私密设置。
- 教程示例应该帮助你理解原则，不应该替你跳过项目调查。

## v0.4.0 · 脚本、正则与交互

第三章加入酒馆助手脚本、正则、展示 UI、操作 UI、生命周期、变量读写、世界书管理、运行时提示词、外部资源和结构化输出。

这一版重点解决的是：

- 为什么正则可以整理文本，却不能独自承担完整业务逻辑；
- 为什么“生成了一段 HTML”不等于按钮真的可用；
- 怎样区分页面显示和真实变量状态；
- 怎样检查入口、执行、写入、刷新和重复加载这条完整链路。

如果你正在制作状态栏、控制面板、按钮或交互模块，应优先阅读这一章。

## v0.3.0 · Zod、CoT 与计算脚本

第二章加入变量结构、自定义 CoT、计算脚本和变量更新分工。

这一版帮助读者分清：

- Zod 负责什么；
- CoT 应该控制哪些生成过程；
- 哪些确定性计算更适合交给脚本；
- 怎样避免模型和计算脚本同时修改同一个最终变量。

目标不是让所有卡都使用同一种结构，而是让每种工具只负责自己擅长的工作。

## v0.2.1 · 从一句需求到第一次可验收交付

第一章建立了教程的基础路径：

- Vibe Code 是什么；
- 怎样完成第一个小任务；
- 怎样选择 Agent；
- 内容模型和开发 Agent 怎样分工；
- 工作区、Git、TavernWeave 与 ST 开发指南 DB 分别负责什么；
- 怎样使用 A0 驾驭协议；
- 怎样完成一次有目标、有边界、有验证、有交接的任务。

从这一版开始，教程坚持同一个原则：

> AI 可以替你调查和执行，但方向、边界和最终验收仍然由你负责。
