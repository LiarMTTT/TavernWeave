先分清这三层

Probe：选择证据

订阅酒馆事件并发送“事件名、时间、参数形状、版本、构建标记”。不要上传整段聊天、完整变量表或密钥。

Receiver：保存记录

只监听 127.0.0.1，校验临时口令，把每条记录追加到本地 NDJSON 文件。

Agent：解释断点

对照操作、版本和已采集检查点，寻找最早的异常线索。记录没出现，也可能是采集或传输失败，需要继续核对。

这些问题，适合先看事件记录

  • 真实事件顺序与回调次数。
  • 热重载后仍在执行旧构建的问题。
  • 重复绑定、重复提交和重复结算。
  • 写入成功但没有重新读取或渲染。
  • 刷新、滑动消息、切换对话后生命周期断裂。
  • 偶发问题发生前的最近一段可回放证据。
它看不到所有东西没有主动采集的局部变量、闭包和调用栈不会自动出现在事件流里。需要查看某一行执行时的精确内存状态时，切换到 VS Code 或浏览器调试器。

建立一个本机调试接收器

示例使用 Node.js 内置模块，接收来自指定来源的调试请求。

先按项目调整，再使用示例这是帮助理解流程的最小接收器。请 Agent 先检查构建与重载方式、可用事件和数据范围，再确定端口、检查点、记录字段与清理办法。它没有完整的日志轮转、请求限流或重试机制，不宜原样作为长期运行服务。

示例文件名为 debug/mock-listener.mjs，放置位置先遵守项目的测试目录约定，启动命令也相应调整。完成调试后清理临时设施，保留需要的脱敏证据；调试文件不要进入正式包。

debug/mock-listener.mjs
import { createServer } from 'node:http';
import { appendFile } from 'node:fs/promises';

const HOST = '127.0.0.1';
const PORT = 17373;
const ALLOWED_ORIGIN = process.env.TW_DEBUG_ORIGIN;
const DEBUG_KEY = process.env.TW_DEBUG_KEY;
const OUTPUT = new URL('./tw-debug.ndjson', import.meta.url);

if (!ALLOWED_ORIGIN || !DEBUG_KEY) {
  throw new Error('请先设置 TW_DEBUG_ORIGIN 和 TW_DEBUG_KEY');
}

function setCors(req, res) {
  if (req.headers.origin !== ALLOWED_ORIGIN) return false;
  res.setHeader('Access-Control-Allow-Origin', ALLOWED_ORIGIN);
  res.setHeader('Access-Control-Allow-Headers', 'Content-Type, X-TW-Debug-Key');
  res.setHeader('Access-Control-Allow-Methods', 'POST, OPTIONS');
  res.setHeader('Vary', 'Origin');
  return true;
}

function reply(res, status, data) {
  res.writeHead(status, { 'Content-Type': 'application/json; charset=utf-8' });
  res.end(JSON.stringify(data));
}

const server = createServer(async (req, res) => {
  if (!setCors(req, res)) {
    reply(res, 403, { ok: false, error: 'origin_not_allowed' });
    return;
  }

  if (req.method === 'OPTIONS') {
    res.writeHead(204);
    res.end();
    return;
  }

  if (req.method !== 'POST' || req.url !== '/events') {
    reply(res, 404, { ok: false, error: 'not_found' });
    return;
  }

  if (req.headers['x-tw-debug-key'] !== DEBUG_KEY) {
    reply(res, 401, { ok: false, error: 'invalid_debug_key' });
    return;
  }

  try {
    let raw = '';
    for await (const chunk of req) {
      raw += chunk;
      if (Buffer.byteLength(raw) > 64 * 1024) {
        throw new Error('payload_too_large');
      }
    }

    const payload = JSON.parse(raw);
    const record = {
      ...payload,
      receivedAt: new Date().toISOString(),
    };

    await appendFile(OUTPUT, `${JSON.stringify(record)}\n`, 'utf8');
    console.log(`${record.receivedAt}  ${record.event}`);
    reply(res, 202, { ok: true });
  } catch (error) {
    reply(res, 400, { ok: false, error: String(error) });
  }
});

server.listen(PORT, HOST, () => {
  console.log(`TW mock listener: http://${HOST}:${PORT}/events`);
  console.log(`output: ${OUTPUT.pathname}`);
});

在酒馆里加入临时 Probe

选择需要监听的事件，确认发送哪些字段，并检查停用后的清理。

下面代码运行在酒馆助手脚本 iframe，依赖酒馆助手提供的 eventOn、tavern_events、iframe_events、getTavernVersion 与 getTavernHelperVersion。事件名和返回的 stop() 以 TavernWeave 随附的声明参考为依据，目标实例仍需现场确认版本。

本地调试脚本 · 不要打包进角色卡
const CONFIG = Object.freeze({
  endpoint: 'http://127.0.0.1:17373/events',
  debugKey: '与 TW_DEBUG_KEY 相同的一次性口令',
  buildRevision: '换成当前构建标记',
});

window.__TW_DEBUG_PROBE__?.stop?.();

const sessionId =
  globalThis.crypto?.randomUUID?.() ??
  `tw-${Date.now()}-${Math.random().toString(16).slice(2)}`;
const subscriptions = [];
const runtime = {
  tavern: getTavernVersion(),
  helper: getTavernHelperVersion(),
  buildRevision: CONFIG.buildRevision,
  frame: typeof getIframeName === 'function' ? getIframeName() : 'unknown',
};

function brief(value, depth = 0, seen = new WeakSet()) {
  if (value == null || typeof value === 'number' || typeof value === 'boolean') {
    return value;
  }
  if (typeof value === 'string') {
    return { type: 'string', length: value.length };
  }
  if (typeof value !== 'object') {
    return { type: typeof value };
  }
  if (seen.has(value)) return '[circular]';
  if (depth >= 2) return Array.isArray(value) ? '[array]' : '[object]';

  seen.add(value);
  if (Array.isArray(value)) {
    return value.slice(0, 8).map(item => brief(item, depth + 1, seen));
  }

  return Object.fromEntries(
    Object.entries(value)
      .slice(0, 12)
      .map(([key, item]) => [key, brief(item, depth + 1, seen)]),
  );
}

async function publish(event, args = []) {
  const response = await fetch(CONFIG.endpoint, {
    method: 'POST',
    headers: {
      'Content-Type': 'application/json',
      'X-TW-Debug-Key': CONFIG.debugKey,
    },
    body: JSON.stringify({
      sourceAt: new Date().toISOString(),
      sessionId,
      event,
      args: args.map(arg => brief(arg)),
      runtime,
    }),
  });

  if (!response.ok) {
    console.warn('[TW debug probe] receiver rejected event', response.status);
  }
}

function listen(eventType) {
  const subscription = eventOn(eventType, (...args) => {
    void publish(eventType, args).catch(error => {
      console.warn('[TW debug probe] publish failed', error);
    });
  });
  subscriptions.push(subscription);
}

[
  tavern_events.CHAT_CHANGED,
  tavern_events.MESSAGE_SENT,
  tavern_events.MESSAGE_RECEIVED,
  tavern_events.MESSAGE_UPDATED,
  tavern_events.GENERATION_STARTED,
  tavern_events.GENERATION_ENDED,
  iframe_events.MESSAGE_IFRAME_RENDER_ENDED,
].forEach(listen);

window.__TW_DEBUG_PROBE__ = {
  mark(label, data = {}) {
    return publish(`mock:${label}`, [data]);
  },
  stop() {
    subscriptions.splice(0).forEach(subscription => subscription.stop());
    delete window.__TW_DEBUG_PROBE__;
  },
};

void publish('probe:ready', [{ origin: location.origin }]);

让 Agent 从事件记录里缩小故障范围

每次只复现一个动作，把对应记录和代码连起来看。

记录运行边界确认 SillyTavern、酒馆助手、卡片和构建标记，记录当前对话、视口与复现动作。
保留旧证据，标记本轮起点按记录时间和实例区分本轮测试，再点击一个按钮、切换一次聊天或触发一次生成，避免混入多个操作。
按时间与 sessionId 分组先找 probe:ready 和构建标记，再寻找入口、写入、渲染与宿主事件。
先查最早异常的位置入口之后没有写入记录，先查业务条件、异常和采集是否正常；写入后没有渲染记录，再查刷新流程。定位后按已授权范围修改。
确认新构建确实加载检查新的 probe:ready、构建标记与目标 iframe；示例标记需要手动更新，不能只改标记就当作新源码已运行。标记不一致时，先排查产物和加载路径。
重复同一动作做回归核对预期次数、关联记录和控制台，再检查刷新与聊天切换。并发请求的到达或写入顺序未必等于业务执行顺序，不能只按日志行号下结论。
事件流更可能的根因
没有 probe:ready调试脚本未加载、接收端来源/口令不匹配，或请求被宿主策略阻止
有 purchase:start，没有 purchase:state-written条件检查、异步调用或数据写入阶段失败
有 state-written，没有 rendered刷新函数未调用、提前返回或渲染抛错
同一 session 内检查点重复两次监听器重复注册、按钮重复绑定或提交没有锁
源码已修改，但构建标记没变编译失败、监听器断开或 iframe 仍在运行上一次成功产物

一次完整调试可以这样安排

  1. 记录版本、卡片、构建标记、对话、视口和最小复现。
  2. 启动本机 Receiver，确认 Probe 上报 probe:ready。
  3. 只执行一个用户动作，让 Agent 读取失败时间线。
  4. 在最早缺失或重复的业务层增加一个短期检查点。
