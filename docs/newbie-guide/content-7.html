26

正则是什么

正则表达式是一套文本匹配规则，不是一套完整应用运行时。

它可以找到满足某种格式的文本，然后提取、隐藏、删除或替换。

结构化输出示例
<status>
地点：学生会办公室
时间：14:30
</status>

正则可以识别 <status>...</status>，将内容隐藏、提取，或替换成固定的展示结构。

适合正则

固定标签、简单字段、前后缀、格式清理和展示替换。

VS

不适合正则

复杂状态、异步请求、多步骤交互、持久化和生命周期管理。

不要堆成巨型正则当一条正则开始承担大量分支、嵌套格式和业务规则时，通常已经到了应该改用结构化数据或脚本的阶段。
27

为什么需要隐藏变量更新内容

系统需要读取的内容，不一定都适合显示给用户。

Zod 卡可能让模型输出：

变量更新块
<UpdateVariable>
  ...
</UpdateVariable>

这部分用于变量更新，不一定应该直接出现在聊天正文里。正则可以识别它，并在显示层隐藏。

模型输出正文与更新块
→
Zod 读取并执行更新
→
正则处理显示
→
用户只看到正文
隐藏不等于提前删除如果正则在变量系统读取前就破坏了更新块，变量可能无法正常写入。具体处理顺序必须按当前运行环境验证。
28

正则可以生成界面外观，但不能自动补齐行为

HTML 出现了，不代表功能闭环已经存在。

例如模型输出：

模型输出标签
<choice>前往旧校舍</choice>

正则可以替换成：

替换后的静态外观
<button>前往旧校舍</button>

但这通常只产生一个按钮元素。想让它真正工作，还需要酒馆助手脚本：

正则生成按钮外观
→
脚本找到新元素
→
绑定点击事件
→
发送消息或修改数据
→
反馈结果
一句话区别正则可以生成外观，脚本负责赋予行为。
29

不要让模型每轮自由生成整套 HTML

模型擅长生成内容，但不适合成为不受约束的前端模板引擎。

让模型直接输出任意 HTML，常见问题包括：

  • 标签没有闭合，导致后续楼层布局被破坏。
  • class、字段和层级每轮变化，脚本无法稳定识别。
  • 内联样式污染主题和移动端显示。
  • 输出变长，挤占正文和变量更新空间。
  • 出现不安全或无法预测的页面内容。

更稳定的方式是让模型输出有限的结构化数据：

结构化数据示例
{
  "标题": "调查旧校舍",
  "状态": "进行中",
  "进度": 60
}
模型输出有限字段
→
正则或脚本读取
→
使用固定模板渲染
→
得到稳定 UI
固定模板的价值内容可以变化，DOM 结构、class 名和交互入口保持稳定，脚本、CSS 和移动端适配才容易维护。
30

正则和脚本怎样配合

不是所有 UI 都需要正则，也不是所有文本处理都要写脚本。

隐藏 Zod 更新

模型输出正文和更新块
→
Zod 更新变量
→
正则隐藏更新块
→
用户只看正文

生成可点击选项

模型输出 choice 标签
→
正则生成按钮
→
脚本绑定事件
→
发送用户选择

从变量直接渲染面板

脚本读取变量
→
固定模板生成 UI
→
监听变量变化
→
重新渲染

第三种情况通常不需要先让模型输出一段文本，也不需要正则参与。数据已经存在于变量中时，脚本可以直接读取和展示。

31

什么时候用正则，什么时候用脚本

先按需求本质选择工具，不要按“哪种写起来短”选择。

正

只处理文本

匹配、隐藏、提取、清理和简单替换，优先正则。

脚

需要逻辑或状态

判断、变量、保存、请求、监听和交互，使用脚本。

合

文本变成交互

正则生成结构，脚本绑定行为，两者配合。

工具选择口诀
找出来、藏起来、换个样子
→ 正则

点了以后做事、数据变化后刷新、失败后反馈
→ 酒馆助手脚本

模型输出要变成可交互界面
→ 正则 + 脚本
能用正则勉强实现，不等于应该用正则如果需求已经包含状态、事件、异步或清理，尽早切换到脚本，通常比继续堆替换规则更可靠。
32

UI、脚本和正则的常见失败

先根据现象判断丢失的是外观、行为、数据还是生命周期。

现象常见原因
页面看得到，但按钮不能用只生成了 HTML，没有绑定脚本事件。
按钮第一次有效，刷新后失效只在首次加载时绑定，没有处理重新渲染。
点击一次执行多次监听器重复注册，或没有执行锁。
状态栏一直显示旧数据只初始化读取一次，没有监听变量变化。
正则把正文也隐藏了匹配范围过大或边界不明确。
变量更新突然失效正则破坏了更新块，或执行顺序不正确。
UI 变了，刷新后恢复只改了 DOM，没有写入真实状态。
变量已变化，UI 没变化写入成功，但没有重新读取和渲染。
反馈问题时说清四件事做了什么、预期什么、实际发生什么、控制台或数据层有什么证据。不要只说“按钮坏了”。
33

页面显示不等于真实状态

DOM 是展示结果，不应自动被当成唯一数据源。

真实状态

保存在变量、设置、消息或其他明确持久层中的数据。

→

展示状态

页面当前显示的文字、卡片、进度条和选中效果。

错误流程：

只改页面
用户点击
→ 把页面文字改成“金钱：999999”
→ 没有修改变量
→ 刷新后恢复原值

正确流程：

用户操作
→
修改真实数据
→
确认写入成功
→
重新读取
→
更新页面
数据驱动界面页面应尽量从真实状态重新渲染，而不是把 DOM 上临时显示的值当作最终真相。
34

怎样验收脚本和正则

离线页面能检查外观，但不能关闭真实 SillyTavern 的运行时验收。

至少检查这些路径

  • 新建对话时能否正常初始化。
  • 刷新页面后是否仍然有效。
  • 切换对话和消息楼层后是否读取正确数据。
  • 按钮是否只执行一次，并能处理快速连点。
  • 重复打开面板是否产生重复 DOM 或监听器。
  • 变量和设置是否真正写入。
  • UI 是否跟随真实数据刷新。
  • 正则是否只匹配目标内容。
  • 脚本禁用或重载后是否存在残留。
  • 控制台是否出现新的错误。
  • 移动端是否可读、可点、无横向溢出。
  • 外部资源失败时是否有明确提示和降级。

离线 HTML 不能证明什么

不能证明 API 可用

宿主函数、事件和作用域只有在真实环境中才能确认。

不能证明持久化成功

页面演示可以改 DOM，但未必写入聊天或消息变量。

不能证明生命周期正确

刷新、切换对话、脚本重载和生成事件需要真机验证。

第三章总结

把文本处理、运行逻辑和真实状态放回各自的位置。

正

正则

匹配、提取、隐藏、清理和替换文本，也能生成静态展示外壳。

脚

酒馆助手脚本

执行逻辑、操作数据、创建交互、监听生命周期和连接外部能力。

态

真实状态

保存在明确的数据层中，UI 只是读取并展示它。

记住这组判断找出来、藏起来、换个样子：正则。点了以后做事、数据变化后刷新、失败后反馈：脚本。
  • 不要把正则当成万能低代码程序引擎。
  • 不要低估酒馆助手脚本在 UI、数据、事件和 API 上的能力范围。
  • 不要把生成了 HTML 当成已经完成交互功能。
  • 不要只修改页面显示而不写入真实状态。
  • 不要只在首次加载路径上验收。
  • 不要跳过真实 SillyTavern 的运行时检查。
