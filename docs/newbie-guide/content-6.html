正则不是低代码神器

它很能找字、换字，但扛不起一整套应用逻辑。

正则非常强，但它的核心仍然是：找到一段文本，然后提取、隐藏或替换它。

找

正则擅长匹配

识别固定标签、字段、前后缀和满足某种格式的文本。

换

正则擅长改写

隐藏内容、清理格式、提取字段、替换成固定文本或静态 HTML。

壳

正则可以生成外壳

把模型输出转换成卡片、按钮或面板的外观结构。

这些活别硬塞给正则

  • 长期保存和迁移状态。
  • 监听对话、生成和变量更新等生命周期。
  • 执行复杂条件分支和多步骤业务逻辑。
  • 发起异步网络请求并处理成功、失败和超时。
  • 稳定管理按钮事件、重复初始化和资源清理。
  • 在多个变量之间执行完整、可回滚的写入链。
最典型的误解正则把 <choice>前往旧校舍</choice> 替换成了一个按钮，不代表这个按钮已经拥有点击行为。它可能只有外观，没有功能。

脚本比正则多的不只是几行代码

需求正则酒馆助手脚本
隐藏一个固定标签块适合通常没必要
把固定字段换成静态卡片适合也可以
点击按钮后读取变量并写回不适合单独承担适合
变量变化后自动刷新状态栏不能只靠文本替换完成适合
加载远程数据并处理失败不适合适合
管理世界书、设置和复杂 UI不适合适合

正则的上限

把文本识别出来，并转换成另一种文本或静态展示结构。

VS

脚本的范围

读取状态、执行逻辑、操作数据、创建交互、处理生命周期和失败。

判断口诀只需要“找出来、藏起来、换个样子”，先考虑正则；需要“点了以后做事、数据变化后刷新、失败后给反馈”，使用酒馆助手脚本。

UI 脚本不只会画状态栏

角色卡前端可以是一整套操作台，不是一张贴上去的皮。

状态与资料

状态栏、角色档案、任务列表、关系面板和世界状态。

功能中心

控制中心、背包、商店、地图、媒体管理和模块设置。

开局与配置

身份、难度、阵营、模式和可选模块的配置页面。

状态栏不是贴在墙上的 HTML

一个真正会工作的状态栏通常需要：

读取变量
→
整理展示数据
→
渲染页面
→
监听状态变化
→
重新刷新

把一段状态栏 HTML 塞进页面，只能证明这层皮能显示；数据变了它会不会跟着动，还是未知数。

开局页不是选完就算

开局页可以让用户选择身份、模式或初始条件，但还需要明确：

  • 选择结果保存到哪里。
  • 什么时候正式写入变量。
  • 重复打开是否覆盖已有数据。
  • 取消、失败或刷新后如何处理。
  • 选择结果怎样进入后续剧情和提示词。
19

能看和能改，中间隔着一条写入链

展示数据是一回事，安全改掉数据是另一回事。

展示型 UI

读取并展示状态，例如时间、地点、任务、关系和装备。通常以只读为主。

VS

操作型 UI

允许用户购买、编辑、切换、使用或提交数据，必须处理写入和失败。

操作型 UI 需要额外回答：

  • 点击后具体修改什么数据。
  • 写入前要检查哪些条件。
  • 写入失败时怎样恢复和提示。
  • 是否允许重复点击。
  • 刷新和切换对话后是否仍然有效。
  • 模型、计算脚本和 UI 谁是主要写入者。
按钮能点击不等于功能完成真正的完成链是：条件检查、数据写入、成功确认、界面刷新、失败反馈和重复执行保护。

一键买五次：重复执行怎么来的

快速连点、事件重复绑定、页面重载和网络延迟，都可能让一次操作执行多次。

  • 执行期间临时禁用按钮。
  • 给事件或请求分配唯一标识。
  • 初始化前检查旧监听器和旧 DOM。
  • 相同事件处理完成后不能再次结算。
  • 失败时释放锁定状态，允许用户重试。
21

第一次能跑，只是最简单的运气

刷新、重载、切对话、再启用，才是生命周期真正来找你。

脚本还需要面对：

页面变化

首次加载、刷新、脚本重载、禁用和重新启用。

对话变化

新建对话、切换对话、切换消息楼层和滑动消息。

生成与数据变化

开始生成、生成结束、变量更新和设置修改。

重载五次，监听器别长成五个

常见的重复监听问题
第一次加载：注册 1 个监听器
第二次加载：又注册 1 个监听器
重复五次后：一次事件执行五遍

脚本应当使用固定标识，初始化前检查旧实例，并在重载、禁用或卸载时清理监听器、DOM、样式和提示词注入。

什么是幂等同一段初始化执行多次，最终仍然只存在一套按钮、一套面板和一套监听器，而不是越加载越多。
22

变量能改，但不能乱改

脚本可以进状态链，不能翻过 Schema 和写入归属偷偷抄近路。

读取变量

状态栏展示、条件判断、计算、功能开关、导出和提示词快照。

+

修改变量

用户操作、计算结果、设置保存和脚本确定产生的状态变化。

脚本新增或修改变量前，应确认：

  • Schema 和初始化中是否存在该字段。
  • 模型、脚本和 UI 中谁负责写入。
  • 哪些组件会读取或展示它。
  • 旧对话缺少这个字段时怎样补全。
  • 字段失效后怎样清理或迁移。
定义
→
初始化
→
写入
→
读取
→
展示
→
清理或迁移
别只在屏幕上演戏把页面上的“金钱 1200”改成“金钱 999999”，真实变量一分钱没多；刷新后当场打回原形。

世界书能装卸，但别拆用户的家

DLC、可选模块和工坊内容都能管，前提是归属清清楚楚。

酒馆助手脚本可以根据目标环境提供的能力，对世界书条目执行创建、读取、更新、启停和卸载等操作。

安装模块

创建一组明确归属于当前功能的世界书条目。

升级模块

识别原版、用户修改版和冲突状态，再决定处理方式。

卸载模块

只删除当前功能明确创建的内容，不误伤用户条目。

用户改过的东西，先别覆盖

读取当前条目
→
与旧版本基线对比
→
未修改则自动升级
→
已修改则提示冲突
→
由用户选择
名称相似不能作为删除依据卸载必须依靠稳定标识和明确归属，不能搜索一个前缀后把相似条目全部删除。
24

运行时提示词：只塞模型此刻要看的

把动态状态递给模型，别顺手造一团没人能追踪的隐藏提示词。

脚本可以在目标运行环境支持时，向生成上下文加入：

  • 当前启用的游戏模式和功能模块。
  • 脚本计算出的只读状态摘要。
  • 用户在 UI 中选择的设置。
  • 模型当前确实需要、但不适合长期写进世界书的信息。

使用时需要控制：

  • 不要重复注入世界书已经提供的内容。
  • 不要把完整数据库每轮塞进上下文。
  • 明确剧情模型和变量更新模型分别能看到什么。
  • 脚本禁用、对话切换和模块关闭后必须清理旧注入。
  • 让用户知道哪些设置会影响模型输出。
它不是世界书的自动替代品稳定设定仍适合放在角色卡和世界书中；脚本注入更适合运行时、可变化和可开关的信息。

外部 API 一抽风，角色卡不能跟着躺

连上外部世界的同时，网络、权限和隐私风险也一起进门。

远程数据

读取 JSON、工坊索引、版本信息和动态配置。

媒体与服务

加载图片、音频，或调用明确授权的外部服务。

独立应用通信

与 Gateway、独立前端或本地服务交换数据。

请求发出去前，先把失败路线画出来

发起请求
→
成功则校验数据
→
失败或超时
→
明确提示并降级
  • 地址失效或网络断开时，核心聊天是否还能继续。
  • 返回数据格式改变时，脚本是否安全停止。
  • 是否存在跨域、鉴权和权限问题。
  • 请求中是否携带隐私、Token 或 API 密钥。
  • 外部服务停止后有没有本地回退方案。
不要公开密钥角色卡、世界书和前端脚本都可能被用户查看。不要把私人 API 密钥硬编码进公开发布的角色卡。
