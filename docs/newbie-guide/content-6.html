正则不是低代码神器

把正则用在格式明确的文本上；需要保存状态或处理操作时，再接脚本。

正则用来描述文本长什么样。在酒馆的查找与替换流程中，它负责定位目标，再配合替换规则提取、隐藏或改写内容。先把这件事理解清楚，后面的分工就容易了。

找

正则擅长匹配

识别固定标签、字段、前后缀和满足某种格式的文本。

换

正则擅长改写

隐藏内容、清理格式、提取字段、替换成固定文本或静态 HTML。

壳

正则可以生成外壳

把符合约定的模型输出替换成卡片、按钮或面板的 HTML；行为还要由宿主或脚本提供。

这些活别硬塞给正则

  • 长期保存和迁移状态。
  • 监听对话、生成和变量更新等生命周期。
  • 执行复杂条件分支和多步骤业务逻辑。
  • 发起异步网络请求并处理成功、失败和超时。
  • 稳定管理按钮事件、重复初始化和资源清理。
  • 在多个变量之间执行完整、可回滚的写入链。
最典型的误解把 <choice>前往旧校舍</choice> 换成按钮后，还要决定点击时做什么：发送一句话，还是修改地点变量？没人处理点击，它就只是一个看起来能按的外壳。

脚本比正则多的不只是几行代码

需求正则酒馆助手脚本
隐藏一个固定标签块适合通常没必要
把固定字段换成静态卡片适合也可以
点击按钮后读取变量并写回不适合单独承担适合
变量变化后自动刷新状态栏不能只靠文本替换完成适合
加载远程数据并处理失败不适合适合
管理世界书、设置和复杂 UI不适合适合

正则在这里负责什么

把文本识别出来，并转换成另一种文本或静态展示结构。

VS

脚本的范围

读取状态、执行逻辑、操作数据、创建交互、处理生命周期和失败。

判断口诀只需要“找出来、藏起来、换个样子”，先考虑正则；需要“点了以后做事、数据变化后刷新、失败后给反馈”，使用酒馆助手脚本。

开局选择，最后存到了哪里

选项亮起来之后，身份真的保存了吗？开局页需要把选择接到后续数据和剧情中，因此还要检查：

  • 选择结果保存到哪里。
  • 什么时候正式写入变量。
  • 重复打开是否覆盖已有数据。
  • 取消、失败或刷新后如何处理。
  • 选择结果怎样进入后续剧情和提示词。

展示界面与操作界面，检查重点不同

能看到背包，就检查它读得对不对；能购买物品，还要检查扣款、入库和失败处理。

展示型 UI

读取并展示状态，例如时间、地点、任务、关系和装备。通常以只读为主。

VS

操作型 UI

允许用户购买、编辑、切换、使用或提交数据，必须处理写入和失败。

操作型 UI 需要额外回答：

  • 点击后具体修改什么数据。
  • 写入前要检查哪些条件。
  • 写入失败时怎样恢复和提示。
  • 是否允许重复点击。
  • 刷新和切换对话后是否仍然有效。
  • 模型、计算脚本和 UI 谁是主要写入者。
购买失败时，也要给出结果余额不足应说明原因，写入失败不能显示成功，连点也不能多扣钱。把这些情况接好，按钮才有了完整的行为。

一键买五次：重复执行怎么来的

如果一次点击买了五件，先别急着怀疑模型。可能是事件绑定了五次，也可能是用户等待时反复点击。需要在入口和结算处都处理重复执行。

  • 执行期间临时禁用按钮。
  • 给事件或请求分配唯一标识。
  • 初始化前检查旧监听器和旧 DOM。
  • 相同事件处理完成后不能再次结算。
  • 失败时释放锁定状态，允许用户重试。
21

生命周期：刷新和切换聊天后，还能不能用

脚本从启动到退出会经历多种状态，这些变化都需要对应的处理。

第一次打开时运行正常，只覆盖了启动路径。还要看看下面这些变化发生后，脚本是否仍读对数据、只执行一次，并清理不再使用的资源：

页面变化

首次加载、刷新、脚本重载、禁用和重新启用。

对话变化

新建对话、切换对话、切换消息楼层和滑动消息。

生成与数据变化

开始生成、生成结束、变量更新和设置修改。

重载五次，监听器别长成五个

常见的重复监听问题
第一次加载：注册 1 个监听器
第二次加载：又注册 1 个监听器
重复五次后：一次事件执行五遍

为脚本实例和自己创建的资源保留明确标识。重新初始化时先处理旧实例，退出、重载或禁用时清理监听器、计时器、DOM、样式和提示词注入；不要把其他模块的资源一起清掉。

什么是幂等同一段初始化执行多次，最终仍然只存在一套按钮、一套面板和一套监听器，而不是越加载越多。

  • 模型、脚本和 UI 中谁负责写入。
  • 哪些组件会读取或展示它。
  • 旧对话缺少这个字段时怎样补全。
  • 字段失效后怎样清理或迁移。

世界书模块：安装、更新与卸载

先记住哪些条目由模块创建，再处理升级和删除，保留用户自己的修改。

酒馆助手脚本可以根据目标环境提供的能力，对世界书条目执行创建、读取、更新、启停和卸载等操作。

安装模块

创建一组明确归属于当前功能的世界书条目。

升级模块

识别原版、用户修改版和冲突状态，再决定处理方式。

卸载模块

只删除当前功能明确创建的内容，不误伤用户条目。

升级时，先比较用户是否改过

读取当前条目
→
与旧版本基线对比
→
未修改则按授权升级
→
已修改则提示冲突
→
由用户选择
名称相似不能作为删除依据模块卸载应根据稳定标识确认条目归属。只因名称像“某模块_设定”就删除，可能连用户自己写的条目也一起带走。

运行时提示词：把当前状态交给模型

适合传递模式、设置与本轮摘要；要能查出它从哪里来、何时失效。

脚本可以在目标运行环境支持时，向生成上下文加入：

  • 当前启用的游戏模式和功能模块。
  • 脚本计算出的只读状态摘要。
  • 用户在 UI 中选择的设置。
  • 模型当前确实需要、但不适合长期写进世界书的信息。

注入内容会占用上下文，也会影响模型输出。接入时要说明来源和清理时机，重点检查：

  • 不要重复注入世界书已经提供的内容。
  • 不要把完整数据库每轮塞进上下文。
  • 明确剧情模型和变量更新模型分别能看到什么。
  • 脚本禁用、对话切换和模块关闭后必须清理旧注入。
  • 让用户知道哪些设置会影响模型输出。
按信息的用途选择位置稳定的人物与世界设定可以放在角色卡、世界书中；“当前启用困难模式”这类会变化的信息，更适合由脚本按需传入。避免两边各写一份，后来却只改了其中一份。

外部 API：接入时，也想好断线怎么办

远程素材或服务不可用时，用户应该知道原因，核心玩法也要有明确的处理办法。

远程数据

读取 JSON、工坊索引、版本信息和动态配置。

媒体与服务

加载图片、音频，或调用明确授权的外部服务。

独立应用通信

与 Gateway、独立前端或本地服务交换数据。

请求成功和失败，都需要处理

→

→
校验成功结果或记录错误

  • 地址失效或网络断开时，核心聊天是否还能继续。
  • 返回数据格式改变时，脚本是否安全停止。
  • 是否存在跨域、鉴权和权限问题。
  • 请求中是否携带隐私、Token 或 API 密钥。
  • 外部服务停止后有没有本地回退方案。
不要公开密钥角色卡、世界书和前端脚本都可能被用户查看。不要把私人 API 密钥硬编码进公开发布的角色卡。
