拿一块折叠面板，完整跑一趟

用一个能打开、能关闭的小面板，把调查、修改、检查和反馈连起来。

保留安全副本或本地 Git 基线先复制角色卡，或记录可恢复的本地版本。练手时把唯一的正式卡改坏，实在没必要。
先只读调查请 Agent 找到控制中心源码，查清面板装在哪里、按钮怎样接入、退出时怎样清理。
审核计划看它是否找对文件，本轮是否只增加面板，以及准备怎样检查开关和原有功能。发现它打算重写整个模块，先问原因。
批准小范围执行确认后，本轮只做面板基础结构和开关。其他改进先记下来，别把练习越做越大。
在真实 SillyTavern 中运行Agent 完成可执行的检查后，再列出需要你在酒馆里测试的步骤：入口、开关、刷新、原有功能及相关报错。
反馈实际现象哪里不符合预期，就把操作步骤和实际表现发回来。有控制台错误，一并附上，方便继续定位。
生成交接留下改了哪些文件、哪些检查通过、哪里还没验、怎样恢复，以及下次从哪里接着做。
有效的问题反馈
面板可以打开，但是关闭按钮无效。

实际表现：
点击右上角关闭按钮后没有反应。

预期表现：
点击后面板关闭，但控制中心保持打开。

复现步骤：
1. 打开控制中心；
2. 点击媒体管理；
3. 点击右上角关闭按钮。

09

这六个习惯，容易让你反复返工

这些坑往往和会不会写代码无关，而是开工前没说清、做完后没检查。

任务太大

世界观、变量、状态栏、地图、战斗、工坊一口气全要，哪里出错都不好找。先做一段能独立体验和验收的流程。

只描述感觉

只说“高级一点”，Agent 可能理解成多加阴影。可以先给参考图，指出哪里太挤、哪个按钮难找、手机上哪里读不清。

相信完成宣言

看到“已完成”先看它验了什么：新文件有没有加载，按钮有没有真的点过，酒馆里的数据有没有改变。

允许顺手优化

本来修一个按钮，顺手改了整个面板。每多动一块，都要补上相应检查；如果暂时没这个必要，就留到下一轮。

没有恢复点

大改前至少保留副本或可恢复的本地 Git 版本。否则出问题后，你和 Agent 就得一起考古：昨天到底哪份能用？

换会话不交接

新任务未必带着前一段对话。把已定方案、当前进度、不能动的内容和下一步写进交接，省得重新争论一遍。

10

第一章结束：你已经可以带 Agent 做小项目了

先试着独立完成一次小修改，再看自己在哪一步需要补课。

能让 Agent 做出一个小东西从打开项目到描述需求，再到试用结果和反馈问题，自己走完一轮。
能保护项目限制目录、建立副本或本地 Git、先计划后执行。
能使用工程资料能让 Agent 按问题查询 ST DB，并说明采用了什么资料、是否适合当前版本。
能使用 TW Skill 阵列不必背英文名，但要能看懂它为什么调用这个 Skill，以及最后应交付什么。
能管理复杂任务把大任务拆成阶段；如果开多个 Agent，要分清写入范围，并保留接口约定和验收记录。

收工前，拿这八问拦一次

  • 我最终想得到什么可见结果？
  • Agent 可以修改哪些文件，哪些绝对不能动？
  • Agent 选了哪些 TW 能力，和这次需求对得上吗？
  • 应该查询 ST 开发指南 DB 的哪个方向？
  • Agent 准备修改什么，证据是什么？
  • Agent 已经检查了什么，哪些面和点还需要我验收？
  • 失败后如何恢复？
  • 切换 Agent 或新会话时，如何完成交接？
驾驶员也在积累经验每做完一轮，你都会更清楚怎样提需求、怎么看方案、哪里值得亲自试。代码可以逐步学，判断力也一样。别拿 Agent 写了多少行当成绩单，看看作品离你的预期近了多少。
