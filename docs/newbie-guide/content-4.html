09

最容易把项目送走的六个习惯

不会写代码还能学；没有边界、没有恢复点，真会把项目一锅端。

任务太大

一次要求世界观、变量、状态栏、地图、战斗和工坊。正确做法是拆成可独立验收的阶段。

只描述感觉

“高级一点”没有明确约束。应该描述层级、布局、状态、响应式和交互。

相信完成宣言

文件可能写了但没加载，测试可能通过但真实环境仍报错。

允许顺手优化

修改范围越大，出现问题后越难定位。一次只处理一个行为路径。

没有恢复点

没有副本、本地 Git 提交或分支时，不要进行大规模修改。

换会话不交接

新会话不知道旧决策。先生成项目目标、架构、进度、禁区和下一步。

10

毕业不是会背命令，是收得住方向盘

能控范围、看证据、留退路，才算真的会带 Agent 干活。

能让 Agent 做出一个小东西打开项目、描述任务、看到结果、给出具体反馈。
能保护项目限制目录、建立副本或本地 Git、先计划后执行。
能使用工程资料根据任务查询 ST DB，要求 Agent说明依据、版本和不确定项。
能使用 TW Skill 阵列检查路由是否正确，避免加载无关 Skill，要求验证与交接。
能管理复杂任务拆阶段、控制并行 Agent、保留行为契约和验收记录。

收工前，拿这八问拦一次

  • 我最终想得到什么可见结果？
  • Agent 可以修改哪些文件，哪些绝对不能动？
  • 当前任务应该使用哪些 TW Skill？
  • 应该查询 ST 开发指南 DB 的哪个方向？
  • Agent 准备修改什么，证据是什么？
  • 我如何亲自验证结果？
  • 失败后如何恢复？
  • 切换 Agent 或新会话时，如何完成交接？
最后把话说透会写代码，决定你能钻多深；会驾驭 Agent，决定 AI 吐出来的东西究竟是项目，还是一团看起来很忙的文本。
